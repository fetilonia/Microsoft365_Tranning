## L2 · 적응형 액세스 · 세션 관리 — 규격 네트워크 · 소스 IP 복원 · CA 신호

- 설정(Control Plane): Global Secure Access 설정의 Adaptive access 토글(Enable Conditional Access Signaling for Microsoft Entra ID) | Microsoft traffic profile | Conditional Access 네트워크 조건(All Compliant Network locations) | Universal Tenant Restrictions 토글
- 강제(Enforcement): Microsoft Entra ID 조건부 액세스 (인증 평면에서 규격 네트워크 판정) | Global Secure Access 클라이언트·원격 네트워크 (신호 경로) | CAE 지원 리소스 (데이터 평면 재평가)
- 증적(Evidence): Entra 로그인 로그(Through Global Secure Access · IP 주소) | KQL: SigninLogs(IsThroughGlobalSecureAccess · NetworkLocationDetails) · AuditLogs(LoggedByService == "Global Secure Access") · NetworkAccessTraffic
- 메뉴(Admin Center): Global Secure Access > 설정(Settings) > 세션 관리(Session management) > 적응형 액세스(Adaptive access) · 범용 테넌트 제한(Universal tenant restrictions) | 연결 > 트래픽 전달
- 라이선스(License): 규격 네트워크 확인·소스 IP 복원·Universal Tenant Restrictions는 Microsoft Entra ID P1/P2(Microsoft traffic profile 기능 표), 범용 CA·Universal CAE는 Entra P1/P2 또는 Internet Access 라이선스 대상 [확인 필요: 고객 라이선스 · 기능별 표 최신 여부]

### L3 · 0 · 기능 상태 전이 — 신호 꺼짐 → 신호·정책 구성 → 규격 네트워크 판정

#### L4 · ⓪ 비활성 — Entra ID가 규격 네트워크도 원래 IP도 알지 못한다

1. [시작] 사용자가 Microsoft 365 앱에 로그인 — Entra ID 인증 요청
   - 주체: 사용자
   - 위치: 브라우저 → Microsoft Entra ID 로그인 (예: Exchange Online · SharePoint Online)
   - 데이터: 인증 요청 · 요청 출발 공용 IP
   - 해설: 사용자가 업무 앱에 로그인하면 Entra ID가 조건부 액세스를 평가합니다
2. [처리] Adaptive access 신호 꺼짐 — Entra ID가 받는 네트워크 신호 없음
   - 주체: Entra ID
   - 데이터: Enable Conditional Access Signaling for Microsoft Entra ID = 꺼짐. 새 테넌트는 소스 IP 복원이 기본으로 켜져 있지만 2025년 6월 이전에 Global Secure Access 기능을 켠 테넌트는 직접 켜야 할 수 있습니다
   - 해설: 이 토글이 꺼져 있으면 Entra ID와 Microsoft Graph는 사용자의 실제 공용 송신 IP를 받지 못합니다
3. [판단] 트래픽이 Global Secure Access를 거쳤는가?
   - 주체: Entra ID
   - 데이터: Global Secure Access 클라이언트 터널 · 원격 네트워크 경유 여부
   - 해설: 경유했다면 Entra ID는 사용자가 아니라 에지 쪽 주소를 보게 됩니다
   - 에지 경유 → 4
   - 직접 인터넷 → 5
4. [처리] Entra ID가 에지 주소를 사용자 IP로 평가 — 실제 IP 안 보임
   - 주체: Entra ID
   - 데이터: 로그인 로그의 IP 주소 = Global Secure Access 서비스의 주소. 소스 IP 복원을 끄면 실제 IP는 보이지 않고, Global Secure Access 서비스 IP를 보려면 복원을 꺼야 한다는 제한이 안내됩니다
   - 해설: 회사 공용 IP 목록 기반 위치 정책과 ID 보호 위험 탐지가 실제 사용자 위치와 맞지 않게 됩니다
5. [처리] 규격 네트워크 조건 사용 불가 — IP 목록을 직접 관리
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Named locations (IP 범위 기반 위치만 사용)
   - 데이터: IPv4·IPv6·국가 위치 목록. 규격 네트워크는 IP 목록을 관리하지 않아도 되도록 만든 위치이고, 이 위치를 쓰려면 신호가 켜져 있어야 합니다. VPN hairpin 없이 소스 IP를 고정하는 장점도 쓰지 못합니다
   - 해설: 관리자는 송신 IP 목록을 직접 유지하거나 VPN으로 트래픽을 되돌려야 합니다
6. [끝] 토큰 탈취·재생을 네트워크로 막을 수단이 없다 — 남는 위험
   - 주체: 외부
   - 위치: 공격자 기기 → Entra ID (조직 네트워크 밖)
   - 데이터: 규격 네트워크 판정 없음 → 훔친 세션 토큰을 어디서 재생해도 네트워크 조건으로는 걸러지지 않음. 규격 네트워크 확인은 이 재생을 인증 시점에 거부하도록 설계된 기능입니다
   - 해설: 신호를 켜지 않으면 IP 정확도와 토큰 재생 방어를 모두 놓치는 상태로 남습니다
- 시나리오: 에지 경유 :: 에지 IP가 실제 IP로 오인되고 위험 탐지가 부정확
- 시나리오: 직접 인터넷 :: 실제 IP는 보이나 규격 네트워크 판정 불가

> 교육 포인트: 규격 네트워크와 소스 IP 복원은 같은 토글(Adaptive access)을 공유합니다. 토글 하나가 IP 정확도와 규격 네트워크 위치 두 가지를 동시에 결정합니다.
>
> 주의: 위치 기반 CA 정책이 있는 상태에서 신호를 끄면 대상 사용자가 의도치 않게 차단될 수 있다고 문서가 경고합니다. 끄기 전에 해당 CA 정책부터 삭제하는 것이 권장됩니다.

#### L4 · ① 구성 — 신호를 켜고 규격 네트워크 위치로 CA를 만든다

1. [시작] 관리자가 Entra 관리 센터에 로그인 — 역할 구분
   - 주체: 관리자
   - 위치: entra.microsoft.com — Global Secure Access Administrator(신호·프로필·소스 IP 복원), Conditional Access Administrator(신호 켜기 안내 계정·CA 정책·이름 있는 위치), Universal Tenant Restrictions 켜기에는 Global Secure Access Administrator와 Security Administrator 둘 다
   - 데이터: Entra 역할 할당. 소스 IP 복원 설정은 Global Secure Access Administrator 또는 Global Administrator가 변경하고, 제품 사용에는 Microsoft Entra ID P1 라이선스가 필요합니다
   - 해설: 규격 네트워크 문서는 신호 켜기를 두 역할을 활성화한 계정으로 하도록 안내합니다
2. [처리] Microsoft traffic profile 켜기 — 소스 IP 복원의 필수 전제
   - 주체: 관리자
   - 위치: Global Secure Access › 연결(Connect) › 트래픽 전달(Traffic forwarding) › Microsoft traffic profile
   - 데이터: 프로필 상태 = 켜짐. Microsoft 365 IP·FQDN 목록에서 파생된 규칙을 Forward(획득) 또는 Bypass로 정하며, Bypass 규칙은 클라이언트의 일반 경로로 나갑니다
   - 해설: Microsoft traffic profile이 꺼져 있으면 소스 IP 복원을 쓸 수 없습니다
3. [처리] 신호를 보낼 수단 준비 — 클라이언트 또는 원격 네트워크
   - 주체: 디바이스
   - 위치: Global Secure Access › 연결 › 클라이언트 다운로드(Client download) 또는 원격 네트워크(Remote networks)
   - 데이터: Global Secure Access 클라이언트가 설치된 기기이거나 구성된 원격 네트워크 뒤의 사용자. 원격 네트워크는 클라이언트 없이도 Microsoft 트래픽에 접근할 수 있지만 그 경우 Global Secure Access 트래픽 프로필 대상 CA는 집행되지 않습니다
   - 해설: 규격 네트워크는 클라이언트 또는 원격 네트워크로 들어온 트래픽만 통과시킵니다
4. [처리] CA 신호 켜기 — Enable Conditional Access Signaling for Microsoft Entra ID
   - 주체: 관리자
   - 위치: Global Secure Access › 설정(Settings) › 세션 관리(Session management) › 적응형 액세스(Adaptive access) › Enable Conditional Access Signaling for Microsoft Entra ID 토글
   - 데이터: 토글 = 켜짐 → Entra ID·Microsoft Graph가 사용자의 공용 송신 소스 IP를 받습니다. 새 테넌트는 소스 IP 복원이 기본 켜짐이고, 2025년 6월 이전에 Global Secure Access를 켠 테넌트는 직접 켜야 할 수 있습니다
   - 해설: 이 한 번의 토글이 소스 IP 복원과 규격 네트워크 위치를 함께 켭니다. 토글 이름은 문서마다 'Global Secure Access signaling'으로도 불립니다
5. [처리] 규격 네트워크 위치 확인 — 이름 있는 위치 목록
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Named locations
   - 데이터: All Compliant Network locations 위치가 있고 위치 유형(location type)이 Network Access여야 합니다. 신뢰할 수 있는 위치(trusted)로 표시하는 것은 선택입니다
   - 해설: 이 위치가 보이면 Entra ID가 규격 네트워크 신호를 평가할 준비가 된 것입니다
6. [처리] CA 정책 만들기 — 규격 네트워크 밖은 차단
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Create new policy › Assignments › Users or workload identities(Include = 시험 사용자·그룹, 운영 전 확대) › Target resources › Include
   - 데이터: 문서 예시는 All users + All resources (처음에는 시험 사용자와 특정 앱으로 시작하도록 튜토리얼이 안내). 같은 화면에서 Network › Configure = Yes › Include = Any location › Exclude = All Compliant Network locations, Access controls › Grant = Block access
   - 해설: 'Require compliant network'라는 허용 컨트롤이 아니라, 네트워크 조건의 위치 제외 + Block access로 구성하는 것이 문서의 방식입니다
7. [처리] 제외 대상 지정 — 잠금 방지
   - 주체: 관리자
   - 위치: 같은 정책 › Users › Exclude (Users and groups) · Target resources › Exclude
   - 데이터: 비상 액세스(break-glass) 계정, 서비스 계정·서비스 주체, Intune에 기기를 등록하는 조직은 Microsoft Intune Enrollment·Microsoft Intune 앱(순환 의존 방지), Defender 모바일 앱의 필요 리소스. Global Secure Access 트래픽 프로필·정책 서비스는 규격 네트워크를 켜면 자동으로 제외됩니다
   - 해설: 클라이언트가 필요한 리소스에 접근하지 못하면 규격 네트워크를 얻을 수 없으므로 일부는 정책에서 자동으로 빠집니다
8. [처리] 보고 전용으로 점검 후 정책 켜기 — Enable policy
   - 주체: 관리자
   - 위치: 같은 정책 › Enable policy = Report-only → On › Create
   - 데이터: 정책 상태. 보고 전용 모드는 조건부 액세스 일반 점검 방법이고 규격 네트워크 문서의 예시는 On으로 바로 만듭니다 [확인 필요: 규격 네트워크 정책의 보고 전용 사용 권장 범위]
   - 해설: 먼저 영향 범위를 로그로 확인한 뒤 켜면 의도치 않은 차단을 줄일 수 있습니다
9. [처리] (선택) 테넌트 제한 켜기 — Universal Tenant Restrictions
   - 주체: 관리자
   - 위치: Global Secure Access › 설정 › 세션 관리 › Universal Tenant Restrictions 탭 › Enable Tenant Restrictions for Microsoft Entra ID and Microsoft Graph 토글
   - 데이터: 사전 조건 = TRv2 기본 정책과 파트너별 정책 구성, Microsoft traffic profile 켜짐과 Entra ID 서비스 FQDN·IP를 Tunnel로 설정, 클라이언트 배포 또는 원격 네트워크 연결. 켜는 계정은 Global Secure Access Administrator와 Security Administrator 역할이 모두 필요합니다
   - 해설: 켜면 클라이언트가 있는 기기와 원격 네트워크의 사용자는 TRv2 정책에 허용된 테넌트·앱에만 로그인할 수 있습니다
10. [끝] 클라이언트 끄고 시험 — 차단 확인
    - 주체: 관리자
    - 위치: 시험 기기 › 시스템 트레이 클라이언트 우클릭 › Disable → 새 브라우저 세션으로 Entra SSO 앱 로그인
    - 데이터: 클라이언트 실행 중 = 정상 로그인, 클라이언트 중지 = 'You can't access this right now' 차단 화면. 이미 로그인한 앱 세션은 즉시 끊기지 않고 다음 로그인 시점에 다시 평가됩니다
    - 해설: 클라이언트를 껐을 때 막히고 다시 켰을 때 풀리면 규격 네트워크 정책이 동작하는 것입니다

#### L4 · ② 활성 — 로그인 요청이 에지를 거쳐 Entra ID에서 판정된다

1. [시작] 사용자가 Entra SSO 앱에 접근 — 클라이언트가 켜진 기기
   - 주체: 사용자
   - 위치: 브라우저 → 앱(예: myapps.microsoft.com · Exchange Online · SharePoint Online)
   - 데이터: 로그인 요청 · 기기의 클라이언트 상태(녹색 = 로그인·실행 중)
   - 해설: 사용자는 평소처럼 앱에 접속합니다
2. [판단] 이미 로그인된 앱 세션이 남아 있는가?
   - 주체: 앱
   - 데이터: 앱 세션 · 토큰 만료 여부
   - 해설: 이미 로그인한 앱은 끊기지 않고, Entra ID는 세션이 만료되어 다시 로그인할 때 규격 네트워크를 다시 평가합니다
   - 기존 세션 → [끝] 세션 유지 — 규격 네트워크는 다음 로그인 때 재평가
   - 새 로그인 → 3
3. [처리] 클라이언트가 Entra ID 트래픽 획득 — Microsoft traffic profile
   - 주체: GSA 클라이언트
   - 위치: 클라이언트 터널 → Microsoft SSE 에지 (Microsoft traffic profile 규칙이 Forward)
   - 데이터: Entra ID 로그인 FQDN 트래픽. 클라이언트는 Entra ID에서 먼저 인증·인가를 받고(유효한 PRT가 있으면 끊김 없이 진행) 터널을 수립합니다
   - 해설: 로그인 요청이 사용자 기기에서 곧바로 나가지 않고 이 테넌트의 에지를 거칩니다
4. [처리] 에지가 원래 송신 IP를 Entra ID로 전달 — 소스 IP 복원
   - 주체: SSE 에지
   - 위치: Microsoft SSE 에지 → Microsoft Entra ID · Microsoft Graph (신호 경로)
   - 데이터: 사용자의 공용 송신 소스 IP를 안전하게 전달하고 이 테넌트의 에지를 거쳤다는 신호(규격 네트워크)를 함께 제공합니다. 원래 IP만 보이고 Global Secure Access 서비스 IP는 보이지 않습니다
   - 해설: Entra ID는 에지 주소가 아니라 실제 IP와 규격 네트워크 여부로 판정합니다
5. [처리] 조건부 액세스 정책 평가 — 네트워크 조건
   - 주체: Entra ID
   - 위치: Microsoft Entra ID 조건부 액세스 (Network › Include Any location · Exclude All Compliant Network locations)
   - 데이터: 규격 네트워크 위치 일치 여부. 규격 네트워크 확인은 이 테넌트 전용이라 다른 테넌트의 Global Secure Access로 들어온 사용자는 통과하지 못합니다
   - 해설: 정책은 인증 평면에서 로그인 시점에 평가됩니다
6. [판단] 요청이 규격 네트워크에서 왔는가?
   - 주체: Entra ID
   - 데이터: All Compliant Network locations 일치 = 제외 조건에 해당하여 Block 정책이 적용되지 않음
   - 해설: 제외 위치에 해당하면 Block 정책은 이 사용자에게 적용되지 않습니다
   - 규격 네트워크 → 7
   - 규격 네트워크 아님 → [차단] 'You can't access this right now' — 정책이 Block access로 거부
7. [처리] 토큰 발급 — 다른 CA 컨트롤과 함께 평가
   - 주체: Entra ID
   - 데이터: 다른 CA 정책(MFA·규격 기기 등)이 모두 충족되면 액세스 토큰·리프레시 토큰 발급. CAE를 지원하는 서비스(Microsoft Graph 등)는 이후 토큰 재생을 근실시간으로 거부합니다
   - 해설: 규격 네트워크는 여러 조건 중 하나이며 다른 컨트롤과 함께 심층 방어를 이룹니다
8. [끝] 로그 기록 — 로그인 로그의 IP와 GSA 표시
   - 주체: 로그
   - 위치: Entra ID › Users › 사용자 › Sign-in logs (Security Reader 이상) · Global Secure Access › 모니터링 › 트래픽 로그
   - 데이터: 로그인 로그의 실제 공용 IP · Through Global Secure Access = Yes (KQL: SigninLogs.IsThroughGlobalSecureAccess · NetworkLocationDetails). 에지 인증용 리소스는 Internet resources with Global Secure Access · Microsoft apps with Global Secure Access · All private resources with Global Secure Access · ZTNA Policy Service로 표시됩니다
   - 해설: 로그인 로그 데이터는 처리 시간이 걸려 늦게 나타날 수 있습니다
- 시나리오: 새 로그인 ▸ 규격 네트워크 :: 에지 경유가 확인되어 Block 정책 미적용으로 로그인
- 시나리오: 새 로그인 ▸ 규격 네트워크 아님 :: 클라이언트 중지 등 경유 실패로 Block 정책에 막힘
- 시나리오: 기존 세션 :: 이미 로그인한 세션이라 끊기지 않고 다음 로그인에 재평가

> 교육 포인트: 규격 네트워크는 IP 목록이 아니라 '이 테넌트의 Global Secure Access를 거쳤는가'를 보는 위치입니다. 관리자는 규격 네트워크 IP 범위를 점검·유지하지 않아도 됩니다.
>
> 주의: 규격 네트워크 조건은 Private Access 앱에는 지원되지 않고, Explicit Forward Proxy를 포함한 모든 앱 정책에서는 GSA-ExplicitForwardProxy 리소스를 제외해야 합니다.
>

>

### L3 · A · 규격 네트워크 판정과 범용 CA — 위치 조건 · 터널 인가 · 연속 재평가

#### L4 · 규격 네트워크 판정 — 정책이 적용되기까지의 확인 순서

1. [시작] Entra ID가 로그인 요청에 CA 정책을 매칭 — 사용자·리소스 대상
   - 주체: Entra ID
   - 위치: Microsoft Entra ID 조건부 액세스 평가 (Users · Target resources 할당)
   - 데이터: 사용자·그룹 포함/제외, 대상 리소스(All resources 등). 정책 대상에 일치해야 네트워크 조건을 봅니다
   - 해설: 네트워크 조건은 정책이 대상 사용자·리소스에 일치한 뒤에야 평가됩니다
2. [판단] 대상 리소스가 Global Secure Access 자동 제외 리소스인가?
   - 주체: Entra ID
   - 데이터: Global Secure Access Traffic Profiles · Global Secure Access Policy Service(내부 서비스)는 규격 네트워크를 켠 정책에서 명시 제외 없이 자동으로 빠집니다. 로그에는 Internet resources with Global Secure Access · Microsoft apps with Global Secure Access · All private resources with Global Secure Access · ZTNA Policy Service로 남습니다
   - 해설: 클라이언트가 자기 리소스에 접근하지 못해 막히는 순환을 막기 위한 자동 제외입니다
   - 자동 제외 → [끝] 정책 미적용 — 클라이언트의 필수 리소스는 항상 통과
   - 일반 리소스 → 3
3. [판단] CA 신호(Adaptive access 토글)가 켜져 있는가?
   - 주체: Entra ID
   - 위치: Global Secure Access › 설정 › 세션 관리 › 적응형 액세스
   - 데이터: Enable Conditional Access Signaling for Microsoft Entra ID 상태. 꺼져 있으면 규격 네트워크 위치를 판정할 신호가 없습니다
   - 해설: 신호를 끈 상태에서 규격 네트워크 기반 CA 정책이 남아 있으면 대상 사용자가 의도치 않게 차단될 수 있습니다 [확인 필요: 신호 꺼짐 시 평가 결과의 정확한 동작]
   - 켜짐 → 4
   - 꺼짐 → [차단] 규격 네트워크로 인정되지 않아 Block 정책에 걸림
4. [처리] 네트워크 조건 평가 — Any location에서 규격 네트워크를 뺀다
   - 주체: Entra ID
   - 위치: CA 정책 › Conditions › Network › Configure = Yes › Include Any location › Exclude All Compliant Network locations
   - 데이터: 네트워크 조건에는 Any location · All trusted networks and locations · All Compliant Network locations · Selected networks and locations이 있습니다. Any location을 선택하면 이름 있는 위치로 등록하지 않은 모든 IP를 포함합니다
   - 해설: 'Any location 중 규격 네트워크 제외'가 곧 '규격 네트워크 밖'을 뜻합니다
5. [판단] 요청이 이 테넌트의 규격 네트워크에서 왔는가?
   - 주체: Entra ID
   - 데이터: 클라이언트가 설치된 기기이거나 구성된 원격 네트워크 뒤 사용자 + 이 테넌트 전용 신호. 예: contoso.com의 정책은 fabrikam.com 사용자가 자기 Global Secure Access로 통과할 수 없습니다
   - 해설: 규격 네트워크는 테넌트별로 정해지며 일반 IPv4·IPv6·국가 위치와 다릅니다
   - 규격 네트워크 → [끝] 제외 조건에 해당해 Block 정책 미적용
   - 규격 네트워크 아님 → 6
6. [차단] Block access — 규격 네트워크 밖 요청 차단
   - 주체: Entra ID
   - 데이터: Grant = Block access 적용 → 사용자에게 'You can't access this right now' 오류. 로그인 로그의 CA 결과는 failure
   - 해설: 정책에 일치하고 규격 네트워크에도 해당하지 않아 로그인이 거부됩니다
- 시나리오: 일반 리소스 ▸ 켜짐 ▸ 규격 네트워크 :: 제외 위치에 해당해 Block 정책이 적용되지 않음
- 시나리오: 일반 리소스 ▸ 켜짐 ▸ 규격 네트워크 아님 :: 규격 네트워크 밖 요청이라 Block access로 차단
- 시나리오: 일반 리소스 ▸ 꺼짐 :: 신호가 없어 규격 네트워크로 인정되지 않아 차단
- 시나리오: 자동 제외 :: 클라이언트 필수 리소스라 정책 대상에서 제외

> 교육 포인트: 'Any location에서 All Compliant Network locations를 제외하고 Block'은 '규격 네트워크가 아니면 막는다'는 뜻입니다. 허용 컨트롤을 따로 고르는 방식이 아닙니다.
>
> 주의: 정책 대상 사용자에 break-glass 계정을 반드시 제외하고, 일부 서비스 계정·서비스 주체는 사용자 대상 정책에 걸리지 않으므로 워크로드 ID용 CA를 따로 씁니다.
>
> 출처: https://learn.microsoft.com/entra/global-secure-access/how-to-compliant-network
>
> 출처: https://learn.microsoft.com/entra/identity/conditional-access/concept-assignment-network

#### L4 · 범용 CA와 Universal CAE — 터널 인가 뒤 재평가

1. [시작] 클라이언트가 Microsoft SSE 터널 연결 시도 — Entra ID로 리디렉션
   - 주체: GSA 클라이언트
   - 위치: GSA 클라이언트 → Microsoft Entra ID (인증·인가)
   - 데이터: 사용자·기기 인증. 유효한 PRT가 있으면 매끄럽게 진행됩니다
   - 해설: 클라이언트도 터널을 열기 전에 Entra ID의 인가를 받아야 합니다
2. [처리] 범용 조건부 액세스 평가 — 트래픽 프로필 대상 정책
   - 주체: Entra ID
   - 위치: Conditional Access › Target resources › All internet resources with Global Secure Access · Microsoft 365(Microsoft traffic profile) 리소스
   - 데이터: MFA·규격 기기·로그인 위험 등 컨트롤을 앱이 아니라 Microsoft traffic·Internet access 터널에 적용합니다. Private Access 터널은 대상으로 지정할 수 없어 Quick Access 같은 Private Access 앱에 개별로 적용해야 합니다
   - 해설: Microsoft 365 서비스를 Global Secure Access 밖으로 우회하지 못하게 하려면 Microsoft 365 앱에 규격 네트워크를 요구하는 정책을 따로 만들라고 안내합니다
3. [판단] 터널 인가가 허용되었는가?
   - 주체: Entra ID
   - 데이터: 범용 CA의 Grant/Block 결과. Internet access 대상 리소스에서 비준수 기기를 막으면 기기를 준수로 되돌릴 Intune 경로조차 막혀 잠길 수 있어 Intune 엔드포인트와 사용자 지정 규정 준수 스크립트의 대상을 Custom Bypass에 넣어 완화합니다
   - 해설: 복구 경로가 터널 안에 있으면 사용자는 기기를 고치지 못한 채 잠깁니다
   - 인가 허용 → 4
   - 인가 거부 → [차단] 터널 인가 거부 — 해당 프로필 트래픽 획득 안 됨
4. [처리] 액세스 토큰 발급·터널 수립 — 60~90분 토큰
   - 주체: Entra ID
   - 데이터: Global Secure Access 액세스 토큰(60~90분 유효). Windows 클라이언트 1.8.239.0 이상은 Universal CAE 토큰을 받고, 다른 플랫폼은 일반 토큰을 사용합니다. CAE 토큰을 못 받으면 일반 토큰으로 되돌아가는 폴백이 있습니다
   - 해설: 토큰이 유효한 동안에는 에지가 연결을 허용하므로 Universal CAE가 이 구간의 공백을 메웁니다
5. [처리] Entra ID 변경 신호 수신 — Universal CAE
   - 주체: SSE 에지
   - 위치: Entra ID → Global Secure Access (CAE 신호) → GSA 클라이언트 알림(toast)
   - 데이터: 사용자 신호(계정 삭제·비활성화, 암호 변경·재설정, MFA 사용 설정, 새로 고침 토큰 모두 취소, ID 보호 높은 사용자 위험)와 기기 신호(기기 삭제·비활성화, 비준수 상태 감지). 신호가 클라이언트에 도달하는 데 약 2~5분이 걸립니다
   - 해설: 토큰이 아직 유효해도 에지가 클레임 챌린지를 보내 다시 인증하게 합니다
6. [판단] 사용자가 재인증을 완료했는가?
   - 주체: GSA 클라이언트
   - 데이터: 재인증 안내를 최대 세 번, 각각 2분 유예 → 약 10분 뒤 끊김. 기기 준수·사용자 위험 신호는 대응하는 CA 정책과 함께 써야 하며, 정책이 없으면 재인증이 조용히 진행되어 행동할 수단이 없습니다
   - 해설: 재인증에 성공하면 연결이 이어지고 실패하면 터널이 끊깁니다
   - 재인증 성공 → [끝] 연결 유지 — 새 토큰으로 계속
   - 재인증 안 함 → [차단] 모든 Global Secure Access 터널 끊김 — 재인증하면 복구
- 시나리오: 인가 허용 ▸ 재인증 성공 :: 신호를 받고 재인증을 마쳐 연결이 이어짐
- 시나리오: 인가 허용 ▸ 재인증 안 함 :: 유예 시간 안에 재인증하지 않아 터널이 끊김
- 시나리오: 인가 거부 :: 범용 CA가 터널 인가를 거부해 트래픽을 획득하지 못함

> 교육 포인트: Universal CAE는 앱이 CAE를 지원하지 않아도 Global Secure Access를 거치는 모든 앱에 근실시간 재평가를 확장합니다. 선택 사항인 Strict Enforcement 모드는 토큰 재생이 원래 IP와 다른 IP에서 시도되면 네트워크 접근을 차단합니다.
>
> 주의: Universal CAE는 Strict Enforcement를 켜기 전까지는 '기회적(opportunistic)'으로 동작하며, Windows 클라이언트만 지원합니다.

### L3 · B · 소스 IP 복원과 로그 변화 — 토글 전후의 IP · 엄격 위치 적용과의 충돌

#### L4 · 토글 켜기·끄기 — 로그인 로그의 IP가 달라진다

1. [시작] 관리자가 시험 사용자로 로그인 — 클라이언트 켜짐
   - 주체: 관리자
   - 위치: 시험 기기(GSA 클라이언트 실행 중) → Entra SSO 앱 로그인
   - 데이터: 시험 사용자 · 시험 기기의 실제 공용 송신 IP
   - 해설: 토글 상태마다 로그인을 하나씩 만들어 로그를 비교합니다
2. [판단] Adaptive access 신호가 켜져 있는가?
   - 주체: Entra ID
   - 위치: Global Secure Access › 설정 › 세션 관리 › 적응형 액세스
   - 데이터: Enable Conditional Access Signaling for Microsoft Entra ID 토글 상태 (Global Secure Access Administrator로 변경)
   - 해설: 새 테넌트는 기본 켜짐, 2025년 6월 이전 테넌트는 명시적으로 켜야 할 수 있습니다
   - 켜짐 → 3
   - 꺼짐 → 4
3. [처리] 복원 켜짐 — Entra ID·Graph가 실제 공용 송신 IP를 받는다
   - 주체: SSE 에지
   - 데이터: 사용자의 원래 송신 IP를 안전하게 전달 → 로그인 로그·감사 로그에 실제 IP 기록. IP 기반 위치 CA 유지, ID 보호 위험 탐지 정확도 향상
   - 해설: Global Secure Access를 거쳐도 Entra ID는 사용자의 원래 위치를 봅니다
   - 다음 → 5
4. [처리] 복원 꺼짐 — 에지 서비스 IP가 보인다
   - 주체: SSE 에지
   - 데이터: 로그인 로그에 사용자의 실제 IP가 아니라 Global Secure Access 서비스의 주소가 기록. 서비스 IP를 보고 싶으면 소스 IP 복원을 꺼야 한다는 제한이 안내됩니다
   - 해설: 이 상태에서는 회사 공용 IP 기반 위치 정책이 맞지 않습니다
5. [처리] 로그인 로그 열기 — 사용자별 로그
   - 주체: 관리자
   - 위치: Entra ID › Users › 시험 사용자 선택 › Sign-in logs (Security Reader 이상). 로그 데이터는 처리 시간이 걸려 늦게 나타납니다
   - 데이터: 로그인 이벤트 상세 → IP address · Through Global Secure Access = Yes. 문서 화면 예시는 복원을 켬 → 끔 → 켬 순서로 IP 변화를 보여 줍니다
   - 해설: 토글 변경 직후에 만든 로그인으로 비교해야 합니다
6. [처리] KQL로 대량 확인 — Global Secure Access 인식 필드
   - 주체: 로그
   - 위치: Log Analytics › SigninLogs (로그인 로그를 진단 설정으로 보낸 경우) [확인 필요: 진단 설정 구성]
   - 데이터: IsThroughGlobalSecureAccess(true/false) · NetworkLocationDetails · IPAddress. 경유하지 않은 로그인은 false로 남습니다
   - 해설: 에지를 거친 로그인과 거치지 않은 로그인을 한 쿼리로 나눠 셀 수 있습니다
7. [끝] 영향 정리 — IP 정확도와 위치 정책
   - 주체: 로그
   - 데이터: 복원 켜짐 = 위치 기반 CA · ID 보호 · 로그인 로그 · 감사 로그의 IP 정확도. 신호를 끄기 전에는 IP 위치 기반 CA 정책부터 삭제 (그렇지 않으면 사용자 차단 가능)
   - 해설: IP를 믿는 모든 기능이 같은 토글에 의존합니다
- 시나리오: 켜짐 :: 실제 공용 IP가 로그에 남아 위치 정책이 정확히 동작
- 시나리오: 꺼짐 :: 에지 서비스 IP가 남아 위치 정책과 위험 탐지가 부정확

> 교육 포인트: 소스 IP 복원은 Microsoft Entra Internet Access for Microsoft Services의 Adaptive Access 기능이며, Microsoft traffic profile을 켜야 사용할 수 있습니다.
>
> 주의: 복원을 켜면 실제 공용 IP만 보이고 Global Secure Access 서비스 IP는 보이지 않습니다. 에지 IP가 필요한 분석(예: 에지 구간 추적)은 이 점을 고려해야 합니다.
>
> 출처: https://learn.microsoft.com/entra/global-secure-access/how-to-source-ip-restoration
>
> 출처: https://learn.microsoft.com/entra/global-secure-access/tutorial-microsoft-traffic-source-ip-restoration
>
> 출처: https://learn.microsoft.com/entra/global-secure-access/reference-current-known-limitations

#### L4 · 엄격 위치 적용 충돌 — 리소스가 본 IP가 다를 때 막힌다

1. [시작] 관리자가 CAE 엄격 위치 적용 도입 계획 — 위치 기반 CA와 함께
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › 정책 › Session › Customize continuous access evaluation › Strictly enforce location policies (미리 보기) [확인 필요: 포털 메뉴 이름 · 미리 보기 상태]
   - 데이터: 엄격 모드 = 리소스 공급자가 본 IP가 CA 정책에서 허용되지 않으면 즉시 접근 차단. 기본값(Standard)은 짧은 토큰만 발급하고 다른 네트워크 경로에서는 사전 CAE 위치 감지 방식으로 되돌아갑니다
   - 해설: 엄격 모드는 보안이 가장 높지만 네트워크 경로를 정확히 아는 환경에서만 쓸 수 있습니다
2. [판단] Global Secure Access로 보내는 트래픽에 Microsoft 365 외 앱이 포함되는가?
   - 주체: 관리자
   - 데이터: Microsoft 외 리소스에는 소스 IP 복원이 지원되지 않으므로 원래 IP를 모릅니다. 현재는 Microsoft 리소스만 IP 위치 기반 CA를 평가합니다
   - 해설: 엄격 모드와 결합하면 신뢰된 위치의 사용자가 막힐 수 있습니다
   - Microsoft 365 외 앱 포함 → 3
   - Microsoft 365만 → 4
3. [차단] 신뢰된 IP 범위여도 차단 — 소스 IP 복원 미지원
   - 주체: 앱
   - 데이터: 리소스가 보는 IP는 에지 주소이므로 허용 위치와 불일치 → 엄격 적용 차단. 문서의 권고: 비 Microsoft 리소스를 대상으로 한 IP 위치 CA가 있으면 엄격 적용을 켜지 않거나, 소스 IP 복원이 지원하지 않는 트래픽은 Global Secure Access로 보내지 않습니다
   - 해설: 이 조합은 사용자가 정당한 위치에 있어도 차단되는 구성입니다
4. [처리] 소수 사용자로 시험 — IP address (seen by resource) 필터
   - 주체: 관리자
   - 위치: Entra ID › Monitoring & health › Sign-in logs (Reports Reader 이상) › 열·필터 추가 › IP address (seen by resource)
   - 데이터: Entra ID가 본 IP와 리소스가 본 IP를 비교. 빈 값을 걸러 불일치 사례만 봅니다
   - 해설: 엄격 모드를 켜기 전에 작은 집단으로 IP 가정을 시험합니다
5. [처리] CAE 인사이트 워크북으로 불일치 확인 — 분할 터널 환경
   - 주체: 관리자
   - 위치: Azure Workbooks › 공개 템플릿 Continuous Access Evaluation Insights
   - 데이터: Entra ID가 본 IP와 IP address (seen by resource)가 다른 건. 모든 Entra ID·리소스 공급자 접근 경로의 송신 IP를 IP 기반 이름 있는 위치에 포함해야 합니다
   - 해설: 분할 터널이 있으면 두 IP가 다를 수 있습니다
6. [판단] 모든 송신 IP가 이름 있는 위치에 들어 있는가?
   - 주체: 관리자
   - 데이터: Exchange Online · Teams · SharePoint Online · Microsoft Graph 접근 IP가 전용·열거 가능한가
   - 해설: 공유 IP나 정의할 수 없는 송신 IP라면 엄격 모드를 켜지 말라고 안내합니다
   - 모두 포함 → 7
   - 누락 있음 → 8
7. [끝] 사용자 집단을 넓혀 단계적 적용 — 시험 반복
   - 주체: 관리자
   - 데이터: 시험 집단 → 확대 집단 순으로 같은 점검 반복
   - 해설: 영향이 작은 집단부터 넓히며 사용자 경험을 살핍니다
8. [끝] 누락 IP를 위치에 추가하거나 엄격 모드 보류 — 다시 시험
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Named locations › 새 위치 · IP 범위 추가
   - 데이터: 조직 송신 지점의 공용 IP를 이름 있는 위치에 추가. 정의할 수 없는 공유 IP면 엄격 적용을 켜지 않습니다
   - 해설: 누락된 송신 IP를 채운 뒤에 다시 시험합니다
- 시나리오: Microsoft 365만 ▸ 모두 포함 :: 송신 IP가 모두 위치에 있어 엄격 적용을 단계 확대
- 시나리오: Microsoft 365만 ▸ 누락 있음 :: 빠진 IP를 위치에 추가하거나 엄격 적용을 보류
- 시나리오: Microsoft 365 외 앱 포함 :: 소스 IP 복원 미지원으로 신뢰된 IP도 차단

> 교육 포인트: 엄격 위치 적용을 쓰려면 Global Secure Access로 Microsoft 365 외 앱의 트래픽을 보내지 않거나, 소스 IP 복원이 지원하는 트래픽만 보내야 합니다.
>
> 주의: 이 기능은 문서에 미리 보기로 표시되어 있습니다. 규격 네트워크 위치 조건과는 다른 기능입니다.
>
> 출처: https://learn.microsoft.com/entra/identity/conditional-access/concept-continuous-access-evaluation-strict-enforcement
>
> 출처: https://learn.microsoft.com/entra/global-secure-access/reference-current-known-limitations

### L3 · C · 신호 켜기 전후 위험 비교 — 우회 가능 경로와 점검

#### L4 · 토큰 재생 — 신호 전후로 달라지는 방어

1. [시작] 공격자가 사용자 세션 토큰을 훔쳐 조직 밖에서 재생 — 공격자 기기는 규격 네트워크 밖
   - 주체: 외부
   - 위치: 공격자 기기 → Microsoft Entra ID · 리소스
   - 데이터: 탈취한 새로 고침 토큰 또는 액세스 토큰
   - 해설: 토큰만 훔치면 사용자 암호·MFA 없이 재생을 시도할 수 있습니다
2. [판단] 규격 네트워크 정책이 집행 중인가?
   - 주체: Entra ID
   - 데이터: 신호 켜짐 + 규격 네트워크 밖 Block 정책 + 대상 리소스 일치 여부
   - 해설: 정책이 없거나 신호가 꺼져 있으면 네트워크 조건으로 막을 방법이 없습니다
   - 정책 집행 중 → 3
   - 신호 꺼짐 또는 정책 없음 → [끝] 네트워크 위치로는 막지 못함 — 다른 CA 컨트롤에 의존
3. [판단] 훔친 토큰은 무엇인가?
   - 주체: Entra ID
   - 데이터: 새로 고침 토큰으로 액세스 토큰 재발급 요청 = 인증 평면. 이미 발급된 액세스 토큰으로 리소스 직접 호출 = 데이터 평면
   - 해설: 두 평면의 방어가 서로 다릅니다
   - 새로 고침 토큰 → 4
   - 액세스 토큰 → 5
4. [차단] 인증 평면에서 즉시 거부 — 규격 네트워크 밖
   - 주체: Entra ID
   - 데이터: 규격 네트워크에서 온 요청이 아니므로 액세스 토큰 발급 요청을 즉시 거부하고 이후 접근을 차단합니다
   - 해설: 토큰 재발급 단계에서 막으면 도난 세션을 이어 쓸 수 없습니다
5. [판단] 대상 서비스가 CAE를 지원하는가?
   - 주체: 리소스
   - 데이터: Global Secure Access와 통합된 CAE 지원 서비스(예: Microsoft Graph). 미지원이면 액세스 토큰은 전체 수명(기본 60~90분) 동안 유효합니다
   - 해설: 액세스 토큰 재생 방어는 서비스의 CAE 지원 여부에 달려 있습니다
   - CAE 지원 → [차단] 근실시간 거부 — 조직 네트워크 밖 재생
   - CAE 미지원 → 6
6. [끝] 토큰 수명 동안 접근 가능 — 남는 위험 (60~90분)
   - 주체: 리소스
   - 데이터: CAE 미지원 서비스는 액세스 토큰이 만료될 때까지 재생을 막지 못합니다. 이 구간은 다른 조건(규격 기기·MFA·위험)과 함께 줄입니다
   - 해설: 네트워크 신호만으로는 CAE가 없는 서비스의 토큰 재생을 즉시 막을 수 없습니다
- 시나리오: 정책 집행 중 ▸ 새로 고침 토큰 :: 재발급 요청을 인증 평면에서 즉시 거부
- 시나리오: 정책 집행 중 ▸ 액세스 토큰 ▸ CAE 지원 :: CAE 지원 서비스가 재생을 근실시간으로 거부
- 시나리오: 정책 집행 중 ▸ 액세스 토큰 ▸ CAE 미지원 :: 만료까지 재생이 허용되는 잔여 위험
- 시나리오: 신호 꺼짐 또는 정책 없음 :: 규격 네트워크 판정이 없어 네트워크로 막지 못함

> 교육 포인트: 규격 네트워크는 인증 평면(로그인 시점)과 데이터 평면(CAE 지원 서비스) 두 층에서 방어하며, 신호를 켜지 않으면 두 층 모두 동작하지 않습니다.
>
> 주의: 조직 네트워크(이 테넌트의 Global Secure Access 경로) 안에서 재생되는 토큰은 위치 신호만으로는 구분하기 어렵습니다 [판단: 문서에 직접 서술 없음 — 규격 기기·MFA 같은 다른 컨트롤과 함께 사용].
>
> 출처: https://learn.microsoft.com/entra/global-secure-access/how-to-compliant-network
>

#### L4 · 남는 경로 점검 — 우회 탐지와 신호 끄기 감시

1. [시작] 신호를 켜고 정책을 집행한 뒤 우회 경로 점검 시작
   - 주체: 관리자
   - 위치: Global Secure Access › 모니터링 · Microsoft Sentinel / Log Analytics
   - 데이터: 점검 항목 = 신호 끄기 · 기존 세션 · 클라이언트 없는 경로 · 사용자 범위 밖 계정
   - 해설: 정책을 만든 뒤에는 우회 경로가 남지 않았는지 정기적으로 확인합니다
2. [처리] 신호 끄기 감시 — 감사 로그
   - 주체: 로그
   - 위치: Log Analytics › AuditLogs
   - 데이터: LoggedByService == "Global Secure Access" and OperationName has_any ("Update Adaptive Access Policy", "Update Global Secure Access Settings"). 감사 로그는 세션 관리 설정 변경의 modifiedProperties를 채우지 않아 알림이 오면 포털에서 현재 상태를 직접 확인해야 합니다
   - 해설: 신호가 꺼지면 규격 네트워크 정책이 즉시 집행되지 않으므로 Critical 알림으로 다룹니다
3. [처리] 기존 세션·사용자 범위 밖 계정의 한계 확인
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Policies (대상·제외 점검)
   - 데이터: 이미 로그인한 앱 세션은 세션이 만료되어 다시 로그인할 때 재평가됩니다. 서비스 계정·서비스 주체는 사용자 대상 정책에 걸리지 않아 워크로드 ID용 CA가 필요합니다
   - 해설: 정책이 있어도 이 두 경로는 별도로 관리해야 합니다
4. [처리] 클라이언트 없는 경로 확인 — 원격 네트워크
   - 주체: 관리자
   - 위치: Global Secure Access › 연결 › 원격 네트워크(Remote networks)
   - 데이터: 원격 네트워크는 클라이언트 없이 Microsoft 트래픽에 접근하게 하지만 Global Secure Access 트래픽 프로필 대상 CA는 클라이언트가 있을 때만 집행됩니다. 규격 네트워크 위치 자체는 원격 네트워크 뒤 사용자에게도 해당됩니다
   - 해설: 사무실 장비만 믿고 클라이언트 요구 정책을 빠뜨리지 않도록 확인합니다
5. [처리] 우회 로그인 탐지 쿼리 — Microsoft 365 로그인이 에지를 거치지 않음
   - 주체: 로그
   - 위치: Microsoft Sentinel 분석 규칙 · Log Analytics › SigninLogs
   - 데이터: SigninLogs | where ResultType == 0 | where AppDisplayName has_any ("Exchange","SharePoint","Teams","Office 365","Outlook") | where IsThroughGlobalSecureAccess == "false". 규칙 이름 'Global Secure Access - Microsoft 365 access from noncompliant network', 심각도 High, 15분마다 실행·최근 1시간, MITRE T1562
   - 해설: 결과가 0건이면 정상이고, Microsoft 365 로그인이 모두 에지를 거쳤다는 뜻입니다
6. [판단] 쿼리 결과가 나왔는가?
   - 주체: 관리자
   - 데이터: 성공한(ResultType 0) 로그인 중 에지를 거치지 않은 건수
   - 해설: 한 건이라도 있으면 규격 네트워크 집행에 구멍이 있다는 신호입니다
   - 결과 있음 → 7
   - 결과 없음 → [끝] 정상 상태 — 모든 로그인이 Global Secure Access 경유
7. [처리] 원인 조사 — 정책 범위와 신호 상태
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Policies · Global Secure Access › 설정 › 적응형 액세스
   - 데이터: 점검 = 신호 켜짐 여부 · Block 정책의 대상 리소스(All resources) · 제외 목록 · 보고 전용 여부 · 앱 이름 토큰 조정(30일 탐색 쿼리로 AppDisplayName 확인)
   - 해설: 쿼리가 과하게 넓은지(오탐)와 정책이 비어 있는지(미탐)를 함께 확인합니다
8. [끝] 외부 테넌트 통제 확인 — Universal Tenant Restrictions
   - 주체: 관리자
   - 위치: Global Secure Access › 설정 › 세션 관리 › Universal tenant restrictions · AuditLogs(Update/Delete Universal Tenant Restrictions Policy)
   - 데이터: TRv2 정책은 다른 테넌트의 ID가 로그인할 때만 처리됩니다(같은 테넌트 사용자와 게스트는 처리되지 않음). 꺼지면 사용자가 허가되지 않은 외부 테넌트에 로그인할 수 있어 감사 로그로 감시합니다
   - 해설: 규격 네트워크가 '어디서' 접속하는지 막는다면 테넌트 제한은 '어느 테넌트로' 로그인하는지 막습니다
- 시나리오: 결과 있음 :: 우회 로그인이 확인되어 정책·신호 점검으로 이어짐
- 시나리오: 결과 없음 :: 모든 로그인이 에지를 거쳐 정상 종료

> 교육 포인트: 우회 탐지 쿼리의 '결과 0건'이 건강한 상태입니다. 신호 끄기와 UTR 끄기는 감사 로그로 따로 감시합니다.
>
> 주의: AppDisplayName 부분 문자열 매칭은 의도적으로 넓어서 테넌트에 맞게 토큰을 조정해야 합니다.
