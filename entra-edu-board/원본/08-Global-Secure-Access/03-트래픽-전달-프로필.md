## L2 · 트래픽 전달 프로필 — 평가 순서 · 우선순위 · 사용자 할당

- 설정(Control Plane): Microsoft access profile · Private access profile · Internet access profile의 상태(켜기/끄기)와 획득 규칙 | 사용자·그룹·기기·기기 플랫폼 할당 · 사용자 지정 Private Access 프로필(미리 보기, 우선순위 101~199) | 프로필에 연결되는 조건부 액세스 정책
- 강제(Enforcement): Global Secure Access 클라이언트 (프로필을 받아 규칙으로 트래픽 획득) | Microsoft SSE 에지 (획득된 트래픽 처리)
- 증적(Evidence): 클라이언트 고급 진단 › Forwarding profile 탭 (Forwarding profile ID · last checked · 워크로드별 규칙) | Graph(beta) networkaccess forwardingProfile (state · priority · trafficForwardingType · associations) · KQL: NetworkAccessTraffic (TrafficType)
- 메뉴(Admin Center): Global Secure Access > 연결(Connect) > 트래픽 전달(Traffic forwarding) · 애플리케이션 > 엔터프라이즈 애플리케이션 > Network access properties · Entra ID > 조건부 액세스
- 라이선스(License): Microsoft traffic profile은 Entra ID P1/P2 | Private access profile은 Entra ID P1/P2 + Entra Private Access(또는 Entra Suite) | Internet access profile은 Entra ID P1/P2 + Entra Internet Access(또는 Entra Suite) [확인 필요: 고객 라이선스 · 미리 보기 범위]

### L3 · 0 · 기능 상태 전이 — 프로필 꺼짐 → 프로필 구성·할당 → 우선순위대로 트래픽 획득

#### L4 · ⓪ 비활성 — 켜진 프로필이 없어 트래픽이 에지로 가지 않는다

1. [시작] 사용자가 Microsoft 365 · 사내 앱 · 웹 사이트에 접속 — 클라이언트가 설치된 업무 기기
   - 주체: 사용자
   - 위치: 브라우저 · 앱 → 대상 FQDN · IP
   - 데이터: 목적지 FQDN 또는 IP · 포트
   - 해설: 같은 기기에서 Microsoft 365, 사내 앱, 일반 웹을 쓰는 평범한 요청입니다
2. [처리] 클라이언트가 받을 프로필을 확인 — 켜진 프로필이 없거나 할당이 비어 있음
   - 주체: GSA 클라이언트
   - 위치: Global Secure Access › Connect › Traffic forwarding (프로필 토글 · Assignments)
   - 데이터: 프로필 상태 = 꺼짐, 또는 User and device assignments = No users and devices (이 프로필은 클라이언트를 통해 할당되지 않습니다). 문서 기준으로 프로필 유형에 일치하지 않는 트래픽은 Global Secure Access로 전달되지 않습니다
   - 해설: 프로필이 꺼져 있거나 대상이 비어 있으면 클라이언트는 획득할 규칙이 없습니다
3. [판단] Internet access profile만 켜고 Microsoft traffic profile은 끈 상태인가?
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding (프로필별 토글)
   - 데이터: Microsoft traffic profile 상태 · Internet access profile 상태. Internet access profile은 Microsoft traffic profile에 있는 인터넷 대상을 포함하지 않으므로 문서는 두 프로필을 함께 켜라고 안내합니다
   - 해설: 프로필 하나만 켜면 그 프로필이 다루지 않는 영역이 구멍으로 남습니다
   - 예 → 4
   - 아니오 → 5
4. [처리] Microsoft 365 트래픽이 어느 프로필에도 잡히지 않음 — 최적 라우팅 · 보안 기능 대상 밖
   - 주체: SSE 에지
   - 데이터: Exchange Online · SharePoint Online/OneDrive · Teams · Microsoft 365 Common and Office Online 정책 그룹이 획득되지 않음
   - 해설: Microsoft 트래픽은 Microsoft traffic profile에서만 획득할 수 있어서, 이 프로필을 끄면 Internet access profile이 대신 잡아 주지 않습니다
5. [처리] 조건부 액세스 연결 대상 없음 — Linked Conditional Access policies = None
   - 주체: Entra ID
   - 위치: Global Secure Access › Connect › Traffic forwarding › 프로필 › Linked Conditional Access policies
   - 데이터: 프로필에 연결된 CA 정책 0건이면 포털에 "None"으로 표시
   - 해설: 프로필 트래픽에 MFA나 기기 준수 같은 조건이 걸리지 않은 상태입니다
6. [끝] 직접 전송 — Entra에는 Global Secure Access 기록 없음
   - 주체: 로그
   - 위치: Global Secure Access › Monitor › Traffic logs (Reports Reader 이상)
   - 데이터: 클라이언트가 획득하지 않은 트래픽은 NetworkAccessTraffic 행이 생기지 않습니다
   - 해설: 어떤 트래픽이 에지를 거쳤는지 Entra에서 확인할 수 없습니다
- 시나리오: 예 :: Microsoft 프로필을 꺼서 Microsoft 365 트래픽이 에지 밖으로 나감
- 시나리오: 아니오 :: 켜진 프로필이 없어 모든 트래픽이 직접 전송되고 기록 없음

> 교육 포인트: 클라이언트를 설치해도 프로필을 켜고 사용자·기기에 할당하지 않으면 아무 트래픽도 에지로 가지 않습니다. 프로필은 "켜기(상태)"와 "누구에게(할당)" 두 가지가 모두 필요합니다.
>
> 주의: Microsoft Entra traffic은 시스템 프로필이라 포털에 보이지 않고, 다른 프로필이 하나라도 활성일 때 자동으로 켜집니다. 따로 켜거나 끌 수 없습니다.

#### L4 · ① 구성 — 프로필 상태 · 사용자 지정 프로필 · 할당 · 조건부 액세스를 정한다

1. [시작] 관리자가 Entra 관리 센터에 로그인 — 작업별로 역할이 다름
   - 주체: 관리자
   - 위치: entra.microsoft.com — Global Secure Access Administrator(프로필 보기·관리), 사용자·그룹 할당에는 Application Administrator도 함께, Private Access 앱 관리에는 Application Administrator, CA 정책 작성에는 Conditional Access Administrator
   - 데이터: Entra 역할 할당 · 제품 라이선스(Microsoft 프로필은 Entra ID P1/P2, Private·Internet은 각 제품 또는 Entra Suite 라이선스 추가)
   - 해설: 프로필 작업, 앱 작업, 조건부 액세스 작업에 필요한 역할이 서로 다릅니다
2. [처리] 프로필 목록 확인 — 시스템 프로필과 사용자 지정 프로필
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding
   - 데이터: 시스템이 만든 프로필(Microsoft · Private · Internet)과 사용자 지정 프로필이 함께 나열됩니다. 프로필 이름을 누르면 Basics · Acquisition rules · Assignments를 관리합니다. Microsoft Entra traffic은 시스템 관리 프로필이라 포털에 보이지 않습니다
   - 해설: 평가 순서 Microsoft → Private → Internet의 세 유형이 이 화면에 모여 있습니다
3. [처리] Microsoft traffic profile 켜기 — 정책 그룹별 Forward · Bypass
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding › Microsoft traffic profile 켜기 › Microsoft traffic policies › View
   - 데이터: 정책 그룹(Exchange Online · SharePoint Online and OneDrive · Microsoft Teams · Microsoft 365 Common and Office Online)과 각 항목의 Destination type · Destination · Ports · Protocol · Action(Forward 또는 Bypass)
   - 해설: Microsoft 프로필은 평가 순서의 첫 번째입니다. 항목별 Bypass를 쓰면 접근은 유지되지만 에지가 그 트래픽을 처리하지 않고, Internet access profile도 그 트래픽을 대신 획득하지 않습니다
4. [처리] Private access · Internet access profile 켜기 — 기본 프로필 토글
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding › Private access profile · Internet access profile 토글
   - 데이터: 프로필 상태 = 켜짐. Private는 Quick Access나 Private Access 앱이 있어야 실제 트래픽이 생기고, Internet 프로필의 Custom Bypass · 획득 규칙 순서는 Entra Internet Access 기능에서 다룹니다
   - 해설: 테넌트마다 유형별 기본 프로필이 하나씩 있고, 기본 프로필은 삭제할 수 없습니다
5. [처리] 사용자 지정 Private Access 프로필 만들기 — 미리 보기, 최대 10개
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding › Create new traffic forwarding profile › Private access profile › Next › Create
   - 데이터: Profile name(고유한 이름) · Description · Priority(101~199) · Status(Enabled). 미리 보기 동안 사용자 지정 Private Access 프로필은 최대 10개이고, 만든 직후에는 앱 획득 규칙과 할당이 비어 있어 둘 다 구성해야 합니다 [미리 보기 확인 필요]
   - 해설: 사용자·기기·플랫폼별로 다른 사설 앱 집합을 주거나, 일부 사용자에게만 단계적으로 배포할 때 만듭니다
6. [처리] 획득 규칙 지정 — 이 프로필이 가져갈 사설 앱
   - 주체: 관리자
   - 위치: 사용자 지정 프로필 › Acquisition rules › Quick Access 포함·제외 › "0 Applications selected" 링크 › 앱 선택 › Select (앱 쪽에서는 Enterprise applications › 앱 › Network access properties › Manage attached profiles)
   - 데이터: Quick Access 포함 여부 · 선택한 Private Access 앱 목록. Select all 후 제외할 앱만 빼는 방식도 가능하며, 앱 하나를 여러 프로필에 연결할 수 있습니다. 미리 보기 동안 사용자 지정 프로필에 선택하려면 그 앱이 기본 Private access profile에 먼저 포함되어 있어야 합니다
   - 해설: 민감한 앱은 넓게 할당한 프로필에서 빼고 별도 프로필로 묶을 수 있습니다
7. [처리] 사용자·기기 할당 — Assignments › User and device assignments
   - 주체: 관리자
   - 위치: 프로필 › Assignments › User and device assignments › View › 옵션 선택 › Save
   - 데이터: No users and devices · All users and devices · Selected users and devices(사용자·그룹·기기). 보안 그룹과 중첩 그룹을 지원하고, 동적 그룹으로 속성 기반 자동 할당도 가능합니다. 사용자·그룹 할당의 최소 클라이언트 버전은 1.7.376.0입니다
   - 해설: 전체 배포 전에 시범 그룹만 선택해 영향 범위를 좁힙니다
8. [처리] 기기 플랫폼 할당 — Device platform assignments
   - 주체: 관리자
   - 위치: 프로필 › Assignments › Device platform assignments › View › 플랫폼 선택 › Save
   - 데이터: 플랫폼 선택(예: Windows · macOS · iOS · Android). 사용자·기기 할당과 AND로 평가되어 플랫폼을 하나도 고르지 않으면 어떤 기기도 프로필을 받지 않습니다
   - 해설: 데스크톱과 모바일에 서로 다른 프로필을 주려면 플랫폼 할당을 씁니다
9. [처리] 조건부 액세스 정책 연결 — 프로필 유형마다 연결 지점이 다름
   - 주체: 관리자
   - 위치: Microsoft·Internet 프로필: Entra ID › Conditional Access › Policies › New policy › Target resources › All internet resources with Global Secure Access · Private 프로필: Global Secure Access › Applications › Enterprise applications › 앱 › Conditional Access › New policy
   - 데이터: Microsoft 프로필은 프로필의 Linked Conditional Access policies › View에서 연결된 정책을 확인·편집합니다. Private Access용 정책은 프로필이 아니라 앱 단위로 만듭니다. 정책은 Report-only로 확인한 뒤 On으로 올립니다
   - 해설: 프로필은 어떤 트래픽을 가져올지를, 조건부 액세스는 그 트래픽에 어떤 조건을 걸지를 정합니다
10. [끝] 클라이언트에서 유효 프로필 검증 — Advanced diagnostics
   - 주체: 디바이스
   - 위치: 할당된 사용자로 로그인한 기기에서 GSA 클라이언트 우클릭 › Advanced diagnostics › Forwarding profile › 트래픽 유형(M365 · Private Access · Internet Access rules) 펼치기
   - 데이터: Forwarding profile ID · last checked · 기대한 앱 세그먼트와 규칙. 문서 기준으로 Internet 프로필에 추가한 규칙은 클라이언트에 10~20분 뒤 보이고, 그래도 안 보이면 프로필을 껐다 켭니다 [확인 필요: Microsoft·Private 프로필 변경 반영 시간은 문서에 명시 없음]
   - 해설: 포털에서 저장했다고 끝이 아니라 클라이언트가 규칙을 받았는지까지 확인합니다

> 교육 포인트: 한 프로필의 구성은 "상태 → 획득 규칙 → 사용자·기기 할당 → 기기 플랫폼 할당 → 조건부 액세스" 순서로 생각하면 빠뜨리지 않습니다.
>
> 주의: 사용자 지정 Private Access 프로필은 미리 보기입니다. 문서에는 v2로 전환하는 것은 되돌릴 수 없다는 안내가 있으니 전환 전에 범위를 확인합니다 [미리 보기 확인 필요]. Device Access 프로필(미리 보기)은 별도 탭이며 기기 기준으로 할당되고 우선순위도 사용자 컨텍스트 프로필과 독립입니다.

#### L4 · ② 활성 — 프로필을 받은 클라이언트가 유형별 규칙으로 트래픽을 가져온다

1. [시작] 클라이언트가 로그인한 Entra 사용자 기준으로 프로필을 가져옴 — Microsoft Entra traffic 포함
   - 주체: GSA 클라이언트
   - 위치: Global Secure Access 클라이언트 → Global Secure Access 서비스 (프로필 정책 다운로드)
   - 데이터: 프로필은 클라이언트에 로그인한 사용자가 아니라 기기에 로그인한 Entra 사용자 기준으로 가져옵니다. Entra 사용자가 없으면 All users and devices일 때만 받습니다. Microsoft Entra traffic은 다른 프로필이 활성이면 별도 할당 없이 자동 포함되고 정책 우선순위가 가장 높아 항상 먼저 처리됩니다
   - 해설: 같은 기기에 여러 사용자가 동시에 로그인한 경우는 지원되지 않습니다
2. [판단] 사용자·기기와 기기 플랫폼이 할당 조건을 모두 만족하는가?
   - 주체: GSA 클라이언트
   - 데이터: User and device assignments AND Device platform assignments. 하나라도 맞지 않으면 그 프로필은 받지 않습니다
   - 해설: 두 조건이 AND로 평가되어 둘 다 맞아야 프로필이 적용됩니다
   - 할당됨 → 3
   - 할당 밖 → [끝] 프로필 미수신 — 직접 전송
3. [처리] 같은 유형 프로필이 여럿이면 우선순위가 가장 높은 하나만 사용
   - 주체: GSA 클라이언트
   - 데이터: 같은 트래픽 유형에서 활성 상태로 적용 가능한 프로필이 둘 이상이면 클라이언트는 우선순위가 가장 높은 프로필 하나만 씁니다
   - 해설: 기본 프로필과 사용자 지정 프로필이 겹쳐도 유효 프로필은 하나입니다
4. [판단] 목적지가 Microsoft access profile의 Forward 규칙에 일치하는가?
   - 주체: GSA 클라이언트
   - 데이터: Microsoft 정책 그룹의 Action(Forward · Bypass) 일치 여부. Bypass면 획득되지 않으며 Internet 프로필도 이 트래픽을 가져가지 않습니다
   - 해설: 세 프로필 중 가장 먼저 평가되는 것이 Microsoft access profile입니다
   - 예 → 7
   - 아니오 → 5
5. [판단] 목적지가 Private access profile 규칙(Quick Access · 앱 세그먼트)에 일치하는가?
   - 주체: GSA 클라이언트
   - 데이터: 유효 Private 프로필의 획득 규칙에 포함된 앱 세그먼트와 Quick Access
   - 해설: 두 번째로 Private access profile을 평가합니다
   - 예 → 8
   - 아니오 → 6
6. [판단] 목적지가 Internet access profile 규칙에 일치하는가?
   - 주체: GSA 클라이언트
   - 데이터: 규칙 우회·획득 규칙 평가는 Entra Internet Access 기능에서 다룹니다
   - 해설: 마지막으로 Internet access profile을 평가하고 여기서도 맞지 않으면 에지로 보내지 않습니다
   - 예 → 9
   - 아니오 → [끝] 어느 프로필에도 없음 — 직접 전송
7. [처리] Microsoft 트래픽을 에지로 전송 — 연결된 CA 평가
   - 주체: SSE 에지
   - 위치: Global Secure Access 클라이언트 터널 → Microsoft SSE 에지
   - 데이터: All internet resources with Global Secure Access를 대상으로 한 조건부 액세스 정책이 Microsoft 트래픽에 적용됩니다. 클라이언트가 인증·CA 실패 등으로 서비스에 연결하지 못하면 이 트래픽은 차단되지 않고 직접 전송되며, 차단하려면 compliant network check CA 정책이 필요합니다
   - 해설: Microsoft 프로필 트래픽의 CA 연결 지점은 프로필의 Linked Conditional Access policies입니다
   - 다음 → 10
8. [처리] Private 트래픽을 에지로 전송 — 앱 단위 CA 평가
   - 주체: SSE 에지
   - 위치: Global Secure Access 클라이언트 터널 → 에지 → 커넥터 → 사내 앱
   - 데이터: Quick Access · Private Access 앱을 대상으로 한 조건부 액세스 정책(앱 단위). 커넥터와 앱 세그먼트 처리는 Private Access 기능에서 다룹니다
   - 해설: Private Access의 조건부 액세스는 프로필이 아니라 앱에 연결됩니다
   - 다음 → 10
9. [처리] Internet 트래픽을 에지로 전송 — 보안 프로필 · CA 평가
   - 주체: SSE 에지
   - 위치: Global Secure Access 클라이언트 터널 → Microsoft SSE 에지
   - 데이터: Internet 트래픽에만 적용하려면 CA 대상 리소스를 Select resources › Internet resources로 고르고 보안 프로필을 설정합니다. 웹 필터링 판정은 Entra Internet Access 기능에서 다룹니다
   - 해설: 같은 "All internet resources with Global Secure Access" 대상은 Microsoft 트래픽과 Internet 트래픽을 함께 포함합니다
10. [끝] 유형별 기록 — 어느 프로필로 획득됐는지 로그로 확인
   - 주체: 로그
   - 위치: Global Secure Access › Monitor › Traffic logs · KQL: NetworkAccessTraffic
   - 데이터: TrafficType(microsoft365 · internet 등)으로 프로필 유형을 구분해 조회합니다 [확인 필요: Private 트래픽의 TrafficType 표기]. 클라이언트 쪽에서는 Advanced diagnostics › Traffic 탭에서 규칙 ID와 연결을 대조합니다
   - 해설: 어느 프로필 규칙이 트래픽을 가져갔는지 클라이언트와 서버 양쪽 기록으로 확인합니다
- 시나리오: 할당됨 ▸ 예 :: Microsoft 프로필 Forward 규칙에 일치해 에지로 전송
- 시나리오: 할당됨 ▸ 아니오 ▸ 예 :: Microsoft는 아니고 Private 규칙에 일치해 에지로 전송
- 시나리오: 할당됨 ▸ 아니오 ▸ 아니오 ▸ 예 :: Internet 프로필 규칙에 일치해 에지로 전송
- 시나리오: 할당됨 ▸ 아니오 ▸ 아니오 ▸ 아니오 :: 어느 프로필에도 없어 직접 전송
- 시나리오: 할당 밖 :: 할당 조건이 맞지 않아 프로필을 받지 못하고 직접 전송

> 교육 포인트: 클라이언트는 프로필을 받는 단계(할당·우선순위)와 받은 프로필로 트래픽을 가져오는 단계(Microsoft → Private → Internet 순서)가 따로 있습니다.
>
> 주의: Microsoft 프로필을 끄거나 Bypass하면 그 트래픽은 Internet 프로필에도 잡히지 않고 직접 나갑니다. 또 Microsoft 프로필 트래픽은 클라이언트가 서비스에 연결하지 못하면 차단이 아니라 직접 전송되므로 차단이 필요하면 compliant network check를 씁니다. 연결 오류 시 우회할지 차단할지는 일치한 규칙의 hardening 값에 따른다는 안내도 있습니다 [확인 필요].

### L3 · A · 프로필 평가 순서 — 세 프로필의 관계와 변경이 클라이언트에 닿는 시간

#### L4 · 트래픽 한 건이 Microsoft → Private → Internet 순으로 평가되는 길

1. [시작] 클라이언트가 워크로드별 규칙 목록을 구성 — M365 · Private access · Internet access
   - 주체: GSA 클라이언트
   - 위치: GSA 클라이언트 우클릭 › Advanced diagnostics › Forwarding profile
   - 데이터: 규칙은 워크로드별(M365 rules · Private access rules · Internet access rules)로 묶여 보이며 테넌트에서 활성인 워크로드만 나타납니다
   - 해설: 클라이언트는 프로필에서 내려온 규칙으로 트래픽을 분류합니다
2. [처리] Microsoft Entra traffic 먼저 획득 — 시스템 프로필
   - 주체: GSA 클라이언트
   - 데이터: 로그인·Graph API·인증서 검증 같은 Entra 인증 관련 FQDN·IP 집합. 다른 프로필이 활성이면 자동으로 켜지고, 정책 우선순위가 가장 높아 항상 먼저 처리됩니다
   - 해설: 이 프로필은 포털에서 보이지 않고 켜고 끌 수 없으며 별도 할당도 필요 없습니다
3. [판단] 목적지가 Microsoft access profile 규칙에 일치하는가?
   - 주체: GSA 클라이언트
   - 데이터: Microsoft 정책 그룹 항목의 Action. Forward는 에지로 보내고 Bypass는 보내지 않습니다
   - 해설: 평가는 Microsoft access profile부터 시작합니다
   - Forward → 4
   - Bypass → [끝] 직접 전송 — Internet 프로필도 이 트래픽을 획득하지 않음
   - 일치 없음 → 5
4. [끝] Microsoft 프로필로 획득 — 에지로 전송
   - 주체: SSE 에지
   - 위치: 클라이언트 터널 → Microsoft SSE 에지
   - 데이터: Microsoft traffic profile에서 획득할 수 있는 트래픽은 그 프로필에서만 획득됩니다
   - 해설: Microsoft 대상 트래픽은 Internet 프로필 규칙까지 내려가지 않습니다
5. [판단] 목적지가 Private access profile 규칙에 일치하는가?
   - 주체: GSA 클라이언트
   - 데이터: 유효 Private 프로필에 포함된 앱 세그먼트와 Quick Access
   - 해설: 두 번째 평가 대상은 Private access profile입니다
   - 예 → 6
   - 아니오 → 7
6. [끝] Private access profile로 획득 — 에지로 전송
   - 주체: SSE 에지
   - 위치: 클라이언트 터널 → 에지 → 커넥터
   - 데이터: Private 트래픽은 Global Secure Access 클라이언트로만 획득됩니다(원격 네트워크로는 획득할 수 없음)
   - 해설: 사설 앱 트래픽은 클라이언트가 없으면 이 프로필로 들어오지 않습니다
7. [판단] 목적지가 Internet access profile 규칙에 일치하는가?
   - 주체: GSA 클라이언트
   - 데이터: Internet 프로필의 획득 규칙과 우회 규칙(Entra Internet Access 기능에서 다룹니다)
   - 해설: 마지막 평가 대상은 Internet access profile입니다
   - 예 → 8
   - 아니오 → 9
8. [끝] Internet access profile로 획득 — 에지로 전송
   - 주체: SSE 에지
   - 위치: 클라이언트 터널 → Microsoft SSE 에지
   - 데이터: 에지의 웹 필터링 등 Internet Access 정책 대상
   - 해설: 앞의 두 프로필에 일치하지 않은 인터넷 트래픽이 여기로 옵니다
9. [끝] 어느 프로필에도 없음 — 직접 전송
   - 주체: 디바이스
   - 데이터: 프로필 유형에 일치하지 않는 트래픽은 Global Secure Access로 전달되지 않습니다
   - 해설: 클라이언트는 로컬 네트워크 경로로 그대로 내보냅니다
- 시나리오: Forward :: Microsoft 프로필 Forward 규칙으로 에지에 전송
- 시나리오: Bypass :: Microsoft 프로필 Bypass라 직접 전송
- 시나리오: 일치 없음 ▸ 예 :: Private 프로필 규칙에 일치해 에지에 전송
- 시나리오: 일치 없음 ▸ 아니오 ▸ 예 :: Internet 프로필 규칙에 일치해 에지에 전송
- 시나리오: 일치 없음 ▸ 아니오 ▸ 아니오 :: 세 프로필 어디에도 없어 직접 전송

> 교육 포인트: 순서는 Microsoft → Private → Internet 하나뿐이고, 어느 프로필에도 일치하지 않으면 에지로 가지 않습니다. Microsoft 프로필의 Bypass는 "Internet 프로필이 대신 잡는다"가 아니라 "직접 나간다"는 뜻입니다.
>
> 주의: 이 순서는 문서가 설명하는 프로필 유형 간 평가 순서이고, 한 유형 안의 규칙 순서(Internet의 Custom Bypass · Default Acquire 등)는 Entra Internet Access 기능을 봅니다.

#### L4 · 프로필 변경이 클라이언트에 반영되는지 확인하는 흐름

1. [시작] 관리자가 프로필 상태 · 규칙 · 할당을 변경하고 저장
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding › 프로필 › Basics · Acquisition rules · Assignments › Save
   - 데이터: 프로필 상태(enabled · disabled) · priority · associations. 이 값은 Graph(beta) networkaccess forwardingProfile의 state · priority · associations에 대응합니다 [확인 필요: beta API 이름과 필드는 변경될 수 있음]
   - 해설: 변경은 서비스에 저장되고 클라이언트가 가져가야 효력이 생깁니다
2. [처리] 클라이언트가 갱신된 프로필을 확인
   - 주체: GSA 클라이언트
   - 위치: GSA 클라이언트 › Advanced diagnostics › Forwarding profile
   - 데이터: Forwarding profile ID · Forwarding profile last checked(클라이언트가 마지막으로 갱신본을 확인한 시각) · Refresh details(캐시 다시 읽기)
   - 해설: last checked 시각이 변경 시각보다 앞이면 아직 새 규칙을 받지 않은 것입니다
3. [판단] 기대한 규칙이 클라이언트에 나타났는가?
   - 주체: 관리자
   - 데이터: Rule ID · 규칙 목록. Internet 프로필에 추가한 규칙은 클라이언트에 10~20분 뒤에 나타납니다 [확인 필요: Microsoft·Private 프로필 변경의 반영 시간은 문서에 명시 없음]
   - 해설: 변경 직후에 안 보이는 것은 정상일 수 있으니 문서에 적힌 시간만큼 기다립니다
   - 보임 → 5
   - 안 보임 → 4
4. [처리] 프로필을 껐다가 다시 켬 — 문서가 안내하는 조치
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding › 프로필 토글 끄기 후 켜기
   - 데이터: 문서는 Internet access profile에 대해 10~20분 후에도 규칙이 안 보이면 프로필을 껐다 켜라고 안내합니다 [확인 필요: 다른 프로필에도 같은 조치가 적용되는지 문서에 명시 없음]
   - 해설: 토글을 끄면 그 시간 동안 그 프로필 트래픽이 에지로 가지 않으므로 업무 시간을 피합니다
5. [끝] 유효 규칙 확인 후 사용자 재시도
   - 주체: 디바이스
   - 위치: Advanced diagnostics › Forwarding profile 탭에서 Refresh details › 트래픽 유형 펼치기
   - 데이터: 기대한 앱 세그먼트·규칙이 있는 Forwarding profile ID. 변경한 할당은 기기의 Entra 로그인 사용자 기준으로 적용됩니다
   - 해설: 규칙이 보이면 사용자가 다시 접속해 동작을 확인합니다
- 시나리오: 보임 :: 규칙이 시간 내에 반영되어 바로 확인
- 시나리오: 안 보임 :: 반영 지연으로 프로필을 껐다 켠 뒤 확인

> 교육 포인트: "저장했는데 안 된다"는 문의는 먼저 클라이언트의 Forwarding profile last checked와 규칙 목록을 확인하면 원인이 서버인지 클라이언트인지 나뉩니다.
>
> 주의: 프로필을 껐다 켜는 조치는 사용자 트래픽에 영향을 주므로 시범 그룹에서 먼저 확인합니다.

### L3 · B · 할당과 우선순위 충돌 — 누가 어떤 프로필을 받고 겹치면 무엇이 이기는가

#### L4 · 사용자·기기 조건과 플랫폼 조건이 AND로 평가되는 길

1. [시작] 클라이언트가 기기에 로그인한 Entra 사용자와 플랫폼을 확인
   - 주체: GSA 클라이언트
   - 위치: GSA 클라이언트 (최소 버전 1.7.376.0 이상에서 사용자·그룹 할당 지원)
   - 데이터: 로그인한 Entra 사용자 · 기기 ID · 기기 플랫폼. 프로필은 클라이언트에 로그인한 사용자가 아니라 기기에 로그인한 Entra 사용자 기준으로 가져옵니다
   - 해설: 할당 평가는 누가 기기에 로그인해 있는가에서 출발합니다
2. [판단] 기기에 로그인한 Entra 사용자가 있는가?
   - 주체: GSA 클라이언트
   - 데이터: Entra 사용자 로그인 여부. 사용자가 없으면 All users and devices일 때만 프로필을 받습니다
   - 해설: 로그인 전 기기는 전체 대상 프로필만 받을 수 있습니다
   - 사용자 있음 → 3
   - 사용자 없음 → 4
3. [판단] 사용자·그룹·기기가 User and device assignments에 포함되는가?
   - 주체: GSA 클라이언트
   - 데이터: No users and devices · All users and devices · Selected users and devices. 보안 그룹과 중첩 그룹을 지원하고 동적 그룹도 쓸 수 있습니다
   - 해설: 선택한 대상에 속하거나 All users and devices면 포함입니다
   - 포함 → 5
   - 미포함 → [끝] 프로필 미수신 — 사용자·기기 조건 불일치
4. [판단] User and device assignments가 All users and devices인가?
   - 주체: GSA 클라이언트
   - 데이터: 할당 옵션 값
   - 해설: 로그인 사용자가 없으면 개별 선택 대상은 판단할 수 없습니다
   - 전체 대상 → 5
   - 선택 대상 → [끝] 프로필 미수신 — 로그인 사용자가 없어 선택 대상 불일치
5. [판단] 기기 플랫폼이 Device platform assignments에 포함되는가?
   - 주체: GSA 클라이언트
   - 데이터: 선택한 플랫폼 목록. 예: All users and devices + iOS는 클라이언트가 있는 모든 iOS 기기, All users and devices + 플랫폼 없음은 아무 기기도 받지 않음
   - 해설: 사용자·기기 조건과 플랫폼 조건은 AND라서 둘 다 맞아야 합니다
   - 플랫폼 일치 → 6
   - 플랫폼 불일치 → [끝] 프로필 미수신 — 플랫폼 조건 불일치
6. [처리] 두 조건을 모두 통과 — 이 프로필이 후보가 됨
   - 주체: GSA 클라이언트
   - 데이터: 사용자·기기 조건 AND 기기 플랫폼 조건 = 참. 같은 유형 프로필이 여럿이면 다음 단계에서 우선순위로 가립니다
   - 해설: 통과한 프로필만 우선순위 비교와 규칙 평가 대상이 됩니다
7. [끝] 효과 확인 — 유효 프로필 검증
   - 주체: 디바이스
   - 위치: GSA 클라이언트 › Advanced diagnostics › Forwarding profile › 예: Private Access rules
   - 데이터: 기대한 앱 세그먼트가 보이는지 확인합니다. 한 기기에 여러 사용자가 동시에 로그인한 경우는 지원되지 않습니다
   - 해설: 기대와 다르면 로그인 사용자, 그룹 구성원, 플랫폼 선택 순서로 점검합니다
- 시나리오: 사용자 있음 ▸ 포함 ▸ 플랫폼 일치 :: 사용자와 플랫폼 조건을 모두 만족해 프로필 수신
- 시나리오: 사용자 있음 ▸ 포함 ▸ 플랫폼 불일치 :: 사용자는 맞지만 플랫폼이 달라 미수신
- 시나리오: 사용자 있음 ▸ 미포함 :: 할당 대상이 아니라 프로필 미수신
- 시나리오: 사용자 없음 ▸ 전체 대상 ▸ 플랫폼 일치 :: 로그인 전이어도 전체 대상 프로필 수신
- 시나리오: 사용자 없음 ▸ 전체 대상 ▸ 플랫폼 불일치 :: 전체 대상이어도 플랫폼이 달라 미수신
- 시나리오: 사용자 없음 ▸ 선택 대상 :: 로그인 사용자가 없어 선택 대상 프로필 미수신

> 교육 포인트: 문서의 예시표 그대로 "All users and devices + 플랫폼 None"과 "No users, groups, or devices + 아무 플랫폼"은 모두 어떤 기기도 프로필을 받지 않습니다. 플랫폼 조건을 비워 두는 실수를 가장 먼저 의심합니다.
>
> 주의: 사용자·그룹 할당은 클라이언트 1.7.376.0 이상이 필요합니다. 로그인 사용자 기준이므로 공용 PC나 다중 사용자 동시 로그인은 지원되지 않습니다.

#### L4 · 같은 유형 프로필이 겹칠 때 우선순위로 하나가 정해지는 길

1. [시작] 한 사용자·기기가 Private access 프로필 둘 이상에 해당 — 예: 기본 프로필 + 사용자 지정 프로필
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding (프로필 목록 · 각 프로필 Assignments)
   - 데이터: 기본 Private access profile(전체 앱)과 사용자 지정 프로필(예: 특정 그룹에 민감 앱을 제외한 앱 집합)이 같은 사용자에게 동시에 적용 가능
   - 해설: 사용자 지정 프로필은 같은 사용자에게 다른 앱 집합을 주려고 만드는 것이라 겹침이 자연스럽게 생깁니다
2. [처리] 활성 상태인 프로필만 후보로 남김
   - 주체: GSA 클라이언트
   - 데이터: 프로필 Status(Enabled · Disabled). 꺼진 프로필은 후보에서 빠집니다
   - 해설: 프로필을 Disabled로 두면 삭제하지 않고 적용만 멈출 수 있습니다
3. [판단] 후보 프로필이 둘 이상인가?
   - 주체: GSA 클라이언트
   - 데이터: 같은 트래픽 유형의 적용 가능한 활성 프로필 수
   - 해설: 하나뿐이면 우선순위 비교가 필요 없습니다
   - 프로필 여럿 → 4
   - 프로필 하나 → 5
4. [처리] 우선순위가 가장 높은 프로필 하나만 사용
   - 주체: GSA 클라이언트
   - 위치: 프로필 › Basics › Priority (사용자 지정 Private Access 프로필은 101~199)
   - 데이터: Priority 값. 클라이언트는 적용 가능한 프로필 중 우선순위가 가장 높은 하나만 사용합니다 [확인 필요: 숫자가 클수록 우선인지 작을수록 우선인지, 기본 프로필의 우선순위 값은 문서에 명시 없음]
   - 해설: 나머지 프로필의 규칙은 이 기기에서 쓰이지 않으므로, 필요한 앱은 우선되는 프로필에 들어 있어야 합니다
5. [처리] 유효 프로필의 규칙을 클라이언트에서 확인
   - 주체: 디바이스
   - 위치: GSA 클라이언트 › Advanced diagnostics › Forwarding profile › Private Access rules
   - 데이터: Forwarding profile ID · 앱 세그먼트 목록. 문서는 여러 프로필이 적용될 수 있으면 우선순위가 가장 높은 프로필이 유효한지 확인하라고 안내합니다
   - 해설: 포털 설정보다 클라이언트가 실제로 받은 프로필이 최종 근거입니다
6. [판단] 기대한 앱 세그먼트가 보이는가?
   - 주체: 관리자
   - 데이터: 앱 세그먼트 · Rule ID
   - 해설: 보이지 않으면 우선순위나 획득 규칙에서 빠졌을 가능성이 큽니다
   - 기대와 일치 → 7
   - 기대와 다름 → 8
7. [끝] 우선순위 구성 정상 — 시범 사용자 확인 완료
   - 주체: 디바이스
   - 데이터: 유효 프로필이 의도한 앱 집합을 제공
   - 해설: 다른 사용자·기기에도 같은 방식으로 확인합니다
8. [처리] 원인 점검 — 우선순위 · 할당 · 앱 포함 여부
   - 주체: 관리자
   - 위치: 사용자 지정 프로필 › Basics(우선순위·상태) · Acquisition rules(앱 선택) · Assignments / 앱 › Network access properties › Manage attached profiles
   - 데이터: 겹친 프로필 중 어느 것이 우선되는지, 필요한 앱이 그 프로필의 획득 규칙에 있는지, 미리 보기 동안 사용자 지정 프로필에 선택할 앱이 기본 Private 프로필에 포함돼 있는지 확인합니다
   - 해설: 이유를 찾으면 우선순위나 규칙을 고친 뒤 5번으로 돌아가 다시 확인합니다
9. [끝] 수정 후 클라이언트 재확인 필요
   - 주체: 관리자
   - 위치: Advanced diagnostics › Forwarding profile › Refresh details
   - 데이터: 변경은 클라이언트가 새 프로필을 받은 뒤에 반영됩니다
   - 해설: 고친 직후에는 반영 시간을 기다린 뒤 확인합니다
- 시나리오: 프로필 여럿 ▸ 기대와 일치 :: 우선순위가 높은 프로필이 의도한 앱 집합을 제공
- 시나리오: 프로필 여럿 ▸ 기대와 다름 :: 우선되는 프로필에 앱이 없어 우선순위·규칙을 수정
- 시나리오: 프로필 하나 ▸ 기대와 일치 :: 겹침 없이 하나의 프로필이 의도대로 적용
- 시나리오: 프로필 하나 ▸ 기대와 다름 :: 겹침은 없지만 앱 누락 등으로 구성을 수정

> 교육 포인트: 프로필이 겹치면 규칙이 합쳐지는 것이 아니라 우선순위가 가장 높은 프로필 하나만 쓰입니다. 그래서 "A 프로필에는 있는데 안 된다"는 문의는 B 프로필이 우선되는지부터 확인합니다.
>
> 주의: 사용자 지정 Private Access 프로필은 미리 보기이며 최대 10개이고, 지원 한도와 동작이 바뀔 수 있습니다 [미리 보기 확인 필요]. 사용자 지정 프로필을 삭제하면 복원할 수 없고, 기본 프로필은 삭제할 수 없으니 삭제 전에 앱·할당을 다른 프로필로 옮깁니다.

### L3 · C · 단계적 배포 — 시범 그룹에서 전체로 넓히는 순서

#### L4 · 시범 그룹 → 조건부 액세스 확인 → 대상 확대

1. [시작] 배포 범위를 정함 — 시범 그룹 · 플랫폼 · 프로필
   - 주체: 관리자
   - 위치: Entra ID › 그룹 (보안 그룹 · 동적 그룹)
   - 데이터: 시범 그룹(보안 그룹 또는 속성 기반 동적 그룹) · 대상 플랫폼 · 켜려는 프로필 유형. 클라이언트는 최소 1.7.376.0 이상
   - 해설: 처음부터 전체 사용자에게 켜지 않고 영향이 작은 그룹으로 시작합니다
2. [처리] 시범 그룹에만 프로필 할당
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding › 프로필 › Assignments › User and device assignments › Selected users and devices › Save (+ Device platform assignments)
   - 데이터: Selected users and devices = 시범 그룹, 플랫폼 = 시범 대상 플랫폼. 사용자 지정 Private Access 프로필(미리 보기)을 만들면 시범 사용자에게만 별도 앱 집합을 줄 수 있습니다
   - 해설: 할당이 곧 배포 범위이므로 범위를 줄이는 가장 안전한 단추입니다
3. [처리] 조건부 액세스 정책을 Report-only로 먼저 만듦
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Policies › New policy › Enable policy = Report-only (Private는 Global Secure Access › Applications › Enterprise applications › 앱 › Conditional Access)
   - 데이터: 대상 사용자(비상용 계정 제외) · 대상 리소스(All internet resources with Global Secure Access 또는 Private 앱) · 허용 조건
   - 해설: 정책 설정을 확인한 뒤에 On으로 올리고, 비상용 계정은 항상 제외합니다
4. [처리] 시범 기기에서 효과 확인
   - 주체: 디바이스
   - 위치: GSA 클라이언트 › Advanced diagnostics › Forwarding profile · Global Secure Access › Monitor › Traffic logs
   - 데이터: 기대한 규칙·앱 세그먼트 · TrafficType별 NetworkAccessTraffic 행. 규칙 반영 시간(Internet은 10~20분)을 기다립니다
   - 해설: 시범 사용자가 평소 쓰는 앱이 정상인지 클라이언트와 로그 양쪽으로 봅니다
5. [판단] 시범 결과에 문제가 없는가?
   - 주체: 관리자
   - 데이터: 시범 사용자 문의 · 트래픽 로그 · Report-only 결과
   - 해설: 문제가 있으면 확대하지 않고 범위를 되돌립니다
   - 이상 없음 → 6
   - 문제 발견 → [끝] 롤백 — 할당을 No users and devices로 바꾸거나 프로필을 끔(Disabled)
6. [처리] 대상 확대 — 그룹 추가 또는 All users and devices
   - 주체: 관리자
   - 위치: 프로필 › Assignments › User and device assignments · Device platform assignments
   - 데이터: Selected users and devices에 그룹 추가, 또는 All users and devices. 플랫폼은 단계적으로 추가(예: Windows·macOS 먼저, 이후 모바일)
   - 해설: 한 번에 하나씩 넓혀서 문제 원인을 좁힙니다
7. [처리] 조건부 액세스 정책을 Report-only에서 On으로
   - 주체: 관리자
   - 위치: Entra ID › Conditional Access › Policies › 정책 › Enable policy = On
   - 데이터: 정책 상태 On. Microsoft·Internet 프로필은 프로필의 Linked Conditional Access policies › View에서 연결 상태를 확인합니다
   - 해설: 프로필 범위가 안정된 뒤에 조건을 강제로 올립니다
8. [끝] 전체 운영 — 우선순위와 사용자 지정 프로필 정리
   - 주체: 관리자
   - 위치: Global Secure Access › Connect › Traffic forwarding › 프로필 목록 · 각 프로필 Basics
   - 데이터: 우선순위·상태·할당을 점검하고 더는 쓰지 않는 사용자 지정 프로필은 삭제(복원 불가, 삭제 전 앱·할당 이전)합니다
   - 해설: 운영 중에는 프로필 겹침과 반영 지연을 같은 절차로 점검합니다
- 시나리오: 이상 없음 :: 시범 그룹 검증 후 대상을 넓히고 정책을 On으로 전환
- 시나리오: 문제 발견 :: 시범에서 문제를 발견해 할당 해제로 롤백

> 교육 포인트: 배포 속도는 할당 범위(사용자·그룹·플랫폼)로 조절하고, 강제 수준은 조건부 액세스의 Report-only → On으로 조절합니다. 두 축을 따로 올립니다.
>
> 주의: 사용자 지정 Private Access 프로필은 미리 보기라 운영 전에 한도(최대 10개)와 우선순위 규칙을 확인합니다 [미리 보기 확인 필요]. 프로필을 껐다 켜는 롤백은 해당 트래픽이 에지를 거치지 않게 만들므로 영향 범위를 먼저 확인합니다.
