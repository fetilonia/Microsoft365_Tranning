# 보드 규격 v3

```text
┌ 상단 바 ─ L1 › L2 › L3 › L4 단계 · [◀ 이전 기능] [다음 기능 ▶] [▶ 처음부터 재생] ┐
├ 왼쪽 블레이드 ──────┬ 중앙 화면 ─────────────────────────────────────────────┤
│ L1 Entra Admin Ctr  │ L2 제목 · 한 줄 소개 · 메뉴 경로 · 라이선스               │
│  ▸ 메뉴 그룹        │ L3 탭                                                    │
│     · L2 기능 카드  │ [⓪ 비활성] [① 구성] [② 활성] [전체 재생]  ← 시나리오 버튼 │

│                     │ 설정 / 강제 / 증적 3칸 · 교육 포인트 · 주의 · 출처         │
```

## V2 · 왼쪽 블레이드

- L1 아래에 `- 메뉴(Admin Center):`의 첫 단어(개요 · ID · 애플리케이션 · 보호 · ID 거버넌스 · 외부 ID · 하이브리드 관리 · Global Secure Access · 에이전트 ID · Verified ID · 모니터링 및 상태)로 그룹을 묶고, 그 안에 L2 카드를 둡니다.
- 카드 = 제목 + 한 줄 소개 + 시나리오 개수. 선택된 카드는 코랄 테두리.

## V3 · 중앙 화면

1. 기능을 고르면 `0 · 기능 상태 전이` 탭이 먼저 열리고 ⓪ ① ② 버튼이 놓입니다. 버튼을 누르면 그 시나리오만 재생합니다.
2. 시나리오 의미는 모든 기능이 같습니다.

| 버튼 | 뜻 | 그림이 답하는 질문 |
| --- | --- | --- |
| ⓪ 비활성 | 기능을 켜지 않았을 때의 기본 동작 | "안 켜면 무슨 일이 생기나(어떤 위험이 남나)?" |
| ① 구성 | 관리자가 포털에서 설정을 만들고 켜는 과정 | "관리자가 어디서 무엇을 어떤 값으로 설정하나?" |
| ② 활성 | 켠 뒤 실제 요청이 들어왔을 때의 데이터 흐름 | "요청이 누구를 거쳐 어디서 판정되고 무엇이 기록되나?" |

3. `A` `B` `C` 탭은 그 기능의 핵심 동작을 더 깊게 보여 주는 흐름입니다(예: 조건부 액세스의 정책 평가 엔진).
4. 그림 아래 **Task 상세 표**는 노드와 1:1입니다. 컬럼 = `# · 주체 · Task · 위치 · 데이터/결과`. 재생 중인 Task 행이 강조되고, 노드나 행을 누르면 그 Task로 이동합니다.

## V4 · 애니메이션 규칙

흐름 하나는 Task `n`에서 `n+1`로 가는 **구간**의 연속입니다. 구간마다:

| 순서 | 동작 | 시간 `[제안]` |
| --- | --- | --- |
| 1 | **시작 노드** 테두리 하이라이트 켜짐 | 0.2초 |
| 2 | 시작 노드 가장자리에서 **점 Fade-In** | 0.2초 |
| 3 | 점이 선을 따라 이동 | 0.8초 |
| 4 | 끝 노드 가장자리에서 **점 Fade-Out**, 동시에 **끝 노드 테두리 하이라이트** | 0.2초 |
| 5 | 시작 노드 하이라이트 꺼짐. 끝 노드는 다음 구간의 시작 노드가 됨 | 0.3초 |

- 판단 노드는 재생 중인 경로의 분기만 보냅니다. `재생할 경로` 칩으로 허용/차단 경로를 고릅니다.
- 차단 노드는 빨강. 시나리오의 첫·마지막 노드는 하이라이트를 한 겹 더 두껍게 합니다.
- 속도(0.5× · 1× · 2×) · 일시정지 · "동작 줄이기" 설정 대응.

## V5 · Task 노드 작성 규칙 (v3 핵심)

노드 한 줄 = **관리자나 시스템이 실제로 하는 일 하나**입니다. "구성한다" 같은 뭉뚱그린 문장 대신, 포털에서 누르는 곳과 고르는 값, 그 결과로 바뀌는 데이터까지 씁니다.

```text
N. [유형] Task 제목 — 보조 설명(값·옵션)
   - 주체: 관리자 | 사용자 | Entra ID | 앱 | 리소스 | 디바이스 | 온프레미스 | 로그 | 외부
   - 위치: 보호 › 조건부 액세스 › 정책 › 새 정책 만들기      ← 포털 경로, 또는 API · 도구 · 명령
   - 데이터: 이 Task가 읽고 쓰는 객체 · 필드 · 토큰 클레임 · 로그 테이블
   - 해설: 재생 중 설명 줄에 나오는 한 문장
   - 예 → 5            ← 판단 노드의 분기
   - 아니오 → [차단] 차단 — 이유
```

- 유형: `시작` `처리` `판단` `차단` `끝`.
- `주체` `해설`은 모든 노드에 씁니다. `위치` `데이터`는 해당될 때 반드시 씁니다(특히 ① 구성).
- **깊이 기준**: ⓪은 4~7개, ①은 6~10개(포털 단계마다 하나), ②는 6~10개(요청이 지나는 구성 요소마다 하나). 기능당 L3는 `0` 외에 핵심 동작 1~3개.
- 위치에는 실제 포털 메뉴 이름과 설정 이름만 씁니다. 확신이 없으면 `[확인 필요]`를 붙입니다.
- 그림 아래 메모: `> 교육 포인트:` `> 주의:` `> 예시:` `> 출처: https://learn.microsoft.com/...` (출처는 Microsoft Learn만)

## V6 · 조건부 액세스 정책 시뮬레이터 (L3 `S`)

조건부 액세스는 시나리오 한두 개로 담기에 범위가 넓어서, `S · 정책 시뮬레이터` 탭은 **옵션을 고르면 평가 흐름이 바뀌는 상호작용 도식**으로 만듭니다.

- 화면: ① 할당(사용자·그룹·역할·게스트·워크로드 ID·Agent ID, 제외) → ② 대상 리소스(앱 · 사용자 작업 · 인증 컨텍스트 · Global Secure Access 트래픽 · 에이전트 리소스) → ③ 조건(위치 · 플랫폼 · 클라이언트 앱 · 디바이스 필터 · 사용자/로그인/내부자 위험 · 인증 흐름) → ④ 허용(차단 / 컨트롤 AND·OR) → ⑤ 세션 → ⑥ 정책 상태.
- 오른쪽 `테스트 로그인`(누가 · 어디서 · 어떤 기기·클라이언트로 · 위험 · 이미 한 MFA)을 바꾸면 같은 정책이 다른 결과를 냅니다. 결과는 `접근 허용 / 차단 / 정책 미적용 / 보고 전용` + 로그인 로그 `result` 값으로 표시됩니다.
- 옵션을 누르면 아래 상세 패널에 **동작 · 포털 위치 · 방법별 표현(브라우저/모바일/데스크톱) · 사용자 경험 · 로그 · 지원 주체 · 제약 · 출처**가 나옵니다.
- **판정 규칙은 화면 엔진(`sim_engine.js`)이, 문구는 이 MD가 가집니다.** 옵션 id(`u-all` `gc-mfa` `s-frequency` …)가 둘을 잇습니다 — id는 바꾸지 않습니다. 새 옵션을 추가하려면 엔진도 함께 고칩니다.
- 예시 정책은 `- 프리셋: 이름 :: 설명 :: 정책 :: 테스트 로그인` 한 줄입니다. 정책은 `그룹key=옵션id,옵션id;…`, 테스트는 `principal=admin;location=other;…` 형식입니다.
- 그룹은 `#### 그룹 · <key> · <제목>`, 옵션은 `##### 옵션 · <id> · <이름>`이고, 필드(`소개 위치 동작 매칭 충족 판정 표현 사용자 경험 미충족 시 지원 주체 제약·주의 로그 노드 제목 노드 보조 해설 주체 데이터 출처`)는 한 줄에 하나씩 씁니다. 글자 수 제한과 필드 의미는 `교육보드_HTML/parts_sim/SPEC.md`를 따릅니다.
- 화면 확인용 주소: `entra-edu-board.html?f=조건부&l3=1&p=<예시번호>&d=<그룹:옵션id>&o=<열어 둘 드롭다운 필드>`
- **입력 방식**: 옵션은 버튼 나열이 아니라 **페이지 안에서 열리는 드롭다운**(시스템 select 미사용)으로 고릅니다. 목록은 유형별 머리글(예: 대상 리소스 → 앱 / 사용자 작업 / 인증 컨텍스트 / Global Secure Access 트래픽 / 에이전트)로 나뉘고, 다중 선택은 체크박스, 단일 선택은 라디오입니다. ‘모든 사용자’와 ‘선택한 사용자 및 그룹’은 동시에 선택되지 않습니다.
- **선택에 따라 달라지는 규칙** (엔진 `sim_ui.js`의 `simRules()` — 근거는 Learn 문서, 불확실한 것은 `[확인 필요]`):
  - 선택할 수 없는 옵션은 숨기지 않고 **회색 + 이유 문구**(⛔)로 보여 줍니다. 눌러도 선택되지 않고 상세 패널에 같은 이유가 나옵니다.
  - 선택 때문에 이미 고른 값이 무효가 되면 **자동으로 해제/조정하고 ‘🔄 자동으로 조정했습니다’ 알림**에 이유를 남깁니다.
  - 주요 규칙: 워크로드 ID·Agent ID 대상 → 허용은 ‘차단’만(테스트 주체·대상 리소스도 맞춤) · MFA ↔ 인증 강도 동시 불가 · 암호 변경 필요는 ‘사용자 위험’ + ‘모든 리소스’에서만, 다른 컨트롤과 불가 · 사용자 작업은 보고 전용 불가(서로 배타) · 규격 네트워크는 Private Access에 불가 · 영구 브라우저 세션은 ‘모든 리소스’에서만 · GSA 보안 프로필은 ‘GSA 인터넷 트래픽’에서만 · 승인된 앱/앱 보호가 단독이면 macOS·Linux 플랫폼 불가 · 게스트 전용 정책은 승인된 앱·앱 보호·암호 변경 불가.
  - 같은 조건에 맞는 컨트롤에는 👍 **권장** 표시가 붙습니다(로그인 위험 → MFA·인증 강도, 사용자 위험 → 위험 해결·암호 변경).
- **하위 설정**: 옵션을 고르면 그 아래에 세부 선택이 나타나 흐름·판정에 반영됩니다 — 인증 강도(MFA/암호 없는/피싱 방지), 로그인 빈도, 영구 세션 방식, CAE 모드(‘사용 안 함’은 ‘모든 리소스 + 조건 없음’에서만), 앱 제어 방식, 명명된 위치 유형, 디바이스 필터 규칙(미등록 디바이스는 속성이 null이라 `-eq`가 일치하지 않고 `-ne`는 일치), 인증 컨텍스트. 예시 정책은 `sub.<옵션id>=값`으로 지정합니다.
- **우측은 선택 없이 요약만 보여 주는 읽기 전용 패널**입니다. `📋 정책 요약`(할당·대상 리소스·조건·허용·세션·상태와 예상 결과)과 `🧪 테스트 로그인`이 왼쪽 선택을 즉시 그대로 반영합니다.
  - 정책에 정의된 신호(주체·위치·플랫폼·클라이언트 앱·로그인/사용자/내부자 위험·인증 흐름·디바이스 필터에 맞는 디바이스·앱이 아닌 대상 리소스)는 **정책에서 자동으로 가져옵니다**(`정책` 표시). 예) 플랫폼에 iOS를 고르면 테스트 로그인 플랫폼이 iOS가 됩니다.
  - 정책이 정하지 않는 신호(디바이스 상태·접근 앱·MFA 이력·약관 동의·세션 경과 시간·CAE 이벤트 등)는 **왼쪽 `⑦ 로그인 상황`**에서 고르고, 우측에는 `입력`으로 표시됩니다. 해당 컨트롤을 고를 때만 나타납니다.
  - 정책과 다른 로그인으로 평가하려면 ⑦의 `테스트 로그인을 직접 지정하기`로 수동 모드를 켭니다(모든 신호를 직접 선택, 우측 표시는 `수동`).
- **토큰 발급 이후 단계(세션 컨트롤의 런타임)**: 세션 컨트롤을 고르면 구성도가 `토큰 발급 · 세션 시작` 뒤로 이어지고, 이후 노드에는 `토큰 이후` 표시가 붙습니다(엔진 `SIM_RUNTIME_ORDER`, 보고 전용 정책은 강제하지 않으므로 생략).
  - **앱 적용 제한**: Entra는 판정하지 않고 앱(SharePoint/Exchange)에 **디바이스 정보(준수·하이브리드 조인)만 전달** → 앱이 `관리되는 디바이스?`를 보고, 아니면 **앱 쪽 정책**(SharePoint 관리 센터 › 정책 › 액세스 제어 › 비관리 디바이스: 전체 허용 / 제한된 웹 전용(편집 허용·불가) / 차단)으로 판정합니다. 제한된 웹 전용은 브라우저 전용이라 데스크톱·모바일 앱(Office 포함)은 접근할 수 없고, 다운로드·인쇄·동기화가 막힙니다. Exchange(OWA) 쪽 정책명은 `[확인 필요]`.
  - **조건부 액세스 앱 제어**: 세션을 Defender for Cloud Apps 프록시로 라우팅 → 세션 정책(모니터링만 / 다운로드 차단 / 사용자 지정)을 활동마다 적용.
  - **토큰 보호**: 토큰이 기기 키에 바인딩 → 키 소유 증명 검증, 다른 기기 재사용은 `unbound`로 거부. **CAE**: 리소스가 이벤트 구독 → 이벤트 시 401 + claims challenge → 재인증·재평가(엄격한 위치 적용은 즉시 거부). **로그인 빈도**: 마지막 인증 시각 vs 주기 → 초과 시 재인증 프롬프트(매번은 5분 안에는 다시 묻지 않음). **영구 세션**: 브라우저를 닫아도 유지 / 닫으면 종료. **복원력 기본값 끄기**: 장애 중 세션 만료 시 거부. **GSA 보안 프로필**: 클라이언트 → 에지 → 보안 프로필 정책 적용.
  - 이 단계용 테스트 입력(앱 제어 활동·토큰 사용 기기·CAE 이벤트·마지막 인증 후 경과·Entra 서비스 상태·GSA 접속 대상)은 해당 세션 컨트롤을 고를 때만 나타납니다. 결과 패널에는 컨트롤별 `→ 토큰 이후: …` 요약이 붙습니다.
- **구성도는 이 로그인이 실제로 지나는 단계만 그립니다(기본)**: 예시 정책·옵션·테스트 로그인이 바뀌면 노드 구성 자체가 달라집니다(조건 노드 유무, 허용 컨트롤 판단·프롬프트, 세션 컨트롤의 토큰 이후 단계, 종료 노드). 판단 노드에는 `이번 로그인` 줄로 그 로그인에서의 판정값이 표시되고, 반대로 판정됐을 때의 행선지는 Task 상세에 적힙니다. 결과 패널의 `전체 평가 구조 보기` 토글을 누르면 가지(미적용·차단 종료 노드 포함) 전체를 그리고 지나는 경로를 주황색으로 강조합니다.
- **충족·미충족 색**: 구성도에서 이 로그인이 지나는 선은 판정 결과로 색이 정해집니다. 충족·일치·완료 등은 **초록**, 미충족·불일치·차단 등은 **빨강**이고, 그 판단 노드의 테두리도 같은 색입니다. 판정이 아닌 분기(예: 제한된 웹 전용)는 주황색입니다.
- **시나리오 자동 생성**: 결과 패널의 `시나리오` 칩은 선택한 정책 옵션으로 서로 다른 결과가 나오는 로그인 변형을 엔진이 자동으로 찾아 만듭니다(정책 그대로 · 추가 요구 수행 못 함 · 비준수 기기 · 대상 아님 등). 칩을 누르면 해당 변형이 테스트 로그인에 적용돼 구성도·평가 순서·우측 요약(`시나리오` 표시)이 바뀝니다. 왼쪽 옵션이나 예시 정책을 바꾸면 시나리오가 다시 만들어집니다.
- **카드 상세 팝업**: 카드 안에서는 글자가 잘려 보일 수 있으므로 위치·데이터·해설 같은 세부는 팝업에 충분히 길게 씁니다(보강 기준: 포털 경로·API·권한·역할·라이선스·기본값·제한·지연·예외·실패 조건, 모두 Microsoft Learn 확인, 미확인은 `[확인 필요]`). 구성도의 카드를 누르면 잘리지 않은 전체 내용(구성 · 이번 로그인 · 설명 · 위치 · 데이터 · 반대로 판정되면)이 팝업으로 열립니다. `Esc`·`✕`·바깥 클릭으로 닫습니다. 딥링크 `&node=<번호>`로 바로 열 수 있습니다.
- **분기 라벨은 한쪽만**: 조건 분기(예/아니오, 일치/불일치 등)의 라벨은 선택한 경로가 지나는 쪽만 보입니다. 경로가 지나지 않는 분기 노드는 첫 번째 쪽 라벨만 보입니다.
- **시나리오 버튼 이름**: 한 분류(L3)에 시나리오(L4)가 여럿이면 버튼은 각 L4의 제목(⓪①② 상태 전이는 해당 기호)으로 보입니다. 전체 재생 버튼은 상태 전이 분류에서만 `⓪→②`이고, 그 외에는 `1→N`입니다.
- **구역·프로토콜 표기**: 카드의 주체 칩은 구역별로 구분합니다(예: `PTA 에이전트` · `DC (AD)` · `Service Bus` · `WAP (DMZ)` · `프록시 · 방화벽` · `AD FS` · `Entra ID`). 선 위의 라벨에 `Kerberos`·`NTLM`·`LDAP`·`WS-Fed`·`SAML`·`HTTPS`·`TLS`로 시작하는 글자를 쓰면 판정이 아닌 **프로토콜 표시**(파란 라벨)로 그려집니다. 분기가 아닌 선에도 `- Kerberos → 7`처럼 라벨을 줄 수 있습니다.
- **분기별 시나리오(재생할 경로)**: 분기가 있는 시나리오(L4)는 경로마다 버튼이 나오고, 버튼 이름은 판단을 나열하지 않고 **그 경로의 요약**(상황 + 결과, 12~36자)입니다. 요약은 각 L4의 마지막 노드 아래에 `- 시나리오: <선택지 라벨을 ' ▸ '로 이은 키> :: <요약>` 줄로 직접 씁니다(예: `- 시나리오: 아니오 ▸ 예 :: 허용 방법으로 검증 후 토큰 발급`). 키는 분기 지점(라벨 붙은 선택지가 둘 이상인 노드)에서 고른 라벨을 경로 순서대로 이은 것이며, 경로와 맞지 않거나 빠진 키는 빌드 점검이 경고합니다. 칩 순서는 `완료` 경로가 먼저이고 같은 묶음 안에서는 `- 시나리오:` 줄을 쓴 순서를 따르므로, 처음 보여 줄(기본) 시나리오는 그 줄을 맨 앞에 쓰면 됩니다. 칩에는 `완료`/`차단` 배지가 붙고, 칩에 마우스를 올리면 지나는 판단 전체가 툴팁으로 나옵니다. 칩을 누르면 그 경로를 강조·재생하고, 카드 팝업의 `분기 선택지` 행에는 모든 선택지와 선택한 경로(▶)가 표시됩니다.
- **하단 Task 상세는 기본으로 접혀 있고**, `Task 상세` 토글(오른쪽 `펼쳐서 전체 내용 확인`)을 누르면 열립니다. 열면 **선택한 시나리오의 단계만**: 경로가 지나는 Task만 경로 순서대로 보이고(`선택한 시나리오 N단계 (전체 M개 중)`), `전체 Task 보기` 버튼으로 나머지를 흐리게 함께 볼 수 있습니다. 경로 밖 카드를 누르면 그 행이 보이도록 전체 보기로 전환됩니다. 칩을 누르면 그 경로를 강조·재생하고, 카드 팝업의 `분기 선택지` 행에는 모든 선택지와 선택한 경로(▶)가 표시됩니다.
