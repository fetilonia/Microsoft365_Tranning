## L2 · 개요 · 권장 사항 — Identity Secure Score

- 설정(Control Plane): 권장 사항 검토 · 상태 변경 (연기 · 해제) | 보안 점수 개선 조치 상태 (해결 예정 · 위험 수락 · 타사로 해결 등)
- 강제(Enforcement): (평가 기능 — 직접 강제하지 않음) | 개선 조치는 각 기능 L2 (MFA · 조건부 액세스 · 암호 보호 등)에서 구성
- 증적(Evidence): Identity Secure Score (%) · 권장 사항 상태 | GET /beta/directory/recommendations · 감사 로그 서비스 "Microsoft Entra recommendations" (완료 처리만)
- 메뉴(Admin Center): 개요 > 권장 사항 · 보안 점수
- 라이선스(License): Identity Secure Score는 무료 포함 · 일부 권장 사항은 유료 라이선스 필요 [확인 필요: 권장 사항별 라이선스]

### L3 · 0 · 기능 상태 전이 — 미확인 → 권장 사항 검토 → 점수 개선

#### L4 · ⓪ 비활성 — 구성 상태를 점검하지 않는다

1. [시작] 테넌트를 운영하며 설정이 점점 달라짐
   - 주체: 관리자
   - 위치: 여러 관리자가 변경하는 테넌트 설정 전반
   - 데이터: 관리자 추가 · 앱 동의 · 인증 방식 변경 이력
   - 해설: 시간이 지나면 권장 구성에서 조금씩 멀어집니다
2. [처리] 권장 사항을 열어 보지 않음
   - 주체: 관리자
   - 위치: Entra ID › 개요 (Overview) › 권장 사항 (Recommendations) — 열람은 최소 Reports Reader 역할
   - 데이터: Entra ID는 매일 테넌트 구성을 분석해 직전 24시간 활동을 반영하며 드물게 최대 72시간까지 지연됩니다 · 새 권장 사항 메일(미리 보기)은 권장 사항별로 정해진 역할 보유자에게만 가고, PIM을 쓰면 그 역할로 활성화돼 있어야 받으며 활성 할당자가 없으면 메일이 발송되지 않습니다
   - 해설: 분석 결과가 쌓여도 확인하지 않으면 소용이 없습니다. 메일 알림이 미리 보기이고 수신 조건이 까다로워 정기적으로 직접 확인하는 것이 안전합니다
3. [처리] 기준 없이 "잘 돼 있다"고 판단
   - 주체: 관리자
   - 위치: Entra ID › Identity Secure Score (또는 개요 › 권장 사항 상단 점수) — 열지 않은 상태
   - 데이터: 점수 · 조치 근거 없음 (감에 의존) · Identity Secure Score는 무료·유료 고객 모두 사용할 수 있고 Microsoft 권장 구성과의 일치도를 %로 보여 줍니다
   - 해설: 객관적 지표가 없어 개선이 필요한지조차 합의되지 않습니다
4. [처리] 놓친 설정이 누적
   - 주체: Entra ID
   - 위치: 개요 › 권장 사항 › 보안 (Security) 필터 — 점수에 포함되는 권장 사항
   - 데이터: 예: Designate more than one Global Administrator · Enable policy to block legacy authentication · Do not allow users to grant consent to unreliable applications · Require multifactor authentication (MFA) for administrative roles
   - 해설: 알기만 하면 쉽게 고칠 항목이 방치됩니다
5. [끝] 미구성 항목을 인지하지 못함
   - 주체: 로그
   - 위치: 개요 › 권장 사항 목록의 상태 (Status) 열
   - 데이터: 상태 값은 Active · Completed · Dismissed · Postponed 네 가지이며 Active 항목이 계속 늘어남 (확인하지 않음)
   - 해설: 위험이 보이지 않은 채로 남아 있습니다

#### L4 · ① 구성 — 권장 사항을 검토하고 처리 방침을 정한다

1. [시작] 관리자가 Entra Admin Center에 로그인
   - 주체: 관리자
   - 위치: entra.microsoft.com — 권장 사항 열람은 최소 Reports Reader (Security Reader · Global Reader도 읽기 전용), Identity Secure Score 대시보드는 Global Reader 이상으로 로그인
   - 데이터: 권장 사항 상태 변경(Update)의 최소 역할은 Authentication Policy Administrator (Security Administrator · Exchange Administrator 등도 가능) · Identity Secure Score 개선 조치는 보기 최소 Service Support Administrator, 상태 변경 최소 SharePoint Administrator · Graph 권한은 DirectoryRecommendations.Read.All(읽기) · DirectoryRecommendations.ReadWrite.All(변경)
   - 해설: 보기 전용 역할과 변경 가능한 역할이 다릅니다. 일부 권장 사항은 P2 등 별도 라이선스가 있어야 보고 조치할 수 있습니다
2. [처리] 점수와 권장 사항 목록 열기
   - 주체: 관리자
   - 위치: Entra ID › Identity Secure Score (대시보드) 또는 Entra ID › 개요 (Overview) › 권장 사항 (Recommendations) 상단의 Identity Secure Score
   - 데이터: 점수(%) · 권장 사항 목록(이름 · 상태 · 우선순위 · 영향받는 리소스 유형 Users/Applications/Tenant) · 점수 대상 항목의 secure score points
   - 해설: 맨 위 점수가 Microsoft 권장 구성과 얼마나 일치하는지 보여 줍니다. 점수는 24시간마다 다시 계산됩니다
3. [처리] 보안 필터로 점수 대상 항목만 보기
   - 주체: 관리자
   - 위치: 권장 사항 › 보안 (Security) 필터 카드
   - 데이터: Identity Secure Score에 포함된 항목만 표시 (예: Enable policy to block legacy authentication · Protect all users with a sign-in risk policy / user risk policy · Enable self-service password reset) · 일부 항목은 미리 보기(Preview) · [Not Scored] 표시 항목은 수행해도 점수 미반영
   - 해설: 점수에 반영되는 개선 조치만 추려 봅니다
4. [처리] 항목 상세 확인
   - 주체: 관리자
   - 위치: 권장 사항 선택 › 상태 설명 (Status description) · 설명 · 가치 (Value) · 조치 계획 (Action plan) · 사용자 영향 (User impact, 일부) · 영향받는 리소스 (Impacted resources)
   - 데이터: 영향받는 리소스 표(이름 · ID · 최초 감지일 · 상태)는 포털에서 최대 50개 — 전체는 GET /beta/directory/recommendations/{recommendationId}/impactedResources · 리소스가 없는 항목은 유형이 Tenant level이라 표가 비어 있음
   - 해설: 무엇이 왜 문제이고 어떻게 고치는지 한 화면에서 봅니다
5. [처리] 우선순위 판단
   - 주체: 관리자
   - 위치: 권장 사항 상세 › 우선순위 (Priority: High · Medium · Low)
   - 데이터: 높음 = 필수(조치하지 않으면 심각한 보안 영향이나 가동 중단 가능) · 중간 = 권장(조치하지 않아도 심각한 위험 없음) · 낮음 = 선택(보안·상태 위험 없음)
   - 해설: 보안 영향 · 상태 우려 · 중단 가능성 같은 요소로 Microsoft가 값을 정하므로 관리자는 이를 보고 순서를 정합니다
6. [처리] 처리 방침 표시 — 연기 또는 해제
   - 주체: 관리자
   - 위치: 권장 사항 상세 상단 다음으로 표시 (Mark as) › 연기 (Postponed) / 해제 (Dismissed) / 활성 (Active) · 개별 영향 리소스는 표의 체크박스를 선택한 뒤 상태 메뉴에서 표시
   - 데이터: 연기는 1년 이내 날짜를 고르며 그 날짜가 되면 Active로 돌아옴 · 해제는 열리는 패널에서 해제 사유 선택 필수 · 해제 · 연기 · 완료 상태는 Active로 수동 복귀 가능 · 리소스 단위 규칙도 동일
   - 해설: 하지 않기로 한 항목은 사유와 함께 정리해 둡니다
7. [처리] 조치 계획에 따라 해당 기능 구성으로 이동
   - 주체: 관리자
   - 위치: 조치 계획의 링크 (예: Entra ID › 조건부 액세스 › 정책)
   - 데이터: 실제 설정은 각 기능 L2에서 수행 · 조치 계획에는 문서 링크나 다른 관리 포털 페이지 안내가 들어갈 수 있고, 일부 항목은 사용자에게 보이는 영향이 별도로 적혀 있음
   - 해설: 이 화면은 평가만 하므로 고치는 곳은 기능별 설정입니다
8. [끝] 상태 변경 저장
   - 주체: 관리자
   - 위치: 권장 사항 상세 › 상태 변경 확인 (상태 설명에 변경 날짜 표시)
   - 데이터: 권장 사항 status = postponed / dismissed / active · 문서상 감사 로그(Entra ID › Audit logs, 서비스 필터 Microsoft Entra recommendations)에 수집되는 변경은 완료 처리뿐
   - 해설: 선택한 처리 방침이 권장 사항 상태로 기록되지만, 연기·해제 같은 수동 변경은 감사 로그로 추적하기 어렵습니다

#### L4 · ② 활성 — 조치가 점수에 반영된다

1. [시작] 관리자가 권장 조치를 적용
   - 주체: 관리자
   - 위치: 예: Entra ID › 조건부 액세스 › 정책 › 레거시 인증 차단 정책 켜기 (정책 상태 사용 = 켜기)
   - 데이터: 해당 기능의 설정 객체 (예: conditionalAccessPolicy.state = enabled) · 조치에 필요한 역할은 기능마다 다름 (예: Conditional Access Administrator)
   - 해설: 설정을 바꿔도 점수는 바로 바뀌지 않고 다음 분석 뒤에 반영됩니다
2. [처리] 테넌트 구성이 바뀜
   - 주체: Entra ID
   - 위치: 해당 기능의 서비스
   - 데이터: 변경된 정책 · 설정 값 · 이 변경 자체는 권장 사항 서비스가 즉시 알지 못하고 다음 분석에서 읽어 감
   - 해설: 평가 대상 구성이 바뀌었습니다
3. [처리] 매일 구성 분석이 다시 실행됨
   - 주체: Entra ID
   - 위치: 권장 사항 서비스 (서비스 내부)
   - 데이터: 24시간 주기 분석 · 직전 24시간 활동을 반영하며 하루 지연이 있고, 드물게 최대 72시간까지 늘어남 · 테넌트 구성을 모범 사례와 비교해 해당되는 항목만 권장 사항으로 표시
   - 해설: 변경이 바로 점수에 보이지 않고 다음 분석 뒤에 반영됩니다. 교육 중 시연하면 점수 변화는 보이지 않을 수 있습니다
4. [판단] 조치가 완전히 충족되었는가?
   - 주체: Entra ID
   - 데이터: 권장 구성 대비 충족도 (충족 · 일부 충족 · 미충족) · 항목은 이진 방식(설정하면 100%)이거나 전체 대비 비율 방식으로 채점
   - 해설: 일부만 충족하면 최대 점수의 일부만 받습니다
   - 예 → 5
   - 아니오 → 6
5. [처리] 완료 처리 — 영향 리소스가 모두 해결됨
   - 주체: Entra ID
   - 위치: 개요 › 권장 사항 목록의 상태 (Completed) · 감사 로그는 Entra ID › Audit logs에서 서비스 Microsoft Entra recommendations로 필터
   - 데이터: status = completed (수동 완료 불가) · 감사 로그에 수집되는 권장 사항 변경은 완료 처리뿐
   - 해설: 모든 영향 리소스가 해결되면 시스템이 자동으로 완료 표시하고, 다음 실행에서 활성 리소스가 다시 발견되면 Active로 돌아갑니다
   - 다음 → 7
6. [처리] 일부 점수만 부여 — 남은 리소스는 Active
   - 주체: Entra ID
   - 위치: 개요 › 권장 사항 › 영향받는 리소스 표 (남은 리소스 확인)
   - 데이터: 부분 충족 → 최대 점수의 일부 (예: 최대 10.71%인 MFA 항목에서 사용자 100명 중 5명만 보호하면 5/100 × 10.71% ≈ 0.53%) · status = active (남은 영향 리소스 존재)
   - 해설: 부분 충족한 항목은 계속 남아 이어서 고치게 합니다
7. [처리] Identity Secure Score(%) 재계산
   - 주체: Entra ID
   - 위치: 개요 › 권장 사항 상단 점수
   - 데이터: 항목별 secure score points 합산 · 항목 안의 부분 점수 계산은 문서에 예시가 있으나 전체 % 합산·정규화 방식 [확인 필요: 문서에 공식 산식 없음] · 이 점수는 Microsoft 보안 점수(Microsoft Secure Score)의 ID 범주와 같은 권장 사항을 씀
   - 해설: 완료·부분 충족 결과가 점수 하나로 합쳐집니다
8. [끝] 추세로 개선 확인
   - 주체: 로그
   - 위치: Identity Secure Score › 점수 변화 추이 · 전체 Microsoft 보안 점수의 변경 상세는 Microsoft Defender 포털(security.microsoft.com)의 기록 (History) 탭
   - 데이터: 시간에 따른 점수 이력 · 점수는 침해 가능성의 절대 척도가 아니라 위험을 줄이는 기능을 얼마나 도입했는지의 지표
   - 해설: 시간에 따른 변화로 개선 효과를 확인합니다. 점수 자체보다 우선순위 높은 권장 사항을 처리했는지가 더 중요합니다
- 시나리오: 예 :: 완전히 충족해 완료 처리 후 개선 추세 확인
- 시나리오: 아니오 :: 일부만 충족해 일부 점수만 부여 후 추세 확인

> 교육 포인트: Identity Secure Score는 "무엇이 부족한지 알려 주는 평가 도구"이며 스스로 설정을 바꾸지 않습니다. 실제 강제는 각 기능(MFA, 조건부 액세스, 암호 보호 등)에서 이뤄집니다.
>
> 주의: 권장 사항·점수 항목 이름과 점수 계산 방식은 변경될 수 있어 교육 전에 포털 화면과 대조합니다 [확인 필요].

### L3 · A · 점수 산정 — 평가 · 충족도 · 처리 상태

#### L4 · 구성 스냅샷이 점수 포인트로 바뀌는 과정

1. [시작] 24시간마다 테넌트 보안 구성을 평가
   - 주체: Entra ID
   - 위치: 권장 사항 서비스 (서비스 내부)
   - 데이터: 현재 정책 · 설정 · 디렉터리 구성 스냅샷 · 24시간마다 실행되어 직전 24시간 활동을 반영
   - 해설: 하루에 한 번 현재 구성을 모범 사례와 비교해 테넌트별로 맞춤 개선 조치를 만듭니다
2. [처리] 점수 대상 개선 조치 목록과 대조
   - 주체: Entra ID
   - 위치: 권장 사항 › 보안 필터
   - 데이터: 점수 문서는 23개 개선 조치를 나열 (예: Require MFA for administrative roles · Ensure all users can complete MFA · Enable policy to block legacy authentication · Enable self-service password reset · Protect all users with a sign-in/user risk policy · Designate more than one Global Administrator · Do not expire passwords) · 권장 사항 개요 표에서는 Identity Secure Score = Yes인 항목이 36개로 보여 문서 간 차이가 있음 [확인 필요: 현재 대상 개수는 포털에서 보안 필터로 확인]
   - 해설: 점수에 포함되는 개선 조치만 평가하며, [Not Scored] 항목은 수행해도 지금은 점수로 인정되지 않습니다
3. [처리] 항목마다 충족도 판정
   - 주체: Entra ID
   - 위치: 권장 사항 상세 › 점수 포인트
   - 데이터: 충족 · 일부 충족 · 미충족 — 이진 항목은 설정하면 100%, 비율 항목은 보호된 비율 × 최대 점수 (예: 최대 10.71% 항목에서 100명 중 5명 보호 시 약 0.53%)
   - 해설: 완전히 하지 않아도 한 만큼은 점수로 인정됩니다
4. [판단] 타사 제품이나 다른 방법으로 이미 충족했는가?
   - 주체: 관리자
   - 위치: 개선 조치 설정 패널 (타사 해결 · 대체 완화로 해결)
   - 데이터: 관리자가 지정하는 상태 Resolved through third party / Resolved through alternate mitigation (Microsoft는 실제 구현을 확인하지 못함) · 상태 변경은 최소 SharePoint Administrator 역할
   - 해설: 다른 도구로 막고 있는 항목은 직접 표시해 점수에 반영합니다
   - 예 → 5
   - 아니오 → 6
5. [처리] 타사·대체 완화로 해결 — 점수 부여
   - 주체: 관리자
   - 위치: 개선 조치 설정 패널 › 상태 변경
   - 데이터: 항목 포인트 전체 인정 · 타사 또는 내부 도구가 더는 통제를 덮지 못하면 다른 상태(To address · Planned 등)로 바꿔야 함
   - 해설: 점수가 실제 보안 수준을 더 잘 반영하지만 구현 완전성은 Microsoft가 보지 못하므로 책임은 관리자에게 있습니다
   - 다음 → 9
6. [판단] 위험을 수용하거나 항목을 무시했는가?
   - 주체: 관리자
   - 위치: 개선 조치 상세 › 위험 수락 (Risk accepted) / 무시 (Ignore)
   - 데이터: 위험 수락 = 포인트 없음 · 목록에서 숨김 · 이력(History)에서 확인하고 언제든 되돌리기 가능 / 무시 = 점수 계산에서 제외
   - 해설: 환경에 맞지 않는 항목을 사유와 함께 정리합니다. 보안과 사용성의 균형 때문에 모든 권장 사항이 모두에게 맞지는 않습니다
   - 예 → 7
   - 아니오 → 8
7. [처리] 위험 수락 · 무시 — 점수 계산에서 제외 또는 포인트 없음
   - 주체: 관리자
   - 위치: 개선 조치 상세 › 상태 · 이력 (History)
   - 데이터: 상태 기록 · 위험 수락은 목록에서 숨겨지지만 이력에서 되돌리기 가능
   - 해설: 의도적으로 하지 않은 항목은 점수를 부풀리지 않고 따로 관리합니다
   - 다음 → 9
8. [처리] 충족도에 따라 포인트를 합산
   - 주체: Entra ID
   - 위치: 권장 사항 목록의 secure score points 열
   - 데이터: 항목별 secure score points 합계 · 상태 To address는 조치가 필요하거나 부분 충족으로 감지된 항목, Planned는 완료 계획이 구체적으로 있는 항목
   - 해설: 충족한 만큼 포인트가 쌓입니다
9. [끝] 점수(%) 표시 — 계산식은 문서 확인
   - 주체: 로그
   - 위치: Entra ID › Identity Secure Score 또는 개요 › 권장 사항 상단
   - 데이터: 점수(%) · 항목 단위 부분 점수 예시는 문서에 있으나 전체 % 산식은 문서에 없음 [확인 필요: 전체 합산 방식]
   - 해설: 퍼센트로 보여 주지만 침해 확률이 아니라 위험을 줄이는 기능을 얼마나 도입했는지의 지표입니다. 특정 점수보다 우선순위가 높은 권장 사항 처리에 집중합니다
- 시나리오: 예 :: 타사·대체 완화로 이미 충족해 점수 표시
- 시나리오: 아니오 ▸ 예 :: 위험 수락·무시 처리 후 점수 표시
- 시나리오: 아니오 ▸ 아니오 :: 충족도대로 포인트를 합산해 점수 표시

> 교육 포인트: 점수는 "남들과 비교한 순위"가 아니라 "Microsoft 권장 구성과 얼마나 일치하는가"입니다. 높이는 것이 목적이 아니라 빠진 보호를 채우는 것이 목적입니다.
>
> 주의: 문서 한쪽은 개선 조치 상태를 "해결 예정(To address) · 계획됨(Planned) · 위험 수락(Risk accepted) · 타사로 해결(Resolved through third party) · 대체 완화로 해결(Resolved through alternate mitigation)"로, 권장 사항은 "활성 · 연기 · 해제 · 완료"로 설명합니다. 포털에서 어느 용어가 어디에 쓰이는지 교육 전에 확인합니다 [확인 필요].

### L3 · B · 권장 사항 수명 주기 — 활성 · 연기 · 해제 · 완료

#### L4 · 권장 사항 한 건이 상태를 바꾸는 흐름

1. [시작] 분석 결과 적용 대상이면 권장 사항이 생성됨
   - 주체: Entra ID
   - 위치: 개요 › 권장 사항
   - 데이터: status = active · 우선순위 · 영향받는 리소스 · 상태 설명 (변경 날짜) · 리소스가 없으면 영향받는 리소스 유형이 Tenant level이고 조치 계획이 테넌트 전체에 적용됨
   - 해설: 테넌트에 해당되는 권장 사항만 목록에 나타나므로 다른 테넌트와 목록이 다를 수 있습니다
2. [처리] 담당 역할에 이메일 알림 (미리 보기)
   - 주체: Entra ID
   - 위치: 권장 사항별 지정 역할 (예: Application Administrator)
   - 데이터: 예: Designate more than one Global Administrator → Global Administrator · Enable policy to block legacy authentication → Conditional Access Administrator · Security Administrator · Enable self-service password reset → Authentication Policy Administrator · Remove unused applications → Application Administrator · 대상 역할이 N/A인 항목은 메일 없음 · PIM 사용 시 해당 역할로 활성화돼 있어야 수신하고 활성 할당자가 없으면 발송 안 됨
   - 해설: 새 권장 사항이 생기면 담당 역할에게 알려 줍니다. 미리 보기 기능이므로 목록을 정기적으로 직접 확인하는 습관이 필요합니다
3. [판단] 관리자가 어떻게 처리하는가?
   - 주체: 관리자
   - 위치: 권장 사항 상세 › 조치 계획 · 다음으로 표시 (Mark as)
   - 데이터: 조치는 Action plan 수행, 연기는 Postponed, 해제는 Dismissed · 변경은 최소 Authentication Policy Administrator 역할(Security Administrator · Exchange Administrator 등 가능)
   - 해설: 바로 조치하거나, 미루거나, 해당 없음으로 정리합니다
   - 조치 → 4
   - 연기 → 5
   - 해제 → 6
4. [처리] 조치 계획 실행 — 영향 리소스를 해결
   - 주체: 관리자
   - 위치: 권장 사항 › 조치 계획 · 영향받는 리소스 표
   - 데이터: 리소스별 상태 갱신 (활성 → 완료) · 표에는 리소스 이름 · ID · 최초 감지일 · 상태가 있고 일부는 More details 링크로 리소스를 바로 열 수 있음 · 개별 리소스도 연기·해제 가능
   - 해설: 리소스를 하나씩 고쳐 나갑니다
   - 다음 → 7
5. [처리] 연기 — 날짜를 정해 미룸
   - 주체: 관리자
   - 위치: 다음으로 표시 › 연기 (Postponed) · 1년 이내 날짜 선택 (리소스 단위는 표에서 항목 선택 후 상태 메뉴)
   - 데이터: 지정한 날짜가 되면 자동으로 Active 복귀 · 날짜 이전에도 수동으로 Active로 되돌릴 수 있음
   - 해설: 지금은 못 하지만 잊지 않도록 날짜를 정해 둡니다
   - 다음 → 8
6. [처리] 해제 — 사유를 남기고 정리
   - 주체: 관리자
   - 위치: 다음으로 표시 › 해제 (Dismissed) › 해제 사유 선택 패널
   - 데이터: 해제 사유 필수(서비스 개선용으로 수집) · 수동으로 Active 복귀 가능
   - 해설: 해당 없음이나 잘못된 데이터인 경우 사유와 함께 닫습니다
   - 다음 → 8
7. [처리] 시스템이 완료 처리
   - 주체: Entra ID
   - 위치: 개요 › 권장 사항 목록의 상태 (Completed) · 감사 로그는 Entra ID › Audit logs에서 서비스 Microsoft Entra recommendations로 필터
   - 데이터: 모든 영향 리소스 해결 시 status = completed (수동 완료 불가) · 감사 로그에 수집되는 권장 사항 변경은 완료 처리뿐
   - 해설: 다음 분석에서 활성 리소스가 다시 발견되면 Active로 되돌아갑니다
8. [끝] 상태 기록 · 조회
   - 주체: 로그
   - 위치: GET https://graph.microsoft.com/beta/directory/recommendations (특정 항목은 ?$filter=recommendationType eq 'applicationCredentialExpiry' 형태) · GET /directory/recommendations/{id}/impactedResources
   - 데이터: DirectoryRecommendations.Read.All (읽기) · ReadWrite.All (변경) · Graph Explorer에서 API 버전을 beta로 선택해 실행
   - 해설: Graph로 전체 권장 사항과 영향 리소스를 조회합니다. 포털은 영향 리소스를 50개까지만 보여 주므로 전체 목록이 필요하면 Graph를 씁니다
- 시나리오: 조치 :: 조치 계획을 실행해 완료 처리하고 기록
- 시나리오: 연기 :: 권장 사항을 연기하고 상태 기록
- 시나리오: 해제 :: 권장 사항을 해제하고 상태 기록

> 교육 포인트: "완료"는 사람이 누르는 상태가 아니라 시스템이 영향 리소스가 모두 해결된 것을 확인한 결과입니다. 연기와 해제는 사람이 정하는 상태이므로 사유와 날짜를 남기는 습관이 중요합니다.
>
> 주의: 권장 사항 Graph API는 /beta 엔드포인트입니다. 변경 가능성이 있으므로 운영 자동화에 쓰기 전에 확인합니다 [확인 필요].
