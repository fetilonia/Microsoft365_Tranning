### L3 · D · 토큰 보호 — 훔친 토큰을 다른 기기에서 못 쓰게 하기

#### L4 · 세션 컨트롤 매칭 → 기기 바인딩 확인 → 바인딩된 토큰만 허용

1. [시작] 앱이 보호 리소스의 토큰을 요청
   - 주체: 앱
   - 위치: Windows 네이티브 앱 (Outlook · Teams · OneDrive · Word · Excel · PowerPoint · OneNote · Edge 프로필 로그인 · Visual Studio Code 등) → Exchange Online · SharePoint Online · Teams (Windows에서는 Azure Virtual Desktop · Windows 365도 가능)
   - 데이터: 로그인 세션 토큰(PRT 기반) 포함 요청. 브라우저 기반 앱은 미리 보기로 Azure Resource Manager에 접근하는 일부 웹 앱에 한정되며 이 Windows 네이티브 흐름과 별도 가이드를 따름
   - 해설: 보호 대상 리소스로 가는 네이티브 앱의 토큰 요청입니다. Office 영구 라이선스 클라이언트는 2024 이상 버전만 지원하고, Surface Hub와 Windows 기반 Teams Rooms 기기는 지원되지 않습니다
2. [처리] "토큰 보호" 세션 컨트롤 매칭
   - 주체: Entra ID
   - 위치: Entra ID › Conditional Access › Policies › 정책 › Access controls › Session › Require token protection for sign-in sessions (Entra ID P1 필요, 생성은 Conditional Access Administrator 이상)
   - 데이터: sessionControls.secureSignInSession.isEnabled (Graph 베타). 정책 조건: Device platforms = Windows, Client apps = Mobile apps and desktop clients만, Target resources = Office 365 Exchange Online · Office 365 SharePoint Online · Microsoft Teams Services (Windows App 사용 시 Azure Virtual Desktop · Windows 365 · Windows Cloud Login 추가)
   - 해설: Windows 플랫폼과 지원 리소스를 대상으로 한 정책이 걸립니다. Client apps를 설정하지 않거나 Browser를 남기면 Teams Web처럼 MSAL.js를 쓰는 앱이 차단될 수 있고, Office 365 앱 그룹 전체를 고르면 의도치 않은 실패가 생깁니다
3. [처리] 기기 바인딩 상태 확인 — PRT와 플랫폼 브로커
   - 주체: 디바이스
   - 위치: Windows Web Account Manager(WAM) 경유
   - 위치: Windows Web Account Manager(WAM) 경유
   - 데이터: Entra에 등록된 기기에 암호로 묶인 기본 새로 고침 토큰(PRT). 지원 기기: Windows 10 이상의 Entra 조인 · 하이브리드 조인 · 등록 기기, Windows Server 2019 이상 하이브리드 조인 기기
   - 해설: 기기 등록 때 발급된 PRT가 그 기기에 묶여 있어야 바인딩을 증명할 수 있습니다. Entra 조인 AVD 세션 호스트 · 일괄 등록(bulk enrollment) 기기 · Autopilot 셀프 배포 · Entra 조인 Windows 365 Cloud PC는 지원되지 않아 코드 1003으로 차단되므로 기기 필터로 제외합니다
4. [판단] 로그인 세션 토큰이 기기에 바인딩되어 있는가?
   - 주체: Entra ID
   - 위치: Entra ID 내부 평가 (결과는 Sign-in logs › Basic info › Token Protection - Sign In Session)
   - 데이터: tokenProtectionStatusDetails.signInSessionStatus (bound / unbound, 베타 enum에는 none도 있음) · signInSessionStatusCode 1002 기기 상태 없음 · 1003 기기 상태가 요건 불충족(미지원 등록 유형 등) · 1005 기타 · 1006 미지원 OS 버전 · 1008 플랫폼 브로커(WAM) 미연동
   - 해설: 요청의 모든 단계가 바인딩된 프로토콜을 써야 정책을 충족합니다. 한 로그인이 여러 요청으로 이뤄지므로 한 요청이 bound여도 다른 요청이 unbound이면 충족하지 못하며 correlation ID로 모든 요청을 확인합니다
   - 예 → 5
   - 아니오 → [차단] 차단 — unbound (코드 1002 기기 상태 없음 · 1008 브로커 미연동 등)
5. [처리] 토큰 발급 — 기기에 묶인 로그인 세션
   - 주체: Entra ID
   - 위치: Entra ID 토큰 발급 (/token 응답)
   - 데이터: 액세스 토큰 · 세션 바인딩 정보. 바인딩이 확인된 PRT 기반 요청에만 보호 리소스 토큰이 발급됨
   - 해설: 바인딩된 요청에만 토큰을 발급합니다. 호환되는 클라이언트와 등록된 기기라면 사용자에게는 보이지 않는 동작입니다
6. [처리] 바인딩 결과를 로그에 기록
   - 주체: 로그
   - 위치: Entra ID › Monitoring & health › Sign-in logs › Basic info › Token Protection - Sign In Session (Conditional Access 또는 Report-only 탭 › 정책 › Session Controls로 충족 여부 확인)
   - 데이터: enforcedSessionControls = SignInTokenProtection · sessionControlsNotSatisfied. 2023년 6월 말 이전 기록은 값이 Binding이었으므로 쿼리는 두 값을 모두 포함. Log Analytics는 SigninLogs와 AADNonInteractiveUserSignInLogs를 함께 조회
   - 해설: Bound · Unbound 값과 상태 코드로 정책 충족 여부와 이유를 확인합니다
7. [끝] 도난 토큰은 다른 기기에서 거부
   - 주체: 외부
   - 위치: 공격자 기기 (토큰을 탈취한 뒤 다른 기기에서 재사용)
   - 데이터: 공격자 기기의 재생 요청 → 바인딩 증명 없음 → unbound
   - 해설: 토큰을 훔쳐 다른 기기에서 재생해도 Entra가 바인딩된 토큰만 받아들입니다. 토큰 보호는 심층 방어의 일부이며 다른 플랫폼으로 위장한 우회를 막으려면 알 수 없는 플랫폼 차단 정책과 알려진 모든 플랫폼에 준수 기기를 요구하는 정책을 함께 둡니다
- 시나리오: 예 :: 기기에 바인딩된 토큰만 발급, 도난 토큰 거부
- 시나리오: 아니오 :: 바인딩되지 않은 토큰이라 요청 차단

> 교육 포인트: 토큰 보호를 먼저 보고 전용으로 켜고, 대화형과 비대화형 로그인 로그를 모두 확인해 호환되는 기기와 앱을 확인한 뒤 강제합니다.
>
> 주의: 지원 플랫폼 표에서 네이티브 앱은 Windows · iOS · iPadOS · macOS가 GA로 적혀 있지만 Apple 기기 요건 절은 Apple을 미리 보기로 표기합니다 [확인 필요: Apple 플랫폼 GA 여부]. 대상 리소스는 Exchange Online · SharePoint Online · Teams(Windows는 Azure Virtual Desktop · Windows 365 포함)로 제한되고, 정책 대상 리소스를 Office 365 앱 그룹 전체로 잡으면 의도치 않은 실패가 생길 수 있습니다.
