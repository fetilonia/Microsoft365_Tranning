#### 그룹 · loc · 위치(네트워크)
- 섹션: 조건
- 선택: 다중
- 위치: 보호 › 조건부 액세스 › 정책 › 새 정책 › 조건 › 네트워크(Network; 이전 '위치(Locations)') — 명명된 위치는 보호 › 조건부 액세스 › 명명된 위치(Named locations) [확인 필요: 한글 UI 명칭]
- 소개: 로그인 트래픽의 출발 네트워크(IP·국가·규격 네트워크)를 정책 적용 조건으로 삼습니다.
- 평가: 명명된 위치는 Entra ID가 공인 IP(또는 Authenticator GPS)로 판정합니다. 규격 네트워크는 Global Secure Access(GSA)를 거친 트래픽만 해당되며, GSA 신호를 켜야 Entra ID가 이 위치를 인식합니다.
- 노드 제목: 위치 조건 일치?
- 노드 보조: 공인 IP·국가·GSA 규격 네트워크 신호와 대조
- 해설: Entra ID가 로그인의 공인 IP·국가를 정책 위치와, GSA 경유 신호를 규격 네트워크와 대조합니다.
- 주체: Entra ID(명명된 위치 판정) · Global Secure Access(규격 네트워크 신호 제공)
- 데이터: 클라이언트 공인 IP(프록시·VPN이면 그 IP), 국가 매핑, Authenticator GPS, GSA 신호(클라이언트·원격 네트워크)
- 출처: https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-assignment-network;https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-compliant-network;https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-source-ip-restoration;https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-continuous-access-evaluation-strict-enforcement;https://learn.microsoft.com/en-us/entra/global-secure-access/reference-current-known-limitations

##### 옵션 · l-any · 포함: 모든 위치
- 소개: 인터넷의 모든 IP를 대상으로 합니다(기본값).
- 위치: 정책 › 조건 › 네트워크 › 구성 예 › 포함 › 모든 네트워크 또는 위치(Any network or location)
- 동작: 명명된 위치로 등록한 IP만이 아니라 인터넷의 모든 주소에 정책을 적용합니다. 제외 목록으로 예외 위치를 뺄 수 있습니다.
- 매칭: 어떤 위치에서 온 로그인이든 일치입니다. 국가에 매핑되지 않는 IP(알 수 없는 영역)도 포함됩니다.
- 미충족 시: 제외 위치에 해당하면 이 조건은 불일치가 되어 정책이 적용되지 않습니다.
- 지원 주체: 사용자, 워크로드 ID(이 조건의 위치 정책으로 문서화)
- 제약·주의: 위치 조건을 구성하지 않아도 정책은 모든 위치에 적용됩니다. '모든 위치 포함 + 신뢰·규격 위치 제외'가 '네트워크 밖' 패턴입니다.
- 로그: 로그인 로그의 조건부 액세스 탭에서 정책 결과(적용/미적용)와 평가된 IP를 확인합니다.

##### 옵션 · l-selected · 포함: 선택한 위치(명명된 위치: 국가·IP 범위)
- 소개: 선택한 명명된 위치(IP 범위·국가/지역)에서 온 로그인만 대상입니다.
- 위치: 정책 › 조건 › 네트워크 › 포함 › 선택한 네트워크 및 위치(Selected) — 위치 정의는 명명된 위치에서
- 동작: 일반 네트워크 신호입니다. IP 범위 위치는 공인 IP가 범위에 속하는지, 국가 위치는 IP→국가 매핑 또는 Authenticator GPS로 국가를 판정합니다.
- 매칭: 공인 IP가 선택한 IP 범위(IPv4·IPv6 CIDR)에 속함, 또는 IP/GPS로 판정한 국가가 선택 국가임. '알 수 없는 국가 포함'을 켜면 매핑 불가 IP도 일치.
- 미충족 시: 선택한 위치 밖이면 이 조건은 불일치이며 정책이 적용되지 않습니다.
- 지원 주체: 사용자, 워크로드 ID(서비스 주체)
- 제약·주의: GPS는 Authenticator 필요·1시간 주기 프롬프트. 195개·위치당 2000범위·/8 초과 마스크만. 프록시·VPN은 프록시 IP로 판정(XFF 미사용), 소스 IP 복원(GSA)이 해법. IPv6 미등록 시 차단 위험.
- 로그: 조건부 액세스 탭의 정책 세부 정보에 평가 결과가 남고, strict 적용 시 'IP address (seen by resource)' 열로 불일치를 봅니다.

##### 옵션 · l-compliant · 포함: 모든 규격(준수) 네트워크 위치(Global Secure Access)
- 소개: GSA를 거친 트래픽만 '규격 네트워크'로 보는 위치입니다.
- 위치: 정책 › 조건 › 네트워크 › 포함 › 모든 규격 네트워크 위치(All Compliant Network locations) — 먼저 GSA › 설정 › 세션 관리 › 적응형 액세스에서 신호 활성화
- 동작: IP 목록이 아니라 GSA가 보내는 신호로 판정합니다. 테넌트의 GSA 클라이언트 또는 구성된 원격 네트워크를 거친 트래픽만 규격으로 보며, 다른 테넌트의 GSA는 통과하지 못합니다.
- 매칭: 신호 활성화 후, 로그인이 이 테넌트의 Global Secure Access(클라이언트 터널·원격 네트워크)를 경유했을 때 일치입니다. GSA를 끄거나 우회하면 불일치.
- 미충족 시: 규격 네트워크가 아니면 이 조건은 불일치이며, 이 옵션을 포함으로 쓴 정책은 적용되지 않습니다.
- 지원 주체: 사용자, 에이전트(GSA 클라이언트가 있는 엔드포인트의 에이전트 사용자 계정). 워크로드 ID는 [확인 필요]
- 제약·주의: GSA 신호를 끄면 이 위치 기반 정책 사용자가 잠길 수 있음. 사용 중 Private Access 앱은 미지원. GSA 자체 리소스는 자동 제외. 위 규격 네트워크는 IP 범위 목록이 아니라 GSA 경유 신호임.
- 로그: 명명된 위치 목록에 'All Compliant Network locations'(유형 Network Access)가 보이고, GSA 리소스 로그인은 'Internet resources with Global Secure Access' 등으로 남습니다.

##### 옵션 · l-ex-trusted · 제외: 모든 신뢰 위치
- 소개: 신뢰로 표시한 IP 위치(와 MFA 신뢰 IP)를 정책에서 뺍니다.
- 위치: 정책 › 조건 › 네트워크 › 제외 › 모든 신뢰할 수 있는 네트워크 및 위치(All trusted networks and locations)
- 동작: '신뢰할 수 있는 위치로 표시'한 명명된 위치와 MFA 신뢰 IP(구성 시)를 제외 대상으로 봅니다. 사내망 밖 사용자에게만 정책이 걸리도록 하는 대표 패턴입니다.
- 매칭: 공인 IP가 신뢰 표시된 IP 범위 위치 또는 MFA 신뢰 IP(IPv4만)에 속하면 제외 일치(= 정책 미적용). 그 외는 정책 적용.
- 미충족 시: 신뢰 위치가 아니면 제외되지 않아 '모든 위치 포함' 등으로 잡힌 로그인에 정책이 적용됩니다.
- 지원 주체: 사용자, 워크로드 ID(위치 제외로 문서화)
- 제약·주의: 신뢰 표시는 위치 정의에 있습니다. 신뢰 위치 로그인은 ID Protection 위험 산정 정확도도 높입니다. MFA 신뢰 IP 사용은 권장되지 않습니다.
- 로그: 신뢰 위치로 제외되면 해당 정책이 '적용 안 됨'으로 표시됩니다.

##### 옵션 · l-ex-compliant · 제외: 규격 네트워크 위치
- 소개: GSA 규격 네트워크에서 온 로그인만 정책에서 뺍니다.
- 위치: 정책 › 조건 › 네트워크 › 제외 › 모든 규격 네트워크 위치(All Compliant Network locations)
- 동작: 모든 위치를 포함하고 규격 네트워크를 제외하면 'GSA를 거치지 않은 접근 차단' 정책이 됩니다. 인증 시점에 Entra ID가 강제하고, CAE 지원 서비스는 탈취 토큰 재사용도 즉시 거부합니다.
- 매칭: 로그인이 이 테넌트의 GSA(클라이언트·원격 네트워크)를 경유하면 제외 일치(= 정책 미적용). 경유하지 않으면 정책 적용(예: 차단).
- 미충족 시: GSA 우회·클라이언트 중지 시 제외되지 않아 정책이 적용됩니다. 이미 로그인된 세션은 다음 로그인 때 재평가됩니다.
- 지원 주체: 사용자
- 제약·주의: GSA 신호를 끄면 사용자가 잠길 수 있습니다. Intune 등록 앱은 순환 의존 때문에 제외 필요, 비상 계정 제외 권장, EFP는 GSA-ExplicitForwardProxy 제외 필요. Defender 모바일 앱도 제외 필요.
- 로그: GSA 클라이언트를 끄고 접근하면 '지금은 액세스할 수 없습니다' 차단 화면과 해당 정책 적용 결과가 로그에 남습니다.
