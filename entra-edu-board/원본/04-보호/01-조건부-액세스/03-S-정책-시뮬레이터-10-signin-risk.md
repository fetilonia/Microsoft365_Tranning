#### 그룹 · signin-risk · 로그인 위험
- 섹션: 조건
- 선택: 다중
- 위치: 보호 › 조건부 액세스 › 정책 › 새 정책 › 조건 › 로그인 위험(Sign-in risk) [확인 필요: 한글 UI 명칭]
- 소개: 이번 인증 요청이 계정 소유자 본인이 아닐 가능성 수준으로 정책 적용을 정합니다.
- 평가: Entra ID가 로그인 중 ID Protection이 산정한 로그인 위험 수준(낮음·중간·높음)을 읽어 선택한 수준과 대조합니다. 실시간 탐지는 로그인 중 MFA로 해결할 수 있습니다.
- 노드 제목: 로그인 위험 조건 일치?
- 노드 보조: 이번 요청의 ID Protection 위험 수준
- 해설: Entra ID가 이번 인증 요청의 로그인 위험 수준을 읽어 선택한 위험 수준과 같은지 봅니다.
- 주체: Entra ID(ID Protection 신호)
- 데이터: 이번 로그인의 ID Protection 위험 수준(실시간·오프라인 탐지 종합)
- 출처: https://learn.microsoft.com/en-us/entra/id-protection/howto-identity-protection-configure-risk-policies;https://learn.microsoft.com/en-us/entra/id-protection/concept-risk-detection-types;https://learn.microsoft.com/en-us/entra/id-protection/concept-identity-protection-risks

##### 옵션 · sr-high · 로그인 위험: 높음
- 소개: 본인이 아닐 확신이 높은 로그인에 정책을 적용합니다.
- 위치: 정책 › 조건 › 로그인 위험 › 구성 예 › 높음(High)
- 동작: 로그인 위험이 높음이면 일치입니다. 권장 구성은 중간·높음에서 인증 강도(다단계 인증)와 로그인 빈도 '매번'을 요구해 사용자가 직접 위험을 해결하게 하는 것입니다.
- 매칭: ID Protection 로그인 위험 수준이 높음일 때 일치입니다(예: 검증된 위협 행위자 IP는 높음).
- 미충족 시: 위험이 없거나 낮음·중간이면 이 옵션은 불일치입니다.
- 지원 주체: 사용자. 워크로드 ID는 별도 '서비스 주체 위험', 에이전트는 별도 '에이전트 위험(미리 보기)' 조건
- 제약·주의: 로그인 위험 정책은 MFA(인증 강도)로 해결하고, 암호 변경은 사용자 위험 몫입니다. 로그인·사용자 위험을 한 정책에 합치지 않습니다. 패스워드리스 사용자는 패스워드리스/피싱 방지 강도.
- 로그: 로그인 로그 조건부 액세스 탭에 정책 결과가 남고 MFA 성공 시 로그인 위험이 해결됩니다.

##### 옵션 · sr-medium · 로그인 위험: 중간
- 소개: 중간 수준 위험 로그인에 정책을 적용합니다.
- 위치: 정책 › 조건 › 로그인 위험 › 구성 예 › 중간(Medium)
- 동작: 중간은 중간 심각도 이상 징후가 있으나 확신이 낮은 수준입니다. Microsoft는 중간·높음에 MFA 요구를 권장합니다.
- 매칭: ID Protection 로그인 위험 수준이 중간일 때 일치입니다.
- 미충족 시: 위험이 없거나 다른 수준이면 이 옵션은 불일치입니다.
- 지원 주체: 사용자. 워크로드 ID는 별도 '서비스 주체 위험', 에이전트는 별도 '에이전트 위험(미리 보기)' 조건
- 제약·주의: 일부 탐지는 로그인 후 오프라인으로 계산돼 수준이 바뀔 수 있습니다. 신뢰 위치 로그인은 위험 산정 정확도를 높입니다. 라이선스는 Entra ID P2(또는 Entra Suite).
- 로그: 실시간 탐지는 5~10분, 오프라인 탐지는 최대 48시간 뒤 보고서에 나타납니다.
