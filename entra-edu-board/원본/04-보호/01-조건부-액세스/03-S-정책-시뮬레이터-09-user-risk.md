#### 그룹 · user-risk · 사용자 위험
- 섹션: 조건
- 선택: 다중
- 위치: 보호 › 조건부 액세스 › 정책 › 새 정책 › 조건 › 사용자 위험(User risk) [확인 필요: 한글 UI 명칭]
- 소개: ID Protection이 산정한 '계정이 탈취됐을 가능성' 수준으로 정책 적용을 정합니다.
- 평가: Entra ID가 로그인 시점에 ID Protection이 계산해 둔 사용자 위험 수준(낮음·중간·높음)을 읽어 선택한 수준과 대조합니다. 일부 탐지는 실시간, 일부는 로그인 후 오프라인으로 산정됩니다.
- 노드 제목: 사용자 위험 조건 일치?
- 노드 보조: ID Protection 위험 수준과 대조
- 해설: Entra ID가 ID Protection의 현재 사용자 위험 수준을 읽어 선택한 위험 수준과 같은지 봅니다.
- 주체: Entra ID(ID Protection 신호)
- 데이터: ID Protection의 사용자 위험 수준(탐지 신뢰도에 기반한 낮음·중간·높음)
- 출처: https://learn.microsoft.com/en-us/entra/id-protection/howto-identity-protection-configure-risk-policies;https://learn.microsoft.com/en-us/entra/id-protection/concept-risk-detection-types;https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-grant

##### 옵션 · ur-high · 사용자 위험: 높음
- 소개: 계정 탈취 확신이 높은 사용자에게 정책을 적용합니다.
- 위치: 정책 › 조건 › 사용자 위험 › 구성 예 › 높음(High)
- 동작: 사용자 위험이 높음이면 일치입니다. Microsoft 권장은 높음에서 '위험 해결 필요'를 요구하는 것이며 인증 강도와 로그인 빈도(매번)가 자동 적용됩니다.
- 매칭: ID Protection 사용자 위험 수준이 높음일 때 일치입니다(유출된 자격 증명 탐지는 항상 높음으로 전달됩니다).
- 미충족 시: 위험이 없거나 낮음·중간이면 이 옵션은 불일치입니다(다른 수준을 같이 선택했다면 그 수준에서 일치).
- 지원 주체: 사용자. 워크로드 ID는 별도 '서비스 주체 위험', 에이전트는 별도 '에이전트 위험(미리 보기)' 조건
- 제약·주의: '암호 변경 필요'는 단독으로만 쓰고, 대상 앱이 모든 리소스여야 하며 다른 컨트롤과 못 섞습니다. 사용자 위험과 로그인 위험은 한 정책에 합치지 않습니다. MFA 사전 등록 필요(하이브리드는 암호 쓰기 저장).
- 로그: 로그인 로그 조건부 액세스 탭에 정책 결과가 남고 ID Protection 위험 보고서에서 위험 상태·해결 여부를 봅니다.

##### 옵션 · ur-medium · 사용자 위험: 중간
- 소개: 중간 수준 위험 사용자에게 정책을 적용합니다.
- 위치: 정책 › 조건 › 사용자 위험 › 구성 예 › 중간(Medium)
- 동작: 중간은 확신이 낮은 이상 징후입니다. 낮음·중간까지 선택하면 보호는 넓어지나 사용자 방해와 오탐이 늘어납니다.
- 매칭: ID Protection 사용자 위험 수준이 중간일 때 일치입니다.
- 미충족 시: 위험이 없거나 다른 수준이면 이 옵션은 불일치입니다.
- 지원 주체: 사용자. 워크로드 ID는 별도 '서비스 주체 위험', 에이전트는 별도 '에이전트 위험(미리 보기)' 조건
- 제약·주의: 중간·높음 위험은 해결되거나 닫힐 때까지 유지됩니다. 허용 컨트롤은 위험 해결 필요·암호 변경 필요(문서상 사용자 위험 한정). 라이선스는 Entra ID P2(또는 Entra Suite).
- 로그: 위험 수준은 실시간 탐지 5~10분, 오프라인 탐지 최대 48시간 뒤 보고서에 나타납니다.

##### 옵션 · ur-low · 사용자 위험: 낮음
- 소개: 낮은 수준 위험 사용자에게 정책을 적용합니다.
- 위치: 정책 › 조건 › 사용자 위험 › 구성 예 › 낮음(Low)
- 동작: 낮음은 이상 징후가 있으나 확신이 낮은 수준입니다. 포함하면 정책이 더 자주 걸려 사용자 방해가 늘어납니다.
- 매칭: ID Protection 사용자 위험 수준이 낮음일 때 일치입니다.
- 미충족 시: 위험이 없거나 다른 수준이면 이 옵션은 불일치입니다.
- 지원 주체: 사용자. 워크로드 ID는 별도 '서비스 주체 위험', 에이전트는 별도 '에이전트 위험(미리 보기)' 조건
- 제약·주의: 낮음 위험 사용자·탐지는 6개월 뒤 자동 소멸합니다. 사용자 위험 정책의 해결 흐름은 사용자가 MFA에 미리 등록돼 있어야 동작합니다.
- 로그: 위험 보고서의 위험 상태·세부 정보와 로그인 로그의 조건부 액세스 결과를 함께 확인합니다.
