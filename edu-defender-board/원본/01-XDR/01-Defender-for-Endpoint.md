## L2 · Defender for Endpoint — Windows 기기 온보딩과 ASR

- 설정(Control Plane): Intune EDR 정책으로 테스트 기기 온보딩 | 엔드포인트 보안에서 ASR 규칙을 감사 또는 차단으로 할당
- 강제(Enforcement): 온보딩된 기기의 센서가 EDR 신호를 제공 | Defender 바이러스 백신의 ASR 규칙이 설정된 모드로 동작
- 증적(Evidence): Intune 정책별 기기·설정 상태 | Defender 디바이스 인벤토리 · ASR 이벤트
- 메뉴(Admin Center): Microsoft Defender 포털 > 시스템 > 설정 > 엔드포인트 > 온보딩 | Intune 관리 센터 > 엔드포인트 보안
- 라이선스(License): Defender for Endpoint와 Intune의 해당 사용 권한 필요; Intune은 별도 제품 | ASR 보고·고급 기능의 플랜별 권한 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 미온보딩 → 정책 할당 → 기기 신호 확인

#### L4 · ⓪ 비활성 — 테스트 기기가 아직 온보딩되지 않았다

1. [시작] 관리자가 테스트 Windows 기기를 정한다
   - 주체: 관리자
   - 데이터: Intune 등록 기기와 테스트 그룹
   - 해설: 기기를 정했지만 아직 Defender for Endpoint에 연결하지 않았습니다.
2. [처리] 기기에 EDR 온보딩 정책을 할당하지 않는다
   - 주체: Intune
   - 데이터: 해당 그룹의 EDR 정책 할당 없음
   - 해설: 이 경로에서는 Intune이 온보딩 설정을 전달하지 않습니다.
3. [처리] 기기 인벤토리에서 해당 기기 상태를 확인한다
   - 주체: 관리자
   - 위치: Microsoft Defender 포털 › 디바이스 인벤토리
   - 데이터: 기기 이름과 온보딩 여부
   - 해설: 인벤토리 부재만으로 기기의 모든 보안 기능이 꺼졌다고 단정하지 않습니다.
4. [끝] 이 온보딩 경로의 EDR 증적이 없다
   - 주체: 관리자
   - 데이터: Sense 서비스 상태와 인벤토리 확인 결과
   - 해설: 다른 온보딩 경로나 기존 바이러스 백신 설정은 별도로 확인해야 합니다.

#### L4 · ① 구성 — Intune으로 테스트 그룹을 온보딩한다

1. [시작] Intune과 Defender 연결 및 권한을 확인한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 › 테넌트 관리 › 커넥터 및 토큰 › Microsoft Defender for Endpoint [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: Intune 구독 · Endpoint Security Manager 또는 동등 권한 · 연결 상태
   - 해설: Intune 등록 Windows 기기와 두 제품의 연결이 이 예제의 전제입니다.
2. [처리] 테스트 기기 그룹을 준비한다
   - 주체: 관리자
   - 위치: Microsoft Entra 관리 센터 › 그룹
   - 데이터: Windows 테스트 기기를 포함한 그룹
   - 해설: 전체 배포 전에 작은 대상 그룹으로 확인합니다.
3. [처리] EDR 정책을 만든다
   - 주체: 관리자
   - 위치: Intune 관리 센터 › 엔드포인트 보안 › 엔드포인트 검색 및 응답
   - 데이터: 플랫폼 Windows · 프로필 Endpoint detection and response
   - 해설: EDR 정책이 테스트 기기의 온보딩 구성을 전달합니다.
4. [처리] 정책을 테스트 그룹에 할당한다
   - 주체: 관리자
   - 위치: EDR 정책 › 할당
   - 데이터: 포함할 테스트 그룹
   - 해설: 기기가 다음에 Intune에 체크인할 때 정책을 받습니다.
5. [처리] ASR 정책을 별도로 만든다
   - 주체: 관리자
   - 위치: Intune 관리 센터 › 엔드포인트 보안 › 공격 표면 감소
   - 데이터: 테스트할 ASR 규칙과 감사 모드
   - 해설: ASR은 EDR 온보딩과 별개 정책으로 평가합니다.
6. [끝] 기기 및 설정별 적용 상태를 검토한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 › 해당 정책 › 기기 및 사용자 체크인 상태
   - 데이터: 적용 성공 · 충돌 · 오류
   - 해설: 성공 여부와 설정별 충돌을 확인한 다음 운영 범위를 넓힙니다.

#### L4 · ▶ ② 활성 — 온보딩 상태와 ASR 적용을 확인한다

1. [시작] 테스트 기기가 Intune에 체크인한다
   - 주체: Windows 기기
   - 데이터: 기기 ID · EDR 및 ASR 할당
   - 해설: 정책이 도착한 뒤 기기의 실제 상태를 살펴봅니다.
2. [판단] EDR 정책 적용이 성공했는가?
   - 주체: Intune
   - 데이터: 기기별 정책 적용 상태
   - 해설: 오류나 충돌이 있으면 즉시 온보딩 성공으로 보지 않습니다.
   - 성공 → 3
   - 실패 또는 대기 → 6
3. [처리] Sense 서비스와 인벤토리를 확인한다
   - 주체: 관리자
   - 위치: 기기 PowerShell › Get-Service Sense | Microsoft Defender 포털 › 디바이스 인벤토리
   - 데이터: 서비스 상태 · 디바이스 목록
   - 해설: 서비스와 포털에 표시되는 기기를 함께 확인합니다.
4. [처리] 테스트 활동과 ASR 모드를 대조한다
   - 주체: Windows 기기
   - 데이터: ASR 규칙 ID · 감사 또는 차단 설정 · 관련 이벤트
   - 해설: 감사는 차단 효과를 뜻하지 않으며 차단은 적용된 규칙과 조건에 따라 달라집니다.
5. [끝] 정책과 기기 증적을 연결해 확인한다
   - 주체: 관리자
   - 데이터: Intune 성공 상태 · 인벤토리 · ASR 이벤트
   - 해설: 정책 설정, 기기 적용, 이벤트를 각각 구별합니다.
6. [끝] 적용 오류나 체크인 대기를 조사한다
   - 주체: 관리자
   - 데이터: 기기별 상태 · 설정별 충돌 · 마지막 체크인
   - 해설: 이벤트가 보이지 않는 이유가 악성 행위 부재인지 수집 공백인지 분리해 조사합니다.
- 시나리오: 성공 :: 온보딩 성공 후 기기와 ASR 증적 확인
- 시나리오: 실패 또는 대기 :: 정책 오류 또는 체크인 대기 진단

> 교육 포인트: ASR 모드는 EDR 온보딩 성공과 별도 설정이다. 원고의 예는 Windows와 Intune에 한정한다.
> 주의: 실제 포털 메뉴와 이벤트 종류·기능별 라이선스는 환경과 플랜에 따라 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조].
> 출처: https://learn.microsoft.com/en-us/defender-endpoint/onboarding-endpoint-manager

### L3 · A · ASR 감사와 차단 — 같은 규칙의 서로 다른 결과

#### L4 · ASR 모드 비교 — 테스트 기기의 규칙 설정을 확인한다

1. [시작] 관리자가 테스트할 ASR 규칙을 고른다
   - 주체: 관리자
   - 위치: Intune 관리 센터 › 엔드포인트 보안 › 공격 표면 감소
   - 데이터: ASR 규칙 ID · 기기 그룹
   - 해설: 특정 규칙과 대상을 정한 다음 적용 모드를 비교합니다.
2. [처리] 우선 감사 모드를 할당한다
   - 주체: 관리자
   - 데이터: 선택 규칙의 Audit 설정
   - 해설: 테스트가 필요한 규칙은 감사부터 시작합니다.
3. [처리] 체크인과 정책 적용 결과를 확인한다
   - 주체: Intune
   - 데이터: 기기별 상태 및 설정 충돌
   - 해설: 정책 생성만으로 기기에 반영됐다고 볼 수 없습니다.
4. [판단] 운영 검토 후 차단 모드로 변경했는가?
   - 주체: 관리자
   - 해설: 승인된 테스트 결과에 따라 감사와 차단을 구분합니다.
   - 감사 유지 → 5
   - 차단 전환 → 6
5. [끝] 감사 이벤트를 검토한다
   - 주체: 관리자
   - 데이터: 적용된 규칙 및 감사 이벤트
   - 해설: 감사 기록은 해당 규칙이 행위를 차단했다는 증거가 아닙니다.
6. [끝] 적용된 차단 결과를 검토한다
   - 주체: 관리자
   - 데이터: 적용된 규칙 · 차단 이벤트 · 예외 설정
   - 해설: 차단 모드 적용과 실제 행위의 규칙 일치 여부를 함께 확인합니다.
- 시나리오: 감사 유지 :: 감사 모드에서 영향과 이벤트 확인
- 시나리오: 차단 전환 :: 차단 모드 적용 후 결과 확인

> 출처: https://learn.microsoft.com/en-us/defender-endpoint/onboarding-endpoint-manager
