## L2 · 자동 조사 · 대응 AIR — 기기 조사와 승인

- 설정(Control Plane): Defender for Endpoint 기기 그룹별 자동화 수준
- 강제(Enforcement): 경고의 관련 아티팩트를 조사하고 설정에 따라 자동 조치 또는 승인 대기
- 증적(Evidence): 조사 세부 정보 · Action center의 Pending · History
- 메뉴(Admin Center): Microsoft Defender 포털 > 시스템 > 설정 > Endpoints > Device groups | Action center [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
- 라이선스(License): Defender for Endpoint의 AIR 및 기기 그룹 기능별 플랜·권한 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 설정 확인 → 자동화 수준 → 조사와 조치

#### L4 · ⓪ 비활성 — 자동 조사 조건을 확인하기 전

1. [시작] 운영자가 기기 보안 경고를 확인한다
   - 주체: 보안 운영자
   - 데이터: 경고 · 기기
   - 해설: 경고가 생겼다고 대응이 자동 완료된 것은 아닙니다.
2. [처리] 기기의 온보딩과 그룹을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 디바이스 인벤토리
   - 데이터: 온보딩 상태 · 기기 그룹
   - 해설: 조사와 대응에는 제품 및 그룹 설정이 영향을 줍니다.
3. [처리] 자동 조사와 조치 상태를 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › 인시던트 · Action center
   - 데이터: 조사 여부 · 대기 조치
   - 해설: 조사 없음과 조치 승인 대기를 혼동하지 않습니다.
4. [끝] 미설정 항목과 수동 대응을 기록한다
   - 주체: 보안 운영자
   - 데이터: 그룹 설정 · 대응 상태
   - 해설: 조치가 보이지 않아도 위험이 없다고 결론 내리지 않습니다.

#### L4 · ① 구성 — 기기 그룹의 자동화 수준을 정한다

1. [시작] Defender for Endpoint와 기기 온보딩을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 디바이스 인벤토리
   - 데이터: 기기 · 온보딩 상태 · 사용 권한
   - 해설: 이 예제는 Defender for Endpoint의 기기 조사입니다.
2. [처리] 기기 그룹 설정을 연다
   - 주체: 관리자
   - 위치: Defender 포털 › Settings › Endpoints › Device groups [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 기존 그룹 · 그룹 순서
   - 해설: 기기가 어느 그룹에 속하는지 확인합니다.
3. [처리] 대상 기기 그룹을 선택한다
   - 주체: 관리자
   - 위치: Device groups › 대상 그룹
   - 데이터: 기기 조건 · 그룹 이름
   - 해설: 자동화 수준은 기기 그룹과 연결됩니다.
4. [처리] 자동화 수준을 선택한다
   - 주체: 관리자
   - 위치: Device group › Automation level
   - 데이터: Full 또는 승인 필요한 수준
   - 해설: 수준에 따라 악성 아티팩트의 조치가 자동 실행되거나 승인을 기다립니다.
5. [처리] 조치 승인 권한을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 권한 · Action center [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 보안 운영자의 승인 권한
   - 해설: 승인 대기 조치를 처리할 담당자를 지정합니다.
6. [끝] 설정을 저장하고 기기 그룹 적용을 확인한다
   - 주체: 관리자
   - 위치: Device groups › 저장
   - 데이터: 그룹 규칙 · 자동화 수준
   - 해설: 설정된 수준과 실제 조사 결과를 별도로 확인합니다.

#### L4 · ② 활성 — 조사 결과의 조치를 추적한다

1. [시작] 지원되는 기기 경고로 자동 조사가 시작된다
   - 주체: Defender for Endpoint
   - 데이터: 경고 · 기기 · 조사 ID
   - 해설: 조사는 관련 아티팩트를 분석합니다.
2. [처리] 조사가 의심 항목을 평가한다
   - 주체: Defender for Endpoint
   - 데이터: 파일 · 프로세스 · 조사 결과
   - 해설: 악성으로 판단된 항목에 필요한 대응이 제안될 수 있습니다.
3. [판단] 필요한 조치가 승인 대기 상태인가?
   - 주체: Defender for Endpoint
   - 데이터: 자동화 수준 · 조치 상태
   - 해설: 자동화 수준과 조치에 따라 승인 필요 여부가 다릅니다.
   - 자동 실행 → 4
   - 승인 대기 → 6
4. [처리] 자동 실행된 조치의 결과를 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Action center › History
   - 데이터: 조치 · 상태 · 기기
   - 해설: 자동 실행이 항상 성공했음을 뜻하지 않습니다.
5. [끝] 조사와 대응 이력을 연결해 기록한다
   - 주체: 보안 운영자
   - 데이터: 조사 ID · 조치 이력
   - 해설: 조치 결과와 후속 확인을 남깁니다.
6. [끝] 대기 조치를 검토하고 승인 또는 거부한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Action center › Pending
   - 데이터: 승인 대기 조치 · 대상 · 사유
   - 해설: 권한 있는 운영자가 영향을 검토한 뒤 처리합니다.
- 시나리오: 자동 실행 :: 자동 대응 이력과 성공 여부 확인
- 시나리오: 승인 대기 :: 대기 중 조치의 영향 검토와 승인

> 주의: AIR 자동화 수준과 기능별 라이선스, 메일 조사의 동작은 제품마다 다르므로 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조].

### L3 · A · 승인 흐름 — 대기와 완료를 구별

#### L4 · Action center 검토 — 조치의 실제 상태

1. [시작] 자동 조사에서 대응 조치가 제안된다
   - 주체: Defender for Endpoint
   - 데이터: 조사 결과 · 제안된 조치
   - 해설: 제안과 실행은 다른 상태입니다.
2. [처리] 운영자가 Action center를 연다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Action center
   - 데이터: Pending · History
   - 해설: 대기 항목과 완료 이력을 구분합니다.
3. [판단] 조치가 Pending에 있는가?
   - 주체: 보안 운영자
   - 데이터: 조치 상태
   - 해설: 승인 대기라면 실행된 것으로 볼 수 없습니다.
   - 대기 → 4
   - 이력 → 5
4. [끝] 대상과 영향을 검토하고 승인 또는 거부한다
   - 주체: 보안 운영자
   - 데이터: 대상 · 승인 결정
   - 해설: 승인 권한과 결과를 확인합니다.
5. [끝] History에서 완료 또는 실패 상태를 확인한다
   - 주체: 보안 운영자
   - 데이터: 실행 상태 · 조치 이력
   - 해설: 이력에 있는 항목도 성공 여부를 별도로 확인합니다.
- 시나리오: 대기 :: 승인 대기 조치의 영향 검토
- 시나리오: 이력 :: 실행된 조치의 결과 확인
