## L2 · M365 활동 → XDR — CloudAppEvents 수집 경로

- 설정(Control Plane): Defender for Cloud Apps 앱 커넥터에서 Microsoft 365 activities 선택
- 강제(Enforcement): Cloud Apps가 연결된 앱 활동을 수집·보강해 고급 헌팅 데이터로 제공
- 증적(Evidence): CloudAppEvents의 Timestamp · ActionType · Application
- 메뉴(Admin Center): Microsoft Defender 포털 > 시스템 > 설정 > Cloud apps > App connectors | 고급 헌팅
- 라이선스(License): Defender for Cloud Apps와 고급 헌팅 접근 조건 및 데이터별 권한 [확인 필요]

### L3 · 0 · 기능 상태 전이 — 활동 미연결 → 수집 설정 → 헌팅

#### L4 · ⓪ 비활성 — Microsoft 365 활동을 수집하지 않는 경우

1. [시작] 보안 운영자가 M365 앱 활동을 찾는다
   - 주체: 보안 운영자
   - 데이터: 사용자 · 앱 · 활동 시간
   - 해설: 앱 활동을 고급 헌팅에서 확인하려는 상황입니다.
2. [처리] Cloud Apps 배포와 앱 커넥터를 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 설정 › Cloud apps › App connectors
   - 데이터: Cloud Apps 배포 및 M365 활동 설정
   - 해설: CloudAppEvents는 Defender for Cloud Apps가 채웁니다.
3. [처리] 수집 설정이 없는 환경에서 테이블 결과를 검토한다
   - 주체: 보안 운영자
   - 데이터: CloudAppEvents 쿼리 결과
   - 해설: Cloud Apps가 배포되지 않았다면 쿼리는 작동하지 않거나 결과가 없을 수 있습니다.
4. [끝] 활동 부재와 수집 부재를 구분한다
   - 주체: 보안 운영자
   - 데이터: 연결 상태 · 조회 범위
   - 해설: 결과가 없다는 이유만으로 사용자 활동이 없었다고 단정하지 않습니다.

#### L4 · ① 구성 — Microsoft 365 활동 수집을 선택한다

1. [시작] 관리자가 Cloud Apps 배포와 권한을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 설정 › Cloud apps
   - 데이터: 제품 배포 · 관리자 권한 [확인 필요]
   - 해설: Cloud Apps가 CloudAppEvents 데이터의 수집 출처입니다.
2. [처리] 앱 커넥터 화면을 연다
   - 주체: 관리자
   - 위치: Defender 포털 › Settings › Cloud apps › App connectors
   - 데이터: Microsoft 365 앱 연결 상태
   - 해설: 앱 커넥터에서 수집할 구성 요소를 선택합니다.
3. [처리] Microsoft 365 구성 요소 선택 화면을 연다
   - 주체: 관리자
   - 위치: App connectors › Select Microsoft 365 components
   - 데이터: 선택 가능한 구성 요소
   - 해설: 다른 구성 요소와 활동 수집을 구분합니다.
4. [처리] Microsoft 365 activities를 선택한다
   - 주체: 관리자
   - 위치: Select Microsoft 365 components › Microsoft 365 activities
   - 데이터: Microsoft 365 활동 선택 상태
   - 해설: 공식 스키마 문서에 안내된 활동 수집 선택입니다.
5. [처리] 커넥터 상태를 검토한다
   - 주체: 관리자
   - 위치: App connectors › Microsoft 365 [확인 필요]
   - 데이터: 연결 상태 · 오류
   - 해설: 설정 저장과 실제 수집 상태를 구분합니다.
6. [끝] 헌팅 조회 권한과 대상 앱 범위를 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › 고급 헌팅
   - 데이터: 사용자 권한 · 테이블 접근
   - 해설: 환경별 라이선스 및 데이터 접근 범위는 확인해야 합니다.

#### L4 · ② 활성 — M365 활동을 헌팅 결과와 대조한다

1. [시작] 연결된 M365 앱에서 사용자 활동이 발생한다
   - 주체: 사용자
   - 데이터: 계정 · 앱 · 활동 시각
   - 해설: 활동 유형과 지원 범위에 따라 수집되는 정보가 다릅니다.
2. [처리] Cloud Apps가 연결된 앱의 활동을 수집한다
   - 주체: Defender for Cloud Apps
   - 데이터: 앱 활동 기록
   - 해설: 이 테이블에는 연결된 여러 SaaS 앱의 보강된 활동이 포함될 수 있습니다.
3. [처리] 운영자가 CloudAppEvents를 쿼리한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › 고급 헌팅
   - 데이터: Timestamp · Application · ActionType
   - 해설: 앱과 기간을 지정해 조사 범위를 좁힙니다.
4. [판단] 기대한 활동이 조회되는가?
   - 주체: 보안 운영자
   - 데이터: 쿼리 결과 · 확인할 활동
   - 해설: 결과가 없을 때에는 수집과 조회 전제를 따로 점검합니다.
   - 조회됨 → 5
   - 조회 안 됨 → 6
5. [끝] 활동 시각과 앱을 다른 증거와 대조한다
   - 주체: 보안 운영자
   - 데이터: Timestamp · Application · ActionType
   - 해설: 이벤트가 의미하는 실제 활동은 해당 앱의 스키마를 확인합니다.
6. [끝] 연결·권한·조회 범위를 점검한다
   - 주체: 보안 운영자
   - 데이터: 커넥터 상태 · 권한 · 시간 필터 · 수집 지연 [확인 필요]
   - 해설: 권한 부족, 수집 공백과 쿼리 범위를 구별합니다.
- 시나리오: 조회됨 :: M365 활동을 헌팅 테이블에서 확인
- 시나리오: 조회 안 됨 :: 활동 부재와 수집 공백을 분리

> 주의: 활동별 지원과 데이터 지연·보존·Copilot 활동 범위는 [확인 필요].

### L3 · A · 테이블 해석 — 연결된 앱별 활동 구별

#### L4 · 앱별 결과 — 조회 범위를 좁힌다

1. [시작] 조사할 앱과 기간을 정한다
   - 주체: 보안 운영자
   - 데이터: Application · 시간 범위
   - 해설: CloudAppEvents는 여러 연결 앱을 포함할 수 있습니다.
2. [처리] 테이블에서 앱과 시간 필드를 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › 고급 헌팅 › CloudAppEvents
   - 데이터: Timestamp · Application · ActionType
   - 해설: 각 행은 기록된 앱 활동의 맥락을 제공합니다.
3. [판단] 찾는 앱 활동이 결과에 있는가?
   - 주체: 보안 운영자
   - 데이터: 앱 필터 · 반환 행
   - 해설: 연결되지 않았거나 지원되지 않는 앱은 별도 확인합니다.
   - 있음 → 4
   - 없음 → 5
4. [끝] 활동 유형과 계정 맥락을 조사한다
   - 주체: 보안 운영자
   - 데이터: ActionType · 계정 · 앱
   - 해설: 활동을 다른 신호와 연관해 조사합니다.
5. [끝] 커넥터와 조회 권한을 확인한다
   - 주체: 관리자
   - 데이터: 앱 연결 상태 · 조회 권한
   - 해설: 결과 없음은 앱에서 아무 일도 없었다는 증명이 아닙니다.
- 시나리오: 있음 :: 앱별 활동 유형과 계정 확인
- 시나리오: 없음 :: 앱 연결과 헌팅 권한 점검
