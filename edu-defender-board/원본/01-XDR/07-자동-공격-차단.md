## L2 · 자동 공격 차단 — 고신뢰 인시던트의 격리 조치

- 설정(Control Plane): 제품별 라이선스·자동화·필수 신호 구성 | 공격 차단 제외 대상 검토
- 강제(Enforcement): 고신뢰 공격 인시던트의 영향을 받는 자산에 지원되는 자동 대응 적용
- 증적(Evidence): 인시던트의 공격 차단 세부 정보 · Action center의 대응 조치
- 메뉴(Admin Center): Microsoft Defender 포털 > Incidents & alerts > Incidents | Action center
- 라이선스(License): Defender XDR의 적격 구독 조합(예: Microsoft 365 E5/A5, 일부 E3 추가 기능, 단독 Defender 제품)을 충족해야 하며 대응 작업에 필요한 제품 배포가 필요 [확인 필요: 테넌트의 SKU 조합·배포 제품·조치별 권한을 Microsoft Learn 요구 사항 및 고객 계약에서 대조]

### L3 · 0 · 기능 상태 전이 — 조건 미충족 → 구성 → 공격 중단 확인

#### L4 · ⓪ 비활성 — 자동 차단 전제가 충족되지 않은 경우

1. [시작] 운영자가 공격 차단 대상 제품을 확인한다
   - 주체: 보안 운영자
   - 데이터: 온보딩 기기 · ID · 메일
   - 해설: 자동 공격 차단은 제품별 신호와 구성에 의존합니다.
2. [처리] 제품과 라이선스 조건을 대조한다
   - 주체: 관리자
   - 데이터: MDE P2 · 연결 제품
   - 해설: 필요한 라이선스가 없으면 해당 기능을 가정할 수 없습니다.
3. [처리] 관련 인시던트의 조치 이력을 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Action center
   - 데이터: 자동 대응 이력
   - 해설: 조치가 없다는 사실만으로 공격이 없었다고 결론 내리지 않습니다.
4. [끝] 누락된 선행 조건을 기록한다
   - 주체: 관리자
   - 데이터: 라이선스 · 제품 상태 · 조치 대상
   - 해설: 탐지, 자동 조치 및 운영자 수동 대응을 구별합니다.

#### L4 · ① 구성 — 자동 차단의 전제와 제외를 검토한다

1. [시작] 제품 라이선스와 권한을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 설정 · 사용 권한
   - 데이터: MDE P2 · 작업 센터 권한
   - 해설: 사용 권한과 조치별 필요 권한을 함께 점검합니다.
2. [처리] 엔드포인트 온보딩과 센서 버전을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 디바이스 인벤토리
   - 데이터: 기기 온보딩 · Sense 버전
   - 해설: MDE 기반 조치는 제품별 필수 설정에 의존합니다.
3. [처리] 기기 그룹 자동화 설정을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 설정 › Endpoints › Device groups [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 기기 그룹 · 자동화 수준
   - 해설: 그룹 설정이 조치 지원에 맞는지 확인합니다.
4. [처리] ID와 메일 보호의 추가 전제를 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › Identity · 이메일 설정 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 도메인 컨트롤러 감사 · 작업 계정 · 사서함 감사 이벤트
   - 해설: 적용할 제품별 필수 신호와 권한을 별도로 확인합니다.
5. [처리] 자동 공격 차단 제외 대상을 검토한다
   - 주체: 관리자
   - 위치: Defender 포털 › 자동 공격 차단 설정 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 제외된 기기 또는 계정
   - 해설: 대상 제외는 조치 가시성과 위험에 영향을 줄 수 있습니다.
6. [끝] 인시던트와 Action center 접근을 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Incidents · Action center
   - 데이터: 조치 검토 및 취소 권한
   - 해설: 자동 조치 이후에도 운영자가 결과를 확인해야 합니다.

#### L4 · ▶ ② 활성 — 고신뢰 공격과 대응 결과를 추적한다

1. [시작] 여러 제품의 신호가 인시던트로 상관된다
   - 주체: Defender XDR
   - 데이터: 엔드포인트 · ID · 메일 신호
   - 해설: 자동 공격 차단은 상관된 고신뢰 공격을 대상으로 합니다.
2. [처리] 공격에 사용된 자산과 가능한 조치를 식별한다
   - 주체: Defender XDR
   - 데이터: 인시던트 · 영향받은 자산
   - 해설: 신호가 있다고 모든 자산을 자동 격리하는 것은 아닙니다.
3. [판단] 대상이 지원 조치의 조건을 충족하고 제외되지 않았는가?
   - 주체: Defender XDR
   - 데이터: 자산 상태 · 조치 전제 · 제외 설정
   - 해설: 조치의 대상과 조건은 제품 및 공격 유형에 따라 다릅니다.
   - 충족 → 4
   - 미충족 또는 제외 → 6
4. [처리] 지원되는 자동 대응을 실행한다
   - 주체: Defender XDR
   - 데이터: 대상 자산 · 대응 작업 · 실행 상태
   - 해설: 실제 수행된 조치는 인시던트와 Action center에서 확인합니다.
5. [끝] 운영자가 대응 상태와 영향을 검토한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Action center · 인시던트
   - 데이터: 수행된 조치 · 결과 · 대상
   - 해설: 자동 조치의 성공과 해제 필요성을 확인합니다.
6. [끝] 미실행 원인과 수동 대응을 검토한다
   - 주체: 보안 운영자
   - 데이터: 제외 설정 · 제품 전제 · 조치 상태
   - 해설: 미실행과 실패는 구분해 조사합니다.
- 시나리오: 충족 :: 지원되는 대상의 자동 대응 결과 확인
- 시나리오: 미충족 또는 제외 :: 대상 제외 또는 전제 미충족 조사

> 주의: 자동 기기 격리는 문서상 미리 보기이며 지원 대상과 정확한 제외 효과는 [확인 필요: 기능·플랫폼·정책 모드별 동작을 최신 Microsoft Learn 및 격리된 테스트 테넌트에서 재현해 확인].

### L3 · A · 기기 격리 — 대상 범위와 해제

#### L4 · 자동 격리 — 온보딩된 워크스테이션

1. [시작] 운영자가 자동 기기 격리의 적용 범위를 검토한다
   - 주체: 보안 운영자
   - 데이터: 공격 인시던트 · 기기 유형
   - 해설: 이 조치는 온보딩되고 관리되는 사용자 워크스테이션에 적용됩니다.
2. [처리] 대상 기기의 제외 설정을 확인한다
   - 주체: 관리자
   - 위치: 자동 공격 차단 제외 설정 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 기기 제외 목록
   - 해설: 제외된 기기에 같은 자동 격리가 적용된다고 가정하지 않습니다.
3. [판단] 격리 조치가 수행되었는가?
   - 주체: Defender XDR
   - 데이터: 조치 상태 · 대상 기기
   - 해설: 실행 전제와 인시던트 조건을 함께 확인합니다.
   - 수행 → 4
   - 미수행 → 5
4. [끝] 운영자가 격리 이력과 해제 필요성을 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Action center
   - 데이터: 격리 상태 · 조치 이력
   - 해설: 보안 서비스 연결은 유지되며 운영자는 조기 해제를 검토할 수 있습니다.
5. [끝] 기기 지원·제외·신호 조건을 조사한다
   - 주체: 보안 운영자
   - 데이터: 온보딩 상태 · 제외 · 인시던트 증거
   - 해설: 조치가 없는 이유를 대상과 필수 조건으로 나누어 확인합니다.
- 시나리오: 수행 :: 자동 격리 이력과 해제 검토
- 시나리오: 미수행 :: 대상 및 제외 조건 확인
