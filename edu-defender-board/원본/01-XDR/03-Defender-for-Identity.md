## L2 · Defender for Identity — AD 센서와 신원 신호

- 설정(Control Plane): 도메인 컨트롤러 센서 설치·활성화 | 센서 버전별 디렉터리 서비스 계정 확인
- 강제(Enforcement): 센서가 AD 관련 활동을 수집해 위협 탐지에 사용 | 탐지 자체가 모든 인증을 차단하는 것은 아님
- 증적(Evidence): 센서 상태 · 신원 관련 경고 · 인시던트
- 메뉴(Admin Center): Microsoft Defender 포털 > 시스템 > 설정 > Identities > 센서 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
- 라이선스(License): Defender for Identity 사용 권한 필요; 센서 버전·서버 요구 사항과 포함 SKU [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 센서 미배포 → 센서 배포 → 신원 활동 조사

#### L4 · ⓪ 비활성 — 도메인 컨트롤러에 센서가 없는 경우

1. [시작] 관리자가 도메인 컨트롤러 목록을 확인한다
   - 주체: 관리자
   - 데이터: 서버 이름 · 도메인 · 운영체제
   - 해설: 보호 대상 서버와 센서 적용 범위를 먼저 정합니다.
2. [처리] 센서 관리 화면에서 온보딩 상태를 대조한다
   - 주체: 관리자
   - 위치: Defender 포털 › 센서 관리 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 서버별 온보딩 상태
   - 해설: 센서가 없는 도메인 컨트롤러는 수집 범위에 공백을 만들 수 있습니다.
3. [처리] 미배포 서버의 인증 활동을 검토한다
   - 주체: 관리자
   - 데이터: 서버별 센서 배포 여부
   - 해설: 다른 서버의 센서가 있다고 모든 도메인 컨트롤러가 관찰되는 것은 아닙니다.
4. [끝] 미배포 서버를 배포 계획에 넣는다
   - 주체: 관리자
   - 데이터: 누락 서버 목록
   - 해설: 센서 부재를 신원 공격이 없었다는 증거로 해석하지 않습니다.

#### L4 · ① 구성 — 도메인 컨트롤러에 센서를 준비한다

1. [시작] 도메인 컨트롤러와 지원되는 서버 버전을 확인한다
   - 주체: 관리자
   - 위치: 도메인 컨트롤러 › 서버 정보
   - 데이터: Windows Server 버전 · 누적 업데이트
   - 해설: 센서 버전의 지원 요구 사항을 확인합니다.
2. [처리] 센서 관리에서 서버 상태를 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 센서 관리
   - 데이터: 활성화 가능 · 온보딩됨 · 수동 온보딩 필요 상태
   - 해설: MDE 온보딩 및 서버 조건에 따라 센서 활성화 경로가 달라집니다.
3. [처리] 적합한 센서 버전과 배포 방법을 고른다
   - 주체: 관리자
   - 위치: 센서 관리 › 센서 활성화 또는 수동 온보딩
   - 데이터: 센서 v2 또는 v3 · 배포 패키지
   - 해설: 서버 조건에 따라 활성화 또는 패키지 배포를 선택합니다.
4. [처리] 센서를 설치하거나 활성화한다
   - 주체: 관리자
   - 위치: 대상 도메인 컨트롤러 · Defender 포털
   - 데이터: 설치 결과 · 센서 버전
   - 해설: 읽기 전용 도메인 컨트롤러도 배포 대상에서 빠뜨리지 않습니다.
5. [처리] 디렉터리 서비스 계정 설정을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › Identity 설정 › 디렉터리 서비스 계정 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 센서 버전 · 계정 유형
   - 해설: v3 센서는 로컬 시스템 계정을 사용하고 v2의 gMSA 설정을 사용하지 않습니다.
6. [끝] 센서 상태와 통신을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 센서 관리 › 센서 상태
   - 데이터: 센서 상태 · 오류 정보
   - 해설: 설치 완료와 정상 통신을 별도로 확인합니다.

#### L4 · ▶ ② 활성 — AD 신원 신호를 조사한다

1. [시작] 도메인 컨트롤러에서 인증 활동이 발생한다
   - 주체: 사용자
   - 데이터: 계정 · 인증 활동 · 대상 서버
   - 해설: 이 예제는 온보딩된 도메인 컨트롤러에서 발생한 활동입니다.
2. [판단] 해당 서버의 센서가 정상인가?
   - 주체: Defender for Identity
   - 데이터: 서버별 센서 상태
   - 해설: 센서 오류가 있으면 탐지 여부만으로 활동의 유무를 판단할 수 없습니다.
   - 정상 → 3
   - 오류 → 6
3. [처리] 센서가 관찰 가능한 AD 신호를 수집한다
   - 주체: Defender for Identity 센서
   - 데이터: 인증 활동과 관련 이벤트
   - 해설: 수집 대상과 이벤트 구성은 서버 및 센서 요구 사항에 따라 확인합니다.
4. [처리] 분석 결과의 경고와 관련 계정을 조사한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › 인시던트 및 경고
   - 데이터: 경고 · 계정 · 활동 시각
   - 해설: 경고는 지원되는 탐지 조건을 충족할 때 생성되며 모든 로그인에 생기지 않습니다.
5. [끝] 신원 신호와 경고의 증거를 연결한다
   - 주체: 보안 운영자
   - 데이터: 센서 상태 · 경고 증거
   - 해설: 센서 수집과 공격 대응은 구별합니다.
6. [끝] 센서 오류와 수집 공백을 조사한다
   - 주체: 관리자
   - 위치: Defender 포털 › 센서 상태
   - 데이터: 상태 경고 · 오류 로그
   - 해설: 서버 상태와 센서 연결을 확인하고 누락 기간을 기록합니다.
- 시나리오: 정상 :: 정상 센서에서 AD 신호와 경고 조사
- 시나리오: 오류 :: 센서 오류로 인한 관찰 공백 조사

> 주의: 실제 포털 경로, 최소 역할, 라이선스 및 이벤트 구성은 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조].

### L3 · A · 센서 버전 — 활성화와 계정 차이

#### L4 · 센서 버전 선택 — 서버 조건에 따른 배포 경로

1. [시작] 관리자가 서버와 센서 버전을 확인한다
   - 주체: 관리자
   - 데이터: 서버 OS · MDE 온보딩 상태
   - 해설: 서버가 어떤 센서 버전을 지원하는지 확인합니다.
2. [판단] 서버가 센서 v3 활성화 대상인가?
   - 주체: 관리자
   - 데이터: 운영체제 · 업데이트 · MDE 상태
   - 해설: MDE에 온보딩된 적격 서버는 포털에서 활성화할 수 있습니다.
   - 적격 → 3
   - v2만 지원 → 4
3. [끝] v3 센서 활성화와 로컬 시스템 계정을 확인한다
   - 주체: 관리자
   - 데이터: 센서 v3 · 로컬 시스템 계정
   - 해설: v3은 v2용 gMSA를 사용하지 않습니다.
4. [처리] v2 센서 설치와 계정 요구를 검토한다
   - 주체: 관리자
   - 데이터: 센서 v2 · 디렉터리 서비스 계정
   - 해설: v2의 설치 방식과 계정 요구를 해당 환경에 맞게 확인합니다.
5. [끝] 설치 후 센서 상태를 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 센서 관리
   - 데이터: 서버 · 센서 상태
   - 해설: 버전 선택 이후에도 실제 상태를 검증해야 합니다.
- 시나리오: 적격 :: 적격 서버에서 v3 센서 활성화
- 시나리오: v2만 지원 :: v2 설치와 계정 설정 검토
