## L2 · Defender for Cloud Apps — 앱 연결과 세션 제어

- 설정(Control Plane): 앱 커넥터로 SaaS 활동 연결 | 조건부 액세스 앱 제어 및 세션 정책 설정
- 강제(Enforcement): API 연결은 앱 활동 가시성 제공 | 지원 세션은 프록시를 통한 실시간 제어
- 증적(Evidence): 앱 활동 · 세션 정책 일치 결과 · Conditional Access App Control 트래픽 로그
- 메뉴(Admin Center): Microsoft Defender 포털 > Cloud Apps > 정책 관리 [확인 필요] | 시스템 > 설정 > Cloud Apps > 연결된 앱
- 라이선스(License): Defender for Cloud Apps 및 조건부 액세스에 필요한 라이선스·권한 [확인 필요]

### L3 · 0 · 기능 상태 전이 — 연결 전 → 제어 구성 → 다운로드 평가

#### L4 · ⓪ 비활성 — 세션 제어가 없는 앱

1. [시작] 사용자가 SaaS 앱에 로그인한다
   - 주체: 사용자
   - 데이터: 사용자 · 앱 · 로그인
   - 해설: 이 예제는 세션 제어가 아직 적용되지 않은 앱입니다.
2. [처리] 관리자가 앱의 연결과 세션 정책을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › Cloud Apps › 연결된 앱 [확인 필요]
   - 데이터: 커넥터 및 세션 정책 여부
   - 해설: API 커넥터의 활동 수집과 프록시 세션 제어는 서로 다릅니다.
3. [처리] 세션 내 다운로드가 발생한다
   - 주체: 사용자
   - 데이터: 파일 다운로드 활동
   - 해설: 이 경로에서 Cloud Apps 세션 정책은 다운로드를 평가하지 않습니다.
4. [끝] 관리자가 제어 범위의 공백을 기록한다
   - 주체: 관리자
   - 데이터: 미적용 앱 · 다른 보호 정책
   - 해설: 다른 앱 측 통제의 존재 여부는 별도로 확인합니다.

#### L4 · ① 구성 — 조건부 액세스와 다운로드 정책을 연결한다

1. [시작] 관리자가 지원 앱과 라이선스를 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › Cloud Apps
   - 데이터: 앱 · 대상 사용자 · 라이선스 [확인 필요]
   - 해설: 지원되는 앱과 대상 범위를 검토합니다.
2. [처리] 조건부 액세스 정책의 대상 앱을 선택한다
   - 주체: 관리자
   - 위치: Entra 관리 센터 › 보호 › 조건부 액세스 › 정책
   - 데이터: 사용자 · 대상 앱 · 적용 조건
   - 해설: 로그인 허용 조건과 세션 제어는 별개로 구성합니다.
3. [처리] 조건부 액세스 앱 제어를 세션에 적용한다
   - 주체: 관리자
   - 위치: 조건부 액세스 정책 › 세션 › 조건부 액세스 앱 제어 [확인 필요]
   - 데이터: 세션 제어 적용 설정
   - 해설: 지원되는 세션이 Cloud Apps 제어 경로를 이용하도록 구성합니다.
4. [처리] Cloud Apps 세션 정책을 만든다
   - 주체: 관리자
   - 위치: Defender 포털 › Cloud Apps › 정책 관리 › 세션 정책 [확인 필요]
   - 데이터: 정책 이름 · 앱 · 사용자 및 활동 필터
   - 해설: 제어할 파일 다운로드와 적용 조건을 명시합니다.
5. [처리] 다운로드 검사와 차단 동작을 선택한다
   - 주체: 관리자
   - 위치: 세션 정책 › Control file download (with inspection) › Block
   - 데이터: 다운로드 필터 · 차단 동작
   - 해설: 지정한 필터에 맞는 다운로드가 제어됩니다.
6. [끝] 정책을 저장하고 테스트 대상을 확인한다
   - 주체: 관리자
   - 위치: Cloud Apps › 세션 정책
   - 데이터: 정책 상태 · 대상 · 예외
   - 해설: 테스트 사용자와 앱이 두 정책의 범위에 드는지 확인합니다.

#### L4 · ② 활성 — 파일 다운로드가 세션 정책에 일치하는지 평가한다

1. [시작] 대상 사용자가 지원 앱에 로그인한다
   - 주체: 사용자
   - 데이터: 사용자 · 앱 · 로그인 조건
   - 해설: 로그인 허용 이후 세션 내 활동을 검토합니다.
2. [처리] 조건부 액세스가 세션 제어를 적용한다
   - 주체: Entra ID
   - 데이터: 조건부 액세스 정책 · 앱 제어 설정
   - 해설: 대상 세션이 Cloud Apps 제어 경로로 라우팅됩니다.
3. [처리] 사용자가 파일을 다운로드한다
   - 주체: 사용자
   - 데이터: 앱 · 파일 · 다운로드 요청
   - 해설: 세션 정책은 이 활동과 필터를 평가합니다.
4. [판단] 다운로드가 차단 정책 필터에 일치하는가?
   - 주체: Defender for Cloud Apps
   - 데이터: 세션 정책 필터 · 다운로드 속성
   - 해설: 정책 일치 여부에 따라 이 예제의 결과가 달라집니다.
   - 일치 → 5
   - 불일치 → 6
5. [끝] 다운로드 차단과 정책 결과를 확인한다
   - 주체: Defender for Cloud Apps
   - 데이터: 차단된 다운로드 · 세션 정책 결과
   - 해설: 검사와 차단으로 구성된 정책은 필터에 맞는 다운로드를 차단합니다.
6. [끝] 이 정책에 의한 다운로드 차단은 적용되지 않는다
   - 주체: Defender for Cloud Apps
   - 데이터: 정책 불일치 · 다른 정책 여부
   - 해설: 다른 앱 또는 보안 정책의 결과는 별도로 평가해야 합니다.
- 시나리오: 일치 :: 세션 필터에 맞는 다운로드 차단
- 시나리오: 불일치 :: 세션 필터 밖 다운로드는 이 정책 미적용

> 주의: 앱 온보딩·지원 클라이언트·조건부 액세스 역할 및 라이선스는 [확인 필요].

### L3 · A · 연결 방식 — API 수집과 프록시 제어 구별

#### L4 · 활동과 세션 — 두 연결의 역할을 비교한다

1. [시작] 관리자가 앱의 보호 목적을 정한다
   - 주체: 관리자
   - 데이터: SaaS 활동 가시성 · 다운로드 제어
   - 해설: 활동 기록과 실시간 제어는 다른 경로입니다.
2. [처리] 지원 앱 커넥터로 앱을 연결한다
   - 주체: 관리자
   - 위치: Defender 포털 › 설정 › Cloud Apps › App connectors
   - 데이터: 앱 인스턴스 · 커넥터 상태
   - 해설: API 연결을 통한 앱 활동 가시성을 확인합니다.
3. [판단] 실시간 세션 제어도 구성했는가?
   - 주체: 관리자
   - 데이터: 조건부 액세스 앱 제어 · 세션 정책
   - 해설: API 연결만으로 프록시 다운로드 차단이 생기지는 않습니다.
   - 구성됨 → 4
   - 미구성 → 5
4. [끝] 지원되는 세션에서 정책을 평가한다
   - 주체: Defender for Cloud Apps
   - 데이터: 앱 제어 경로 · 세션 정책
   - 해설: 조건에 일치하는 활동에 설정된 세션 제어가 적용됩니다.
5. [끝] API 활동 가시성과 세션 제어 공백을 구분한다
   - 주체: 관리자
   - 데이터: 앱 활동 · 미구성 세션 정책
   - 해설: 활동 기록이 존재해도 다운로드 차단을 가정하지 않습니다.
- 시나리오: 구성됨 :: API 가시성과 프록시 세션 제어 결합
- 시나리오: 미구성 :: 앱 연결만 있는 세션 제어 공백
