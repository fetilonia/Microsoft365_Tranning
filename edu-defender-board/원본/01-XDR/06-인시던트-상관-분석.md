## L2 · 인시던트 상관 분석 — 관련 경고와 공격 맥락

- 설정(Control Plane): 연결된 보안 제품과 경고 수집 범위 · 인시던트 조사 권한
- 강제(Enforcement): Defender 상관 엔진이 관련 경고를 인시던트로 집계
- 증적(Evidence): 인시던트 경고 · 엔터티 · 조사 그래프 · 활동 타임라인
- 메뉴(Admin Center): Microsoft Defender 포털 > Incidents & alerts > Incidents [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
- 라이선스(License): Defender XDR과 연결된 제품의 사용 조건 · 조사 데이터별 권한 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 신호 공백 → 수집 범위 확인 → 인시던트 조사

#### L4 · ⓪ 비활성 — 연결되지 않은 제품의 신호

1. [시작] 운영자가 여러 제품의 공격 흔적을 조사한다
   - 주체: 보안 운영자
   - 데이터: 계정 · 기기 · 메일
   - 해설: 관련 신호가 여러 원본에 흩어질 수 있습니다.
2. [처리] 제품 연결과 경고 수집을 확인한다
   - 주체: 관리자
   - 데이터: 제품별 연결 · 라이선스
   - 해설: 연결되지 않은 제품의 데이터는 이 조사 경로에 없을 수 있습니다.
3. [처리] 인시던트에서 관찰 가능한 경고를 검토한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › 인시던트
   - 데이터: 수집된 경고 · 관련 엔터티
   - 해설: 보이는 경고만으로 전체 공격 범위를 단정하지 않습니다.
4. [끝] 신호 공백과 조사 범위를 기록한다
   - 주체: 보안 운영자
   - 데이터: 미연결 제품 · 누락된 데이터
   - 해설: 인시던트 부재는 공격 부재를 의미하지 않습니다.

#### L4 · ① 구성 — 제품 신호와 조사 권한을 준비한다

1. [시작] 조사할 제품과 자산을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 제품 설정
   - 데이터: 연결 제품 · 보호 대상
   - 해설: 사용자, 기기, 메일 등 출처별 수집 범위를 확인합니다.
2. [처리] 제품별 온보딩 상태를 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 설정
   - 데이터: 제품 연결 상태 · 오류
   - 해설: 제품별 연결 절차와 필요 조건은 다릅니다.
3. [처리] 운영자의 조사 권한을 검토한다
   - 주체: 관리자
   - 위치: Defender 포털 › 권한 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 역할 · 데이터 범위
   - 해설: 권한에 따라 볼 수 있는 자산과 조치가 달라질 수 있습니다.
4. [처리] 인시던트 목록 필터를 지정한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Incidents & alerts › Incidents
   - 데이터: 상태 · 심각도 · 담당자
   - 해설: 조사할 인시던트를 찾기 위한 화면 필터입니다.
5. [처리] 관련 경고와 엔터티 탭을 확인한다
   - 주체: 보안 운영자
   - 위치: 인시던트 상세 › Alerts · Assets
   - 데이터: 경고 출처 · 기기 · 사용자
   - 해설: 상관 결과와 개별 경고의 출처를 구분합니다.
6. [끝] 조사 범위와 담당자를 기록한다
   - 주체: 보안 운영자
   - 위치: 인시던트 상세
   - 데이터: 인시던트 ID · 담당자 · 상태
   - 해설: 이후 증거와 대응을 같은 인시던트에서 추적합니다.

#### L4 · ▶ ② 활성 — 관련 경고와 자산을 조사한다

1. [시작] 연결된 제품에서 보안 경고가 발생한다
   - 주체: Defender 제품
   - 데이터: 경고 · 자산 · 시각
   - 해설: 서로 다른 제품의 신호가 하나의 공격과 관련될 수 있습니다.
2. [처리] 상관 엔진이 관련 경고를 집계한다
   - 주체: Defender XDR
   - 데이터: 경고 및 관련 엔터티
   - 해설: 관련된 경고를 인시던트로 묶어 공격 맥락을 보여 줍니다.
3. [처리] 운영자가 인시던트와 조사 그래프를 연다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Incidents › 인시던트 상세
   - 데이터: 경고 · 사용자 · 기기 · 메일
   - 해설: 엔터티 간 연결과 타임라인을 살펴봅니다.
4. [판단] 조사 대상의 관련 경고와 자산이 보이는가?
   - 주체: 보안 운영자
   - 데이터: 수집 출처 · 관련 증거
   - 해설: 연관성이 부족하거나 신호가 늦으면 보이는 범위가 달라질 수 있습니다.
   - 확인됨 → 5
   - 누락 → 6
5. [끝] 경고별 증거와 자산을 기록한다
   - 주체: 보안 운영자
   - 데이터: 인시던트 ID · 경고 ID · 엔터티
   - 해설: 상관된 경고를 함께 보되 각 경고의 증거를 검토합니다.
6. [끝] 연결 상태와 권한·수집 지연을 조사한다
   - 주체: 보안 운영자
   - 데이터: 제품 연결 · 권한 · 경고 시각
   - 해설: 누락된 경고가 다른 인시던트인지 또는 아직 수집되지 않았는지 확인합니다.
- 시나리오: 확인됨 :: 관련 경고와 자산의 연결을 조사
- 시나리오: 누락 :: 수집 공백과 별도 인시던트 가능성 점검

> 주의: 상관 기준과 데이터 접근 범위는 환경마다 다르며 구체적 일치 조건은 [확인 필요: 대상 구독·테넌트·리전의 설정과 권한을 공식 절차 및 실제 관리자 화면에서 확인].
> 출처: https://learn.microsoft.com/en-us/defender-xdr/incidents-overview

### L3 · A · 조사 그래프 — 경고에서 엔터티로 이동

#### L4 · 공격 범위 확인 — 사용자와 기기를 연결한다

1. [시작] 운영자가 인시던트에서 경고를 선택한다
   - 주체: 보안 운영자
   - 데이터: 경고 ID · 발생 시각
   - 해설: 하나의 경고에서 조사를 시작합니다.
2. [처리] 조사 그래프의 관련 자산을 연다
   - 주체: 보안 운영자
   - 위치: 인시던트 상세 › 조사 그래프
   - 데이터: 사용자 · 기기 · 관련 경고
   - 해설: 그래프는 엔터티와 연관된 자산을 보여 줍니다.
3. [판단] 관련 기기의 세부 정보가 표시되는가?
   - 주체: 보안 운영자
   - 데이터: 기기 엔터티 · 접근 권한
   - 해설: 표시되지 않으면 수집 및 권한 범위부터 확인합니다.
   - 표시 → 4
   - 미표시 → 5
4. [끝] 기기와 사용자에 연결된 경고를 조사한다
   - 주체: 보안 운영자
   - 데이터: 기기 · 사용자 · 관련 경고
   - 해설: 관련 관계를 검토하고 개별 증거를 확인합니다.
5. [끝] 미표시 자산의 권한과 제품 연결을 점검한다
   - 주체: 보안 운영자
   - 데이터: 제품 상태 · 조사 권한
   - 해설: 그래프의 공백을 안전 판정으로 해석하지 않습니다.
- 시나리오: 표시 :: 관련 기기와 사용자 증거 조사
- 시나리오: 미표시 :: 조사 권한과 신호 수집 범위 점검

> 출처: https://learn.microsoft.com/en-us/defender-xdr/incidents-overview
