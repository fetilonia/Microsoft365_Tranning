## L2 · Defender for Office 365 — Safe Links 메일 보호

- 설정(Control Plane): Safe Links 사전 설정 또는 사용자 지정 정책 | 받는 사람 조건·예외 · URL 다시 쓰기 및 클릭 검사
- 강제(Enforcement): 메일 흐름에서 URL 검사 | 지원되는 클라이언트 또는 다시 쓴 URL에서 클릭 시 평가
- 증적(Evidence): Safe Links 정책 설정 · URL 클릭 보고서 [확인 필요: 기능별 이벤트·보고 필드, 필요한 감사 설정과 역할을 대상 테넌트의 Activity explorer·감사·경고에서 확인] | 사용자에게 표시된 경고 및 클릭 결과
- 메뉴(Admin Center): Microsoft Defender 포털 > 이메일 및 협업 > 정책 및 규칙 > 위협 정책 > Safe Links [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
- 라이선스(License): Defender for Office 365 라이선스와 사용자별 적용 조건 확인 | 기능 및 보고서의 플랜별 차이 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 보호 범위 확인 → 정책 구성 → 클릭 평가

#### L4 · ⓪ 비활성 — 이 메일에 Safe Links가 적용되지 않는 경우

1. [시작] 사용자가 링크가 포함된 메일을 받는다
   - 주체: Exchange Online
   - 데이터: 수신자 · 메시지 · URL
   - 해설: 이 예제는 수신 메시지의 링크 보호를 살펴봅니다.
2. [처리] 정책 적용 여부를 확인한다
   - 주체: 관리자
   - 데이터: 수신자 조건 · 예외 · 사전 설정 정책
   - 해설: 사용자 지정 정책이 없다는 사실만으로 보호가 없다고 결론 내리지 않습니다.
3. [처리] 해당 메시지 또는 클라이언트가 보호되지 않는 조건을 식별한다
   - 주체: 관리자
   - 데이터: 메시지 형식 · 클라이언트 지원 · 적용 정책
   - 해설: 예를 들어 RTF 메시지의 URL은 Safe Links 보호 범위가 아닙니다.
4. [끝] 링크 클릭 보호의 공백을 기록한다
   - 주체: 관리자
   - 데이터: 미지원 조건과 다른 보호 계층
   - 해설: Safe Links 공백이 모든 메일 보안 계층의 부재를 의미하지는 않습니다.

#### L4 · ① 구성 — 수신자와 메일 보호 옵션을 정한다

1. [시작] 관리자가 사용자 지정 정책 화면을 연다
   - 주체: 관리자
   - 위치: Microsoft Defender 포털 › 이메일 및 협업 › 정책 및 규칙 › 위협 정책 › Safe Links [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 관리자 역할과 기존 사전 설정 정책
   - 해설: 기존 Built-in protection과 사용자 지정 정책의 적용 범위를 먼저 확인합니다.
2. [처리] 정책 이름과 대상 수신자를 지정한다
   - 주체: 관리자
   - 위치: Safe Links › 만들기 › 사용자 및 그룹 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 사용자 · 지원되는 그룹 또는 도메인 조건
   - 해설: 서로 다른 조건 유형은 모두 충족해야 합니다.
3. [처리] 예외가 필요한 대상을 검토한다
   - 주체: 관리자
   - 위치: Safe Links 정책 › 예외 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 사용자 · 그룹 · 도메인 예외
   - 해설: 예외를 설정한 정책만으로 해당 사용자의 전체 보호를 판단하지 않습니다.
4. [처리] 메일에서 Safe Links 검사를 켠다
   - 주체: 관리자
   - 위치: Safe Links 정책 › 이메일 메시지 보호 설정 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 이메일 검사 · 내부 발신 메시지 적용 여부
   - 해설: 메일 보호와 내부 메시지 적용 여부를 각각 확인합니다.
5. [처리] URL 다시 쓰기와 다운로드 링크 검사 옵션을 검토한다
   - 주체: 관리자
   - 위치: Safe Links 정책 › 이메일 설정 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: URL 다시 쓰기 또는 API 전용 · 실시간 URL 검사
   - 해설: 다시 쓰지 않으면 클릭 시 검사는 지원되는 Outlook 클라이언트에 의존합니다.
6. [끝] 정책을 저장하고 적용 대상을 확인한다
   - 주체: 관리자
   - 위치: Safe Links 정책 › 검토 및 저장 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 정책 우선순위 · 수신자 범위
   - 해설: 실제 우선순위와 적용 정책은 환경에서 다시 확인합니다.

#### L4 · ② 활성 — 메일 링크를 클릭할 때 결과를 확인한다

1. [시작] 보호 대상 사용자가 링크가 포함된 메일을 받는다
   - 주체: Exchange Online
   - 데이터: 수신자 · URL · 적용 정책
   - 해설: 메시지 수신자에게 적용되는 Safe Links 설정이 중요합니다.
2. [처리] 메일 전달 전 URL을 검사한다
   - 주체: Safe Links
   - 데이터: 수신 메시지 URL · 정책의 검사 및 다시 쓰기 설정
   - 해설: 보호가 켜져 있으면 URL 다시 쓰기 여부와 무관하게 전달 전 검사가 수행됩니다.
3. [처리] 사용자가 메일의 URL을 클릭한다
   - 주체: 사용자
   - 데이터: 다시 쓴 URL 또는 지원 Outlook의 API 호출
   - 해설: 여기서는 URL 다시 쓰기가 켜진 메일을 예로 듭니다.
4. [판단] 클릭 시 URL이 악성으로 판정되는가?
   - 주체: Safe Links
   - 데이터: 클릭 시점의 URL 평가 결과
   - 해설: 같은 URL이라도 클릭 시점의 판정이 중요합니다.
   - 악성 → 5
   - 안전 → 6
5. [끝] 경고 페이지와 정책상 후속 동작을 확인한다
   - 주체: 사용자
   - 데이터: 악성 링크 경고 · 사용자 진행 허용 설정 [확인 필요: 기능별 이벤트·보고 필드, 필요한 감사 설정과 역할을 대상 테넌트의 Activity explorer·감사·경고에서 확인]
   - 해설: 악성으로 판정되면 경고가 나타나며 사용자의 진행 가능 여부는 설정을 확인합니다.
6. [끝] 대상 사이트로 이동한다
   - 주체: 사용자
   - 데이터: 클릭한 URL · 안전 판정
   - 해설: 이 시점의 안전 판정은 사이트의 미래 안전성을 보장하지 않습니다.
- 시나리오: 안전 :: 클릭 시 안전 판정으로 사이트 이동
- 시나리오: 악성 :: 클릭 시 악성 판정과 경고 확인

> 교육 포인트: Built-in protection이 존재할 수 있으므로 사용자 지정 정책이 없다는 이유만으로 비활성이라고 하지 않는다.
> 주의: 표시 메뉴·클릭 보고서·권한과 라이선스 상세는 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조].
> 출처: https://learn.microsoft.com/en-us/defender-office-365/safe-links-about

### L3 · A · 다시 쓰기와 API — 클라이언트 지원 경계

#### L4 · URL 검사 경로 — 다시 쓰기 없는 경우를 비교한다

1. [시작] 관리자가 URL 다시 쓰기 옵션을 검토한다
   - 주체: 관리자
   - 데이터: 다시 쓰기 사용 여부 · 사용자 클라이언트
   - 해설: 클릭 시 평가가 어느 경로로 가능한지 확인합니다.
2. [처리] URL을 다시 쓰지 않도록 선택한다
   - 주체: 관리자
   - 위치: Safe Links 정책 › 이메일 설정 › Do not rewrite URLs
   - 데이터: API 전용 클릭 검사 설정
   - 해설: URL은 전달 전에 검사되지만 클릭 시 검사는 클라이언트 지원에 좌우됩니다.
3. [처리] 사용자가 전달된 링크를 클릭한다
   - 주체: 사용자
   - 데이터: URL · 메일 클라이언트
   - 해설: 전달 후 악성으로 바뀐 링크가 특히 중요한 예입니다.
4. [판단] 클라이언트가 Safe Links API를 지원하는가?
   - 주체: 메일 클라이언트
   - 데이터: Outlook 지원 버전 여부
   - 해설: 미지원 클라이언트는 이 API 전용 경로를 사용할 수 없습니다.
   - 지원 → 5
   - 미지원 → 6
5. [끝] 클릭 시 API로 URL을 확인한다
   - 주체: Safe Links
   - 데이터: 클릭 시 URL 판정
   - 해설: 지원 Outlook은 API를 사용해 다시 쓰지 않은 링크를 검사합니다.
6. [끝] 클릭 시 API 보호 공백을 기록한다
   - 주체: 관리자
   - 데이터: 미지원 클라이언트 · 다시 쓰기 비활성
   - 해설: 전달 후 악성으로 바뀐 링크를 이 경로에서 놓칠 수 있습니다.
- 시나리오: 지원 :: 지원 Outlook에서 클릭 시 API 검사
- 시나리오: 미지원 :: 미지원 클라이언트의 클릭 검사 공백

> 주의: 특정 앱에서 정책 구성을 읽는 시스템 오류가 나면 Safe Links 보호 없이 링크로 이동할 수 있다. 사용자에게 오류가 항상 표시된다고 가정하지 않는다.
> 출처: https://learn.microsoft.com/en-us/defender-office-365/safe-links-about
