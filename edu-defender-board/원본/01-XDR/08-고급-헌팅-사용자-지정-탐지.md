## L2 · 고급 헌팅 · 사용자 지정 탐지 — KQL에서 경고로

- 설정(Control Plane): 고급 헌팅 KQL · 사용자 지정 탐지 빈도 · 경고 및 대응 설정
- 강제(Enforcement): 규칙이 지정 빈도로 데이터를 조회해 일치 결과에 경고와 선택적 대응 생성
- 증적(Evidence): 쿼리 결과 · 규칙 실행 상태 · 경고 · 대응 이력
- 메뉴(Admin Center): Microsoft Defender 포털 > Advanced hunting | Custom detection rules
- 라이선스(License): Defender XDR과 대상 데이터 원본별 헌팅·탐지 권한 필요; 플랜·데이터 보존 범위 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 규칙 없음 → 쿼리 검증 → 탐지 실행

#### L4 · ⓪ 비활성 — 사용자 지정 탐지가 없는 쿼리

1. [시작] 운영자가 특정 기기 활동을 조사한다
   - 주체: 보안 운영자
   - 데이터: DeviceEvents · 기기 식별자
   - 해설: 쿼리로 활동을 찾는 것과 주기적인 탐지는 다릅니다.
2. [처리] 고급 헌팅에서 KQL을 실행한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Advanced hunting
   - 데이터: 쿼리 결과 행
   - 해설: 수동 조회 결과는 그 자체로 탐지 규칙을 만들지 않습니다.
3. [처리] 사용자 지정 탐지 목록을 확인한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Custom detection rules
   - 데이터: 기존 규칙 · 상태
   - 해설: 해당 규칙이 없으면 이 쿼리의 자동 실행은 구성되지 않았습니다.
4. [끝] 규칙 작성 전 조사 기준을 정한다
   - 주체: 보안 운영자
   - 데이터: 의심 행위 · 정상 활동 제외 조건
   - 해설: 평상시 동작으로 불필요한 경고가 발생하지 않도록 조건을 다듬습니다.

#### L4 · ① 구성 — 쿼리에서 탐지 규칙을 만든다

1. [시작] 관리자가 대상 데이터 권한을 확인한다
   - 주체: 관리자
   - 위치: Defender 포털 › 사용 권한
   - 데이터: 보안 설정 관리 · 데이터 원본 범위
   - 해설: 여러 원본을 조회하는 규칙에는 해당 원본별 권한이 필요합니다.
2. [처리] 고급 헌팅에서 쿼리를 작성한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › Advanced hunting
   - 데이터: KQL · 대상 테이블
   - 해설: 기기 이벤트 등 조사하려는 원본을 선택합니다.
3. [처리] 쿼리 결과의 식별자를 검토한다
   - 주체: 보안 운영자
   - 위치: Advanced hunting › 쿼리 결과
   - 데이터: Timestamp · ReportId · DeviceId
   - 해설: MDE 테이블의 기기 범위와 프로세스 트리에는 DeviceId와 ReportId가 권장됩니다.
4. [처리] Create detection rule을 선택한다
   - 주체: 보안 운영자
   - 위치: Advanced hunting › Create detection rule
   - 데이터: 쿼리 · 규칙 이름 · 실행 빈도
   - 해설: 수동 조회를 검증한 다음 규칙 설정을 시작합니다.
5. [처리] 경고와 영향 자산을 지정한다
   - 주체: 보안 운영자
   - 위치: 규칙 마법사 › Alert settings
   - 데이터: 경고 제목 · 심각도 · 영향 자산 식별자
   - 해설: 쿼리 결과의 올바른 엔터티를 영향 자산에 매핑합니다.
6. [처리] 대응 및 대상 범위를 검토한다
   - 주체: 보안 운영자
   - 위치: 규칙 마법사 › Automated actions · Scope
   - 데이터: 대응 조치 · 기기 범위
   - 해설: 자동 조치는 필요한 권한과 대상 식별자가 충족될 때만 구성합니다.
7. [끝] 검토 후 규칙을 만든다
   - 주체: 보안 운영자
   - 위치: 규칙 마법사 › Review and create
   - 데이터: 규칙 설정 · 활성 상태
   - 해설: 자동 실행과 결과는 규칙 이력에서 확인합니다.

#### L4 · ▶ ② 활성 — 규칙 일치와 미일치 결과를 비교한다

1. [시작] 설정된 빈도에 따라 탐지 규칙이 실행된다
   - 주체: Defender XDR
   - 데이터: 규칙 · 실행 시각 · 조회 범위
   - 해설: 규칙은 해당 실행의 데이터 범위를 평가합니다.
2. [처리] KQL이 대상 이벤트를 검색한다
   - 주체: Defender XDR
   - 데이터: 테이블 · 필터 · 식별자
   - 해설: 데이터 수집과 조회 권한이 결과의 전제입니다.
3. [판단] 쿼리에 일치하는 결과가 있는가?
   - 주체: Defender XDR
   - 데이터: 쿼리 반환 행
   - 해설: 결과 없음과 규칙 실행 오류는 구분해야 합니다.
   - 일치 → 4
   - 일치 없음 → 6
4. [처리] 일치 결과로 경고를 만든다
   - 주체: Defender XDR
   - 데이터: 경고 세부 정보 · 영향 자산
   - 해설: 필요한 경우 규칙에 설정된 대응도 수행됩니다.
5. [끝] 경고와 대응 이력을 검토한다
   - 주체: 보안 운영자
   - 위치: Defender 포털 › 인시던트 및 경고 · Action center
   - 데이터: 경고 · 대응 상태
   - 해설: 자동 대응을 설정하지 않았다면 조치가 자동 실행되었다고 가정하지 않습니다.
6. [끝] 규칙 이력과 수집 범위를 확인한다
   - 주체: 보안 운영자
   - 데이터: 실행 상태 · 수집 상태 · 결과 없음
   - 해설: 미일치, 권한 부족, 수집 공백을 구별합니다.
- 시나리오: 일치 :: 쿼리 일치 경고와 조치 이력 확인
- 시나리오: 일치 없음 :: 결과 없음과 실행 오류를 구분

> 주의: 규칙당 각 실행에서 만들 수 있는 경고 수는 문서상 150개이며 동작·보존 기간은 최신 문서와 테넌트에서 [확인 필요: 기능별 이벤트·보고 필드, 필요한 감사 설정과 역할을 대상 테넌트의 Activity explorer·감사·경고에서 확인].
> 출처: https://learn.microsoft.com/en-us/defender-xdr/custom-detection-rules

### L3 · A · 결과 열과 권한 — 탐지 대상 자산 연결

#### L4 · 결과 열 검토 — 기기 매핑과 범위 확인

1. [시작] 운영자가 기기 이벤트 쿼리를 만든다
   - 주체: 보안 운영자
   - 데이터: DeviceEvents · KQL
   - 해설: 결과의 자산 식별자가 경고의 맥락에 영향을 줍니다.
2. [처리] DeviceId와 ReportId를 결과에서 확인한다
   - 주체: 보안 운영자
   - 데이터: DeviceId · ReportId · Timestamp
   - 해설: 공식 문서는 MDE 테이블에 기기 ID와 보고서 ID를 포함하도록 권장합니다.
3. [판단] 운영자가 규칙의 기기 범위를 관리할 수 있는가?
   - 주체: Defender XDR
   - 데이터: 관리 권한 · 대상 기기 범위
   - 해설: 전체 기기에 대한 권한이 없으면 전체 범위 규칙을 수정할 수 없습니다.
   - 가능 → 4
   - 불가 → 5
4. [끝] 영향 기기를 매핑하고 범위를 지정한다
   - 주체: 보안 운영자
   - 데이터: DeviceId · 규칙 범위
   - 해설: 정확한 자산과 사용 가능한 범위를 확인합니다.
5. [끝] 필요한 권한 또는 규칙 범위를 조정한다
   - 주체: 관리자
   - 데이터: 제품별 RBAC · 기기 범위
   - 해설: 조회 가능 여부와 규칙 관리 권한은 같지 않을 수 있습니다.
- 시나리오: 가능 :: 허용된 기기 범위에서 탐지 설정
- 시나리오: 불가 :: 기기 범위 관리 권한 부족 조사

> 출처: https://learn.microsoft.com/en-us/defender-xdr/custom-detection-rules
