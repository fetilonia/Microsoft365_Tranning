## L2 · AI 위협 보호 — AI 서비스 경고와 프롬프트 증거

- 설정(Control Plane): Azure 구독의 AI services 위협 보호 플랜 활성화 | 사용자 프롬프트 증거 옵션 검토
- 강제(Enforcement): 지원 AI 워크로드의 위협 신호 분석과 경고 | 경고가 프롬프트 차단을 뜻하지 않음
- 증적(Evidence): AI 보안 경고 · 증거 옵션에 따른 의심 프롬프트 및 모델 응답 조각
- 메뉴(Admin Center): Azure portal > Defender for Cloud > Environment settings > 구독 > Defender plans > AI services
- 라이선스(License): Defender for AI services 플랜의 과금·지원 리소스 및 역할 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 보호 범위 확인 → 플랜 구성 → 경고 조사

#### L4 · ⓪ 비활성 — AI 서비스 플랜이 꺼진 구독

1. [시작] 관리자가 AI 워크로드의 보안 범위를 확인한다
   - 주체: 관리자
   - 데이터: Azure 구독 · AI 리소스
   - 해설: 지원되는 AI 워크로드와 구독을 구별합니다.
2. [처리] AI services 플랜의 상태를 확인한다
   - 주체: 관리자
   - 위치: Defender for Cloud › Environment settings
   - 데이터: AI services 플랜
   - 해설: 이 예제는 해당 플랜이 꺼진 구독입니다.
3. [처리] 기존 AI 보안 통제를 확인한다
   - 주체: 관리자
   - 데이터: 애플리케이션 설정 · 다른 보호 계층
   - 해설: 플랜 미활성은 다른 보호 기능이 없다는 뜻이 아닙니다.
4. [끝] 위협 경고 범위의 공백을 기록한다
   - 주체: 관리자
   - 데이터: 구독 · 지원 리소스
   - 해설: 경고가 없다는 것을 안전성의 증거로 해석하지 않습니다.

#### L4 · ① 구성 — AI 서비스 위협 보호를 켠다

1. [시작] Azure 구독과 AI 리소스를 확인한다
   - 주체: 관리자
   - 위치: Azure portal › 구독 · AI 리소스
   - 데이터: 구독 · 리소스 유형 · 권한 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]
   - 해설: 지원되는 리소스와 적용 지역을 확인합니다.
2. [처리] Defender for Cloud 환경 설정을 연다
   - 주체: 관리자
   - 위치: Defender for Cloud › Environment settings › 구독
   - 데이터: Defender plans
   - 해설: 대상 구독의 플랜을 선택합니다.
3. [처리] AI services 플랜을 켠다
   - 주체: 관리자
   - 위치: Defender plans › AI services › On
   - 데이터: 플랜 상태 · 예상 비용
   - 해설: 위협 보호 플랜과 적용 범위를 확인합니다.
4. [처리] 프롬프트 증거 설정을 연다
   - 주체: 관리자
   - 위치: AI services › Settings › Enable user prompt evidence
   - 데이터: 증거 옵션 현재 상태
   - 해설: 프롬프트와 응답은 고객 데이터이므로 접근과 개인정보 처리를 검토합니다.
5. [처리] 조직 정책에 맞게 증거 옵션을 선택한다
   - 주체: 관리자
   - 위치: AI services › Settings › Enable user prompt evidence
   - 데이터: 증거 On 또는 Off
   - 해설: 옵션은 경고에 표시될 프롬프트 내용의 수준에 영향을 줍니다.
6. [끝] 저장하고 경고 조사 권한을 확인한다
   - 주체: 관리자
   - 위치: Defender for Cloud › Security alerts
   - 데이터: 플랜 · 증거 설정 · 조회 권한
   - 해설: 플랜 사용과 경고의 증거 열람 권한을 구분합니다.

#### L4 · ▶ ② 활성 — 의심 프롬프트의 경고 증거를 조사한다

1. [시작] 지원되는 AI 워크로드에서 의심 활동이 감지된다
   - 주체: Defender for Cloud
   - 데이터: AI 리소스 · 위협 신호
   - 해설: 이 예제는 탐지 조건을 충족해 경고가 발생한 경우입니다.
2. [처리] 보안 운영자가 AI 경고를 연다
   - 주체: 보안 운영자
   - 위치: Defender for Cloud › Security alerts
   - 데이터: 경고 · 리소스 · 발생 시각
   - 해설: 경고가 자동으로 요청을 차단했다는 뜻은 아닙니다.
3. [판단] 사용자 프롬프트 증거가 활성화되어 있는가?
   - 주체: Defender for Cloud
   - 데이터: Enable user prompt evidence 설정
   - 해설: 설정에 따라 경고에서 보이는 정보가 달라집니다.
   - 활성 → 4
   - 비활성 → 6
4. [처리] 의심 프롬프트 또는 응답 조각을 검토한다
   - 주체: 보안 운영자
   - 데이터: 경고 증거 · 자동으로 가려진 민감 데이터
   - 해설: 권한과 조직의 데이터 처리 정책을 지켜 조사합니다.
5. [끝] 경고와 관련 리소스의 대응을 기록한다
   - 주체: 보안 운영자
   - 데이터: 경고 ID · 리소스 · 조사 결론
   - 해설: 보이는 조각만으로 모든 사용자 의도를 단정하지 않습니다.
6. [끝] 마스킹된 내용과 다른 경고 맥락을 검토한다
   - 주체: 보안 운영자
   - 데이터: 내용이 마스킹된 경고 · 리소스 정보
   - 해설: 증거 옵션이 꺼져도 위협 탐지를 위한 분석은 계속됩니다.
- 시나리오: 활성 :: 의심 프롬프트 증거를 권한 범위에서 검토
- 시나리오: 비활성 :: 내용 마스킹 상태에서 경고 맥락 조사

> 주의: 지원 모델·리소스·리전, 경고 종류 및 증거 보관 정책은 [확인 필요: 기능별 이벤트·보고 필드, 필요한 감사 설정과 역할을 대상 테넌트의 Activity explorer·감사·경고에서 확인].
> 출처: https://learn.microsoft.com/en-us/azure/defender-for-cloud/ai-onboarding

### L3 · A · 프롬프트 증거 — 표시와 탐지 구분

#### L4 · 증거 옵션 비교 — 민감 데이터 접근 경계

1. [시작] 관리자가 AI 경고의 증거 옵션을 검토한다
   - 주체: 관리자
   - 데이터: 프롬프트 및 모델 응답
   - 해설: 증거에는 고객 데이터가 포함될 수 있습니다.
2. [처리] 구독의 증거 옵션을 확인한다
   - 주체: 관리자
   - 위치: AI services › Settings › Enable user prompt evidence
   - 데이터: 옵션 On 또는 Off
   - 해설: 조사에 필요한 정보와 데이터 보호를 함께 고려합니다.
3. [판단] 증거 옵션이 켜져 있는가?
   - 주체: Defender for Cloud
   - 데이터: 사용자 프롬프트 증거 설정
   - 해설: 탐지 자체와 경고에 표시되는 내용은 다릅니다.
   - 켜짐 → 4
   - 꺼짐 → 5
4. [끝] 의심 부분의 증거와 마스킹을 확인한다
   - 주체: 보안 운영자
   - 데이터: 의심 조각 · 민감 데이터 마스킹
   - 해설: 접근 권한과 데이터 처리 기준을 적용합니다.
5. [끝] 프롬프트 내용이 가려진 경고를 조사한다
   - 주체: 보안 운영자
   - 데이터: 마스킹된 경고 · 리소스 맥락
   - 해설: 경고 내용이 가려져도 위협 분석은 계속됩니다.
- 시나리오: 켜짐 :: 마스킹된 의심 프롬프트 증거 검토
- 시나리오: 꺼짐 :: 내용이 가려진 경고와 리소스 조사

> 출처: https://learn.microsoft.com/en-us/azure/defender-for-cloud/ai-onboarding
