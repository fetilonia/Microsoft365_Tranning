## L2 · Defender for Storage — 업로드 멀웨어 검사

- 설정(Control Plane): Storage 플랜과 업로드 시 멀웨어 검사 활성화 | 월별 검사 한도와 제외 필터 검토
- 강제(Enforcement): 지원되는 Blob 업로드·수정 시 서비스 측 멀웨어 검사
- 증적(Evidence): 검사 결과 · Blob 인덱스 태그 · 악성 파일의 보안 경고
- 메뉴(Admin Center): Azure portal > Defender for Cloud > Environment settings > Defender plans > Storage [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
- 라이선스(License): Defender for Storage 유료 플랜 및 검사량 기반 비용·한도 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 검사 미활성 → 설정 → 업로드 결과

#### L4 · ⓪ 비활성 — 업로드 검사가 꺼진 스토리지

1. [시작] 사용자가 스토리지 계정에 Blob을 업로드한다
   - 주체: 사용자
   - 데이터: 스토리지 계정 · Blob
   - 해설: 업로드한 데이터의 멀웨어 검사 여부를 확인합니다.
2. [처리] 관리자가 Storage 플랜과 검사 설정을 확인한다
   - 주체: 관리자
   - 위치: Defender for Cloud › Environment settings
   - 데이터: Storage 플랜 · on-upload 검사 상태
   - 해설: 이 예제는 업로드 검사가 꺼져 있습니다.
3. [처리] 해당 Blob의 검사 결과를 조회한다
   - 주체: 관리자
   - 데이터: 검사 결과 유무
   - 해설: 검사를 실행하지 않은 파일은 검사 결과가 없을 수 있습니다.
4. [끝] 미검사와 무해 판정을 구분한다
   - 주체: 관리자
   - 데이터: Blob · 검사 설정
   - 해설: 검사 결과가 없다는 것은 악성이 없다는 증명이 아닙니다.

#### L4 · ① 구성 — 업로드 검사와 비용 한도를 정한다

1. [시작] 대상 구독과 스토리지 계정을 확인한다
   - 주체: 관리자
   - 위치: Azure portal › 구독 · 스토리지 계정
   - 데이터: 계정 · 리소스 범위 · 권한 [확인 필요: 대상 테넌트에서 해당 데이터 필드·수집 조건·정책 결과를 기록 또는 보고서와 대조]
   - 해설: 보호 범위와 비용을 함께 검토합니다.
2. [처리] Storage 플랜 설정을 연다
   - 주체: 관리자
   - 위치: Defender for Cloud › Environment settings › 구독 › Storage
   - 데이터: 플랜 상태
   - 해설: 대상 구독 또는 스토리지 계정의 적용을 확인합니다.
3. [처리] 업로드 시 멀웨어 검사를 켠다
   - 주체: 관리자
   - 위치: Storage › Malware scanning › On-upload scanning [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 검사 활성 상태
   - 해설: 지원 Blob의 업로드 또는 수정 시 검사합니다.
4. [처리] 월별 검사 한도를 검토한다
   - 주체: 관리자
   - 위치: Malware scanning › 검사량 한도 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 스토리지 계정별 월간 GB 한도
   - 해설: 한도에 도달하면 해당 월의 이후 파일은 검사되지 않을 수 있습니다.
5. [처리] 제외 필터와 결과 전달을 검토한다
   - 주체: 관리자
   - 위치: Malware scanning › 필터 · 결과 설정 [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 제외 조건 · 결과 경로
   - 해설: 제외 조건은 검사 공백이 될 수 있으므로 명시적으로 검토합니다.
6. [끝] 스캔 인프라와 계정 상태를 확인한다
   - 주체: 관리자
   - 위치: 스토리지 계정 › Event Grid 시스템 토픽 · ID [확인 필요: 현재 포털 메뉴명과 기능별 경로를 대상 테넌트에서 확인하고 최신 Microsoft Learn 절차와 대조]
   - 데이터: 시스템 토픽 · 관리 ID
   - 해설: 시스템 토픽을 제거하면 업로드 검사가 작동하지 않습니다.

#### L4 · ▶ ② 활성 — Blob 업로드와 검사 결과를 확인한다

1. [시작] 지원되는 Blob이 업로드되거나 수정된다
   - 주체: 사용자
   - 데이터: Blob · 스토리지 계정
   - 해설: 설정된 업로드 검사가 해당 이벤트를 처리합니다.
2. [처리] 검사 서비스가 대상 Blob을 평가한다
   - 주체: Defender for Storage
   - 데이터: Blob 콘텐츠 · 검사 조건
   - 해설: 지원 형식과 크기, 검사 제한이 적용됩니다.
3. [처리] 검사 결과를 Blob과 연결한다
   - 주체: Defender for Storage
   - 데이터: 스캔한 Blob · 검사 결과
   - 해설: 업로드한 파일과 실제 검사 결과를 대조합니다.
4. [판단] 검사 결과가 악성으로 판정되었는가?
   - 주체: Defender for Storage
   - 데이터: 검사 결과
   - 해설: 이 분기는 검사가 완료된 파일만 비교합니다.
   - 악성 → 5
   - 악성 아님 → 6
5. [끝] 보안 경고와 결과를 확인한다
   - 주체: 보안 운영자
   - 위치: Defender for Cloud › Security alerts · Blob 결과
   - 데이터: 악성 판정 · 경고 · Blob
   - 해설: 후속 격리 또는 삭제는 별도로 구성된 동작을 확인합니다.
6. [끝] 검사 결과와 태그를 검토한다
   - 주체: 보안 운영자
   - 데이터: 검사 결과 · Blob 인덱스 태그
   - 해설: 정상 결과라도 이후 변경된 Blob의 검사 상태를 확인해야 합니다.
- 시나리오: 악성 :: 검사 완료 후 악성 경고 확인
- 시나리오: 악성 아님 :: 검사 완료 결과와 Blob 태그 확인

> 주의: 암호화·크기·처리량·한도·타임아웃으로 검사되지 않은 파일은 무해 결과와 다르다. 지원 및 결과 전달 설정은 [확인 필요: 기능·플랫폼·정책 모드별 동작을 최신 Microsoft Learn 및 격리된 테스트 테넌트에서 재현해 확인].

### L3 · A · 검사 공백 — 월간 한도와 결과

#### L4 · 검사 한도 도달 — 미검사 파일을 식별한다

1. [시작] 관리자가 스토리지 계정의 월간 검사량을 확인한다
   - 주체: 관리자
   - 데이터: 계정별 월간 사용량 · 검사 한도
   - 해설: 한도는 검사 비용 제어를 위한 설정입니다.
2. [처리] 새 Blob이 업로드된다
   - 주체: 사용자
   - 데이터: 업로드 시각 · Blob 크기
   - 해설: 검사 여부는 설정과 한도에 영향을 받습니다.
3. [판단] 계정의 월간 검사 한도에 도달했는가?
   - 주체: Defender for Storage
   - 데이터: 월간 검사량 · 상한
   - 해설: 한도 도달 후 해당 월의 스캔이 중단됩니다.
   - 미도달 → 4
   - 도달 → 5
4. [끝] 검사 결과를 확인한다
   - 주체: 보안 운영자
   - 데이터: 검사 상태 · Blob 결과
   - 해설: 한도 미도달만으로 검사가 성공했다고 단정하지 않습니다.
5. [끝] 이후 파일의 검사 공백을 기록한다
   - 주체: 보안 운영자
   - 데이터: 한도 도달 시각 · 미검사 Blob
   - 해설: 한도는 월말 UTC 자정에 초기화되며 적용에는 차이가 있을 수 있습니다.
- 시나리오: 미도달 :: 한도 내 파일의 실제 검사 결과 확인
- 시나리오: 도달 :: 월간 한도 이후 미검사 공백 확인
