## L2 · 민감도 레이블 — 게시 · 적용 · 우선순위

- 설정(Control Plane): 민감도 레이블의 범위·보호 설정 | 사용자·그룹 대상 레이블 게시 정책 | 별도의 자동 레이블 정책
- 강제(Enforcement): 지원 앱에서 게시된 레이블 선택·적용 | 지원 위치에서 자동 레이블 정책 평가 [확인 필요: 앱·위치별 지원]
- 증적(Evidence): 문서에 적용된 레이블 | Activity explorer 및 감사 기록 [확인 필요: 위치별 이벤트와 지연]
- 메뉴(Admin Center): Information Protection > Sensitivity labels | Label policies
- 라이선스(License): 수동·자동 레이블과 기능별 라이선스 요건이 다름 [확인 필요: 고객 SKU 및 적용 범위]

### L3 · 0 · 기능 상태 전이 — 게시 전 → 게시 정책 구성 → 앱에서 적용

#### L4 · ⓪ 비활성 — 새 레이블을 아직 게시하지 않음

1. [시작] 관리자가 분류 체계 설계
   - 주체: 관리자
   - 위치: 조직의 정보 보호 기준
   - 데이터: 교육용 레이블 이름과 사용 목적
   - 해설: 사용자가 문서에서 알아볼 분류 이름을 정합니다.
2. [처리] 새 레이블을 게시 정책에 아직 추가하지 않음
   - 주체: 관리자
   - 데이터: 이 예제에서 게시되지 않은 신규 레이블
   - 해설: 레이블 정의를 만들더라도 게시하지 않으면 앱에서 선택할 수 없습니다.
3. [처리] 기존 레이블과 정책 확인
   - 주체: 관리자
   - 위치: Information Protection › Sensitivity labels 및 Label policies
   - 데이터: 기존 정의와 적용 대상
   - 해설: 이 새 레이블이 미게시라고 다른 레이블이 모두 없는 것은 아닙니다.
4. [끝] 게시 전에는 새 레이블을 수동 선택할 수 없음
   - 주체: 사용자
   - 위치: 지원 Office 앱의 민감도 메뉴
   - 데이터: 현재 사용자에게 게시된 레이블
   - 해설: 대상과 지원 앱을 확인하고 게시 정책을 만듭니다.

#### L4 · ① 구성 — 레이블을 만들고 사용자에게 게시

1. [시작] 관리자 역할과 라이선스 확인
   - 주체: 관리자
   - 위치: Microsoft Purview portal › 역할 및 Information Protection
   - 데이터: 레이블 관리 권한과 대상 사용자의 구독
   - 해설: 관리 권한과 사용자 라이선스를 각각 확인합니다.
2. [처리] 민감도 레이블 화면 열기
   - 주체: 관리자
   - 위치: Solutions › Information Protection › Sensitivity labels
   - 데이터: 기존 레이블 목록과 클래식 또는 현대적 레이블 체계
   - 해설: 테넌트의 레이블 체계에 따라 만들기 화면이 다를 수 있습니다.
3. [처리] 새 레이블 만들기
   - 주체: 관리자
   - 위치: Sensitivity labels › Create label 또는 Create › Label
   - 데이터: 이름·표시 이름·사용자 설명
   - 해설: 사용자가 레이블 의미를 구별할 수 있도록 설명합니다.
4. [처리] 파일 및 데이터 자산 범위 선택
   - 주체: 관리자
   - 위치: 레이블 만들기 › Define the scope for this label
   - 데이터: Files & other data assets 범위
   - 해설: 범위는 구성할 수 있는 설정과 게시 후 표시되는 위치에 영향을 줍니다.
5. [처리] 보호 설정과 레이블 순서 검토
   - 주체: 관리자
   - 위치: 레이블 설정 및 Sensitivity labels 순서
   - 데이터: 표시·암호화 설정 및 우선순위
   - 해설: 필요한 설정만 선택하고 다른 레이블과의 순서를 확인합니다.
6. [처리] 레이블을 게시 정책에 추가
   - 주체: 관리자
   - 위치: Information Protection › Label policies › Publish labels
   - 데이터: 정책의 레이블 목록과 사용자·그룹 대상
   - 해설: 레이블 정의와 사용자에게 제공하는 게시 정책은 별개입니다.
7. [끝] 정책 배포 후 대상 사용자의 앱 확인
   - 주체: 관리자
   - 위치: 지원 Office 앱 › Sensitivity
   - 데이터: 게시 정책의 배포 상태와 표시 목록
   - 해설: 배포에는 시간이 걸리므로 즉시 표시되지 않으면 대상과 배포 상태를 확인합니다.

#### L4 · ② 활성 — 게시 대상 사용자가 문서에 레이블 적용

1. [시작] 사용자가 지원 앱에서 문서 열기
   - 주체: 사용자
   - 위치: 지원 Office 앱
   - 데이터: 교육용 문서와 로그인한 사용자
   - 해설: 실제 파일과 앱이 레이블 기능을 지원하는지 확인합니다.
2. [처리] 앱이 사용자의 게시 정책을 사용
   - 주체: Office 앱
   - 위치: 사용자에게 적용된 레이블 정책
   - 데이터: 정책 대상·레이블 목록·앱의 정책 갱신 상태
   - 해설: 정책에 게시된 레이블이 사용자에게 제공됩니다.
3. [판단] 사용자가 이 레이블의 게시 대상인가?
   - 주체: Office 앱
   - 위치: 레이블 게시 정책의 사용자·그룹
   - 데이터: 사용자 대상과 배포 상태
   - 해설: 대상에서 제외된 사용자는 이 정책을 통해 새 레이블을 받지 않습니다.
   - 예 → 4
   - 아니오 → 6
4. [처리] 사용자가 레이블 선택 후 문서 저장
   - 주체: 사용자
   - 위치: Office 앱 › Sensitivity › 게시된 레이블
   - 데이터: 문서에 적용된 레이블과 설정
   - 해설: 게시된 레이블을 선택하면 그 설정이 문서에 적용됩니다.
5. [끝] 적용된 레이블 확인
   - 주체: 사용자
   - 위치: Office 앱 문서 상태 및 Sensitivity 메뉴
   - 데이터: 저장된 문서의 레이블
   - 해설: 암호화나 표시가 구성된 경우 지원 앱에서 해당 보호가 적용됩니다.
6. [끝] 정책 대상·지원 앱·배포 상태 확인
   - 주체: 관리자
   - 위치: Label policies 및 사용자의 앱
   - 데이터: 게시 대상과 레이블 범위
   - 해설: 새 레이블이 목록에 없으면 배포와 범위를 확인하며 기존 문서의 레이블 제거로 해석하지 않습니다.
- 시나리오: 예 :: 게시 대상이 문서에 레이블 적용
- 시나리오: 아니오 :: 게시 대상이 아니라 새 레이블이 목록에 없음

> 교육 포인트: 레이블 생성, 사용자 게시, 문서 적용은 서로 다른 단계입니다.
> 주의: 정책에서 레이블을 제거해도 이미 적용된 문서의 레이블이 제거되는 것은 아닙니다.

### L3 · A · 게시 대상과 적용 상태

#### L4 · 게시 정책의 대상 비교 — 같은 레이블을 서로 다른 사용자에게 시험

1. [시작] 관리자가 가상 사용자 두 명 준비
   - 주체: 관리자
   - 위치: 레이블 정책 대상 설계
   - 데이터: 게시 그룹에 포함된 사용자와 포함되지 않은 사용자
   - 해설: 앱과 문서는 같게 두고 게시 대상만 바꿉니다.
2. [처리] 파일 범위가 포함된 레이블을 정책에 게시
   - 주체: 관리자
   - 위치: Information Protection › Label policies
   - 데이터: 레이블·그룹 대상·정책 배포 상태
   - 해설: 사용자별 목록은 게시 대상과 정책 갱신에 영향을 받습니다.
3. [처리] 각 사용자가 지원 앱에서 문서 열기
   - 주체: 사용자
   - 위치: 지원 Office 앱 › Sensitivity
   - 데이터: 로그인 계정과 앱의 게시 레이블 목록
   - 해설: 정책이 반영된 후 두 계정의 목록을 비교합니다.
4. [판단] 해당 게시 정책이 사용자에게 적용되는가?
   - 주체: Office 앱
   - 위치: 게시 정책 대상
   - 데이터: 그룹 멤버십과 게시 정책
   - 해설: 다른 게시 정책이 같은 레이블을 제공하는지까지 함께 확인합니다.
   - 대상 → 5
   - 대상 아님 → 6
5. [끝] 대상 사용자는 게시된 레이블 선택
   - 주체: 사용자
   - 위치: Office 앱 › Sensitivity
   - 데이터: 저장된 문서의 선택 레이블
   - 해설: 사용자는 문서에 레이블을 적용할 수 있습니다.
6. [끝] 이 정책을 통해서는 레이블이 제공되지 않음
   - 주체: 관리자
   - 위치: Label policies › 정책 대상
   - 데이터: 제외된 사용자와 다른 정책의 게시 여부
   - 해설: 이 예제에서는 다른 정책도 해당 레이블을 게시하지 않는다고 가정합니다.
- 시나리오: 대상 :: 게시 대상은 레이블을 선택해 문서에 적용
- 시나리오: 대상 아님 :: 게시 대상이 아니면 이 정책으로는 제공되지 않음

> 교육 포인트: 게시 대상에서 제외해도 문서에 이미 적용된 레이블이 자동 제거되지는 않습니다.
> 주의: 자동 레이블은 별도 정책과 조건을 검증해야 하며 수동 게시 대상 비교와 동일하게 가정하지 않습니다. 기존 레이블과 자동 적용의 교체 조건 [확인 필요: 위치·적용 방식별 동작].
