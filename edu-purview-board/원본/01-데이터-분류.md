## L2 · 데이터 분류 — SIT · 학습 가능한 분류자

- 설정(Control Plane): 민감 정보 유형(SIT) 선택·테스트 | 학습 가능한 분류자와 사용자 지정 SIT [확인 필요: 유형별 설정 권한]
- 강제(Enforcement): 지원 서비스가 콘텐츠를 분류 | 탐지 결과를 DLP 등 별도 정책이 활용하며 분류만으로 차단하지 않음
- 증적(Evidence): SIT 테스트 일치 결과 | Content explorer의 분류 항목·위치·내용(권한별)
- 메뉴(Admin Center): Information Protection > Classifiers > Sensitive info types | Content explorer: Data Lifecycle Management > Explorers > Content explorer
- 라이선스(License): 기능·위치·탐색기별 구독 요건과 대상 사용자 라이선스 [확인 필요: 고객 SKU 및 최신 서비스 설명]

### L3 · 0 · 기능 상태 전이 — 기준 선정 전 → SIT 테스트 → 분류 결과 확인

#### L4 · ⓪ 비활성 — 민감 정보 유형을 정책에 사용하기 전

1. [시작] 관리자가 보호하려는 데이터 식별
   - 주체: 관리자
   - 위치: 조직의 데이터 보호 설계
   - 데이터: 교육용 가상 데이터의 형식과 보호 목표
   - 해설: 어떤 콘텐츠를 구분할지 먼저 정합니다.
2. [처리] 정책에 사용할 SIT를 아직 선정하지 않음
   - 주체: 관리자
   - 데이터: 정책의 분류 조건 없음
   - 해설: 이 예제에서는 해당 SIT 조건을 사용하는 정책을 아직 만들지 않았습니다.
3. [처리] 서비스의 기존 분류와 다른 정책을 별도로 확인
   - 주체: 관리자
   - 데이터: 기존 분류 결과와 정책 범위
   - 해설: 새 정책이 없다고 기본 제공 분류나 기존 보호가 모두 꺼진 것은 아닙니다.
4. [끝] 탐지와 차단 기준을 확정하지 못함
   - 주체: 관리자
   - 데이터: 검증할 SIT와 테스트 샘플 목록
   - 해설: 분류 기준을 정하고 테스트한 다음 실제 보호 정책에 연결합니다.

#### L4 · ① 구성 — SIT를 선택하고 가상 문서로 테스트

1. [시작] 테스트 권한 확인
   - 주체: 관리자
   - 위치: Microsoft Purview 역할 그룹 및 Exchange 역할 할당
   - 데이터: SIT 테스트에는 Purview 역할 그룹과 Exchange 역할 또는 역할 그룹이 각각 필요
   - 해설: 두 권한 영역의 조건을 공식 문서와 대조합니다.
2. [처리] 암호화되지 않은 양성·음성 문서 준비
   - 주체: 관리자
   - 위치: 테스트용 문서 저장 위치
   - 데이터: 가상 데이터가 포함된 일치 샘플과 일치하지 않는 샘플
   - 해설: 실제 개인정보를 업로드하지 않고 두 결과를 비교합니다.
3. [처리] 민감 정보 유형 목록 열기
   - 주체: 관리자
   - 위치: Microsoft Purview portal › Information Protection › Classifiers › Sensitive info types
   - 데이터: 기본 제공 또는 사용자 지정 SIT 목록
   - 해설: 보호하려는 데이터와 맞는 유형을 선택합니다.
4. [처리] 유형의 세부 화면에서 Test 선택
   - 주체: 관리자
   - 위치: Sensitive info types › 선택한 유형 › Test
   - 데이터: 선택한 SIT의 탐지 정의
   - 해설: 유형을 선택한 뒤 별도의 파일 테스트를 시작합니다.
5. [처리] 첫 번째 파일을 업로드하고 테스트
   - 주체: 관리자
   - 위치: Test › 파일 업로드 › Test
   - 데이터: 암호화되지 않은 샘플 한 개
   - 해설: 한 번에 파일 하나만 테스트합니다.
6. [처리] Match results를 검토하고 다른 샘플 반복
   - 주체: 관리자
   - 위치: Match results › Finish › Test
   - 데이터: 두 샘플의 일치 결과와 예상 결과
   - 해설: 일치와 불일치가 설계 의도에 맞는지 비교합니다.
7. [끝] 결과를 검토해 정책 설계에 반영
   - 주체: 관리자
   - 위치: SIT 테스트 결과 및 정책 설계 기록
   - 데이터: 선택한 유형·테스트 결과·검토 내용
   - 해설: 테스트는 분류 유형 검증이며 DLP나 자동 레이블 정책을 만들지 않습니다.

#### L4 · ② 활성 — 분류된 항목을 Content explorer에서 조사

1. [시작] 지원 위치에 분류할 문서가 존재
   - 주체: 사용자
   - 위치: SharePoint 또는 OneDrive
   - 데이터: 교육용 문서와 해당 위치
   - 해설: 지원 범위와 분류 전제조건을 먼저 확인합니다.
2. [처리] 서비스가 콘텐츠를 분류
   - 주체: Microsoft 365
   - 위치: 지원되는 콘텐츠 검사 경로
   - 데이터: 문서의 분류 결과와 일치한 SIT
   - 해설: 실제 분류 결과가 탐색기의 스냅샷에 반영됩니다.
3. [처리] Content explorer 열기
   - 주체: 관리자
   - 위치: Microsoft Purview portal › Solutions › Data Lifecycle Management › Explorers › Content explorer
   - 데이터: 분류 항목·위치의 현재 스냅샷
   - 해설: 탭에 들어갈 수 있는 권한과 항목 자체를 볼 권한은 다릅니다.
4. [처리] SIT 이름과 위치로 결과 좁히기
   - 주체: 관리자
   - 위치: Content explorer › SIT 필터 › All locations
   - 데이터: SIT와 선택한 위치의 항목 목록
   - 해설: 분류 유형과 위치로 항목을 탐색합니다.
5. [판단] 항목 내용을 볼 권한이 있는가?
   - 주체: Content explorer
   - 위치: Purview 역할 그룹 할당
   - 데이터: Content Explorer List viewer 및 Content viewer 권한
   - 해설: 목록·내용 권한은 별도이며 관리 단위 범위도 영향을 줄 수 있습니다.
   - 예 → 6
   - 아니오 → 7
6. [끝] 허용된 항목의 내용을 열어 검토
   - 주체: 관리자
   - 위치: Content explorer › 선택한 항목
   - 데이터: 항목 내용과 분류 결과
   - 해설: 암호화된 문서는 미리보기와 다운로드가 제한됩니다.
7. [끝] 내용 대신 권한과 범위 확인
   - 주체: 관리자
   - 위치: Purview 역할 그룹 및 관리 단위
   - 데이터: 역할 할당·검색 위치·분류 반영 시점
   - 해설: 조회 권한이 없거나 항목이 아직 반영되지 않았다면 결과 부재가 탐지 실패를 뜻하지는 않습니다.
- 시나리오: 예 :: 내용 권한을 가진 조사자가 분류 항목 검토
- 시나리오: 아니오 :: 내용 권한이 없어 역할과 반영 범위 점검

> 교육 포인트: 분류는 발견 신호이며, 차단은 별도 정책의 위치·조건·동작에 달려 있습니다.
> 주의: Content explorer 집계는 최대 7일, SharePoint 파일은 최대 14일이 걸릴 수 있습니다. SIT 정의 변경만으로 변경되지 않은 과거 파일이 자동 재분류되지는 않습니다.

### L3 · A · SIT 일치 판단

#### L4 · SIT 테스트와 결과 비교 — 같은 유형에 일치·불일치 샘플을 넣는다

1. [시작] 민감 정보 유형과 비교할 샘플 선정
   - 주체: 관리자
   - 위치: Information Protection › Classifiers › Sensitive info types
   - 데이터: 동일한 SIT와 암호화되지 않은 테스트 문서
   - 해설: 분류 기준을 하나로 고정해야 두 샘플의 결과를 비교할 수 있습니다.
2. [처리] Test에서 문서 하나를 업로드
   - 주체: 관리자
   - 위치: 선택한 SIT › Test
   - 데이터: 일치 예상 또는 불일치 예상 문서
   - 해설: 파일 테스트는 기존 SharePoint 파일의 재분류나 정책 시뮬레이션과 별개입니다.
3. [처리] 선택한 SIT의 패턴과 보조 요소 평가
   - 주체: 분류 서비스
   - 위치: SIT 테스트
   - 데이터: 패턴·키워드 등 선택한 유형의 정의와 테스트 파일 내용
   - 해설: 각 SIT의 구성과 신뢰도 정의에 따라 일치 여부가 달라집니다.
4. [판단] 테스트 파일이 SIT 정의에 일치하는가?
   - 주체: 분류 서비스
   - 위치: Match results
   - 데이터: 해당 파일의 일치 결과
   - 해설: 비교할 샘플의 예상과 실제 판정을 대조합니다.
   - 일치 → 5
   - 불일치 → 6
5. [처리] 일치 결과와 예상 조건 확인
   - 주체: 관리자
   - 위치: Match results
   - 데이터: 일치 표시와 테스트한 유형
   - 해설: 예상한 양성 샘플이 일치했다면 탐지 조건을 검토한 뒤 다른 샘플도 시험합니다.
   - 다음 → 7
6. [처리] 불일치 결과와 샘플·정의 확인
   - 주체: 관리자
   - 위치: Match results 및 SIT 정의
   - 데이터: 일치하지 않은 샘플과 정의의 요소
   - 해설: 예상한 음성 샘플이면 정상 결과이며 양성 샘플이었다면 조건을 조사합니다.
   - 다음 → 7
7. [끝] Finish 후 다른 파일을 별도로 시험
   - 주체: 관리자
   - 위치: Match results › Finish › Test
   - 데이터: 일치·불일치 파일의 비교 기록
   - 해설: 테스트 성공은 기존 파일의 재분류나 DLP 차단이 수행됐다는 뜻이 아닙니다.
- 시나리오: 일치 :: 조건에 맞는 샘플이 SIT에 일치
- 시나리오: 불일치 :: 조건에 맞지 않는 샘플이 탐지되지 않음

> 교육 포인트: SIT 테스트 결과와 실제 데이터의 분류·정책 결과를 구별합니다.
> 주의: 암호화 파일은 이 업로드 테스트에서 지원되지 않습니다. 학습 가능한 분류자는 SIT와 다른 방식이므로 별도 검증이 필요합니다.
