   - 해설: 일치와 불일치가 설계 의도에 맞는지 비교합니다.

#### L4 · 민감 정보 유형(SIT) — 패턴 기반 탐지와 기본 제공·사용자 지정 경로

1. [시작] 패턴으로 식별할 민감 정보의 예시를 정리
   - 주체: 정보 보호 관리자

   - 해설: 패턴 기반 SIT는 숫자·키워드 등 정의한 패턴에 맞는 콘텐츠를 찾습니다.
2. [판단] 기본 제공 SIT가 요구한 탐지 범위에 맞는가?
   - 주체: 관리자
   - 위치: Sensitive info types 목록과 요구사항 검토
   - 데이터: Microsoft 제공 SIT와 조직의 탐지 기준
   - 해설: 기본 제공 유형으로 충분하면 이를 선택하고, 기준을 직접 정의해야 하면 사용자 지정 경로를 택합니다.
   - 기본 제공으로 충분 → 3
   - 사용자 지정 필요 → 4
3. [처리] 기본 제공 SIT를 선택하고 정의를 검토
   - 주체: 관리자
   - 위치: Information Protection › Classifiers › Sensitive info types
   - 데이터: 선택한 기본 제공 SIT와 해당 설명
   - 해설: 기본 제공 SIT는 편집할 수 없으며, 필요하면 복사해 사용자 지정 유형의 바탕으로 삼을 수 있습니다.
   - 다음 → 5
4. [처리] 사용자 지정 SIT의 패턴을 정의
   - 주체: 관리자
   - 위치: 사용자 지정 Sensitive information type 구성
   - 데이터: 기본 요소, 보조 요소, 신뢰도 수준, 근접성
   - 해설: 정의 방식은 탐지 목적에 맞춰 선택하며, 이 요소들은 패턴 일치의 근거를 설명합니다.
   - 다음 → 5
5. [처리] 안전한 샘플 파일 하나를 사용해 SIT를 테스트
   - 주체: 관리자
   - 위치: 선택한 SIT › Test
   - 데이터: 암호화되지 않은 양성 또는 음성 샘플 한 개
   - 해설: 테스트 결과는 해당 샘플이 유형 정의에 일치하는지 보여 주며, 기존 파일 재분류나 정책 실행을 의미하지 않습니다.
6. [끝] 예상과 일치 결과를 대조해 분류 기준을 검토
   - 주체: 관리자
   - 위치: Match results 및 SIT 정의
   - 데이터: 테스트 파일의 예상 결과와 실제 결과
   - 해설: 실제 보호 동작은 이후 연결하는 정책과 적용 위치를 별도로 검증합니다.
- 시나리오: 기본 제공으로 충분 :: 기본 제공 SIT를 선택해 샘플을 시험

#### L4 · Exact Data Match(EDM) — 구조화된 참조 데이터의 정확한 값 비교

1. [시작] 패턴만으로 구별하기 어려운 구조화된 민감 데이터셋을 선정
   - 주체: 정보 보호 관리자
   - 위치: Information Protection › Classifiers
   - 데이터: 가상 레코드 필드와 식별할 값
   - 해설: EDM은 조직이 제공한 기준 데이터의 정확한 값과 콘텐츠를 비교하는 사용자 지정 SIT 경로입니다.
2. [처리] 데이터 저장소 스키마와 기본 필드를 설계
   - 주체: 관리자
   - 위치: EDM 스키마 및 rule package 설계
   - 데이터: 필드 이름, 기본 요소가 연결될 기존 SIT, 보조 요소
   - 해설: 기본 요소는 콘텐츠에서 찾을 수 있는 기존 SIT 패턴과 연결해야 합니다.
3. [판단] 보조 필드에 여러 단어로 된 값이 있어 다중 토큰 일치가 필요한가?
   - 주체: 관리자
   - 위치: EDM 스키마의 보조 필드 설정
   - 데이터: 이름·주소 등 다중 토큰일 수 있는 보조 값
   - 해설: 다중 토큰 옵션은 여러 단어로 된 보조 데이터 필드의 일치를 지원합니다.
   - 다중 토큰 필드 존재 → 4
   - 다중 토큰 필드 없음 → 5
4. [처리] 해당 보조 필드에 다중 토큰 일치 설정
   - 주체: 관리자
   - 위치: EDM 스키마
   - 데이터: 여러 토큰으로 비교할 보조 필드
   - 해설: 선택한 필드가 다중 토큰 방식의 적용 대상이 되도록 스키마에 표시합니다.
   - 다음 → 6
5. [처리] 다중 토큰 설정 없이 필드 일치 기준을 유지
   - 주체: 관리자
   - 위치: EDM 스키마
   - 데이터: 설정한 기본·보조 필드
   - 해설: 다중 토큰 값이 필요하지 않으면 해당 옵션을 추가하지 않습니다.
   - 다음 → 6
6. [처리] 기준 데이터와 스키마를 보호해 EDM에 준비
   - 주체: 관리자
   - 위치: EDM 데이터 업로드 및 스키마 등록
   - 데이터: 조직의 기준 테이블, salt를 적용해 해시된 값
   - 해설: 서비스에 업로드되는 값의 보호 방법과 테넌트 설정은 배포 전에 검토합니다.
7. [처리] EDM 기반 사용자 지정 SIT의 rule package 구성
   - 주체: 관리자
   - 위치: EDM SIT 구성
   - 데이터: 기본 일치 요소, 보조 요소, 신뢰도와 근접성
   - 해설: EDM은 기본 값과 보조 증거를 함께 평가해 정확한 데이터 매치를 구성합니다.
8. [처리] 별도 테스트 샘플로 EDM SIT의 일치 결과 검증
   - 주체: 관리자
   - 위치: 선택한 EDM SIT › Test
   - 데이터: 가상 기준 레코드와 일치·불일치 문서
   - 해설: 양성·음성 결과를 확인한 뒤 필요한 정책 조건에 연결합니다.
9. [끝] 검증된 EDM SIT를 지원 정책의 조건으로 사용
   - 주체: 관리자
   - 위치: Microsoft Purview Data Loss Prevention 정책
   - 데이터: 승인된 EDM SIT와 정책 범위
   - 해설: 분류기 자체가 콘텐츠를 차단하지 않으며 정책의 조건과 동작이 보호 결과를 결정합니다.
- 시나리오: 다중 토큰 필드 존재 :: 여러 단어 보조 값을 EDM 스키마에서 비교
- 시나리오: 다중 토큰 필드 없음 :: 구성한 단일 필드 기준으로 EDM 매치

> 시나리오 교육 예시: 기준 데이터는 가상 값이며, 실제 민감 정보는 이 설명에 포함하지 않습니다.

#### L4 · 문서 지문 — 표준 양식에서 SIT를 만들고 부분·정확 일치 구성

   - 주체: 정보 보호 관리자
   - 위치: Information Protection › Classifiers
   - 데이터: 텍스트 기반 표준 양식과 보호 목적
   - 해설: 문서 지문은 제공한 양식을 바탕으로 그 템플릿의 변형 문서를 찾는 SIT를 만듭니다.

   - 해설: 원본 파일이 아니라 고유한 텍스트 패턴을 나타내는 지문이 생성됩니다.

   - 데이터: 업무상 필요한 문서 유사도와 일치 범위
   - 해설: 정확 일치와 부분 일치 중 목적에 맞는 방식을 선택합니다.

   - 데이터: 원본 지문과 동일한 텍스트
   - 해설: 작은 텍스트 차이가 있어도 정확 일치로 탐지되지 않을 수 있습니다.

   - 주체: 관리자

   - 데이터: 문서 텍스트의 30%~90% 범위와 신뢰도 수준
   - 해설: 요구하는 일치 비율을 선택하고 오탐·미탐 영향을 검토합니다.

   - 해설: 지원 위치와 기기 설정 요건을 정책 배포 전에 확인합니다.

   - 주체: 관리자
   - 위치: Fingerprint SIT 테스트 및 정책 검토
   - 데이터: 가상으로 채운 양식과 테스트 결과
   - 해설: 비밀번호 보호, 이미지 전용, 원본 텍스트 누락, 4MB 초과 문서 등의 제한을 확인합니다.
