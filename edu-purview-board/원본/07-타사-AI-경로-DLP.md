## L2 · 타사 AI 경로 DLP — 기기 · 브라우저 · 네트워크

- 설정(Control Plane): 기기 온보딩과 Endpoint DLP 규칙 | 브라우저 또는 네트워크 데이터 보안은 별도 구성
- 강제(Enforcement): 지원 Windows 기기의 AI 사이트 붙여넣기·업로드 통제 | 별도 통합 경로는 해당 정책에 따름
- 증적(Evidence): AI 활동의 Activity explorer·감사 | DLP 경고 [확인 필요: 경로별 이벤트와 표시 필드]
- 메뉴(Admin Center): Data loss prevention > Policies | Data Security Posture Management > AI activities [확인 필요: 포털 메뉴]
- 라이선스(License): 타사 AI 상호작용 관리의 종량제 활성화 필요 | 기능·공급자별 구독 및 추가 과금 [확인 필요: 고객 계약]

### L3 · 0 · 기능 상태 전이 — 기기 미준비 → 정책 구성 → AI 사이트 전송 평가

#### L4 · ⓪ 비활성 — 예제 기기 통제 미구성

1. [시작] 관리자가 AI 사이트 사용 경로 파악
   - 주체: 관리자
   - 데이터: 사용 브라우저·기기·사이트
   - 해설: 타사 AI의 여러 전송 경로를 구분합니다.
2. [처리] 예제 기기의 Endpoint DLP 정책은 아직 구성하지 않음
   - 주체: 관리자
   - 데이터: 온보딩 및 정책 적용 상태
   - 해설: 이 예제는 새 기기 정책의 도입 전입니다.
3. [처리] 별도 브라우저·네트워크 보호 확인
   - 주체: 관리자
   - 데이터: 기존 통합과 정책
   - 해설: 기기 정책이 없어도 다른 경로 통제가 있을 수 있습니다.
4. [끝] 지원 사이트와 과금 전제 검토
   - 주체: 관리자
   - 데이터: 지원 목록·종량제·사용자 구독
   - 해설: 지원 범위를 확인하고 시험합니다.

   - 주체: 관리자
   - 위치: Purview 과금 및 AI 지원 목록
   - 데이터: 종량제 활성화와 지원 AI 사이트
   - 해설: 공식 안내는 타사 AI 상호작용 관리에 종량제 활성화를 요구합니다.
2. [처리] 지원 Windows 기기 온보딩
   - 주체: 관리자
   - 위치: Purview 기기 온보딩
   - 데이터: 기기·사용자·지원 OS
   - 해설: Endpoint DLP의 기기 전제를 충족합니다.
3. [처리] 필요한 브라우저 및 확장 구성 확인
   - 주체: 관리자
   - 위치: Purview 브라우저 신호 지원 문서
   - 데이터: 브라우저·확장·버전
   - 해설: 기능과 경로별 확장 요건을 검증합니다.
4. [처리] AI 사이트와 민감 정보 유형을 정책에 지정
   - 주체: 관리자
   - 위치: Data loss prevention › Policies
   - 데이터: 대상 사이트·SIT·사용자·기기
   - 해설: 테스트용 사이트와 가상 데이터를 사용합니다.
5. [처리] 지원되는 붙여넣기 또는 업로드 동작 설정
   - 주체: 관리자
   - 위치: 기기 DLP 규칙의 활동·동작
   - 데이터: 감시·경고 또는 차단 설정
   - 해설: 실제 지원 동작은 브라우저와 OS별로 확인합니다.
6. [처리] 정책 배포 전 테스트 범위 확인
   - 주체: 관리자
   - 위치: DLP 정책 대상과 모드
   - 데이터: 테스트 사용자·기기와 정책 모드
   - 해설: 전체 조직에 적용하기 전 영향 범위를 확인합니다.
7. [끝] AI 활동 및 DLP 증적 검토
   - 주체: 관리자
   - 위치: Activity explorer 및 DLP 정책
   - 데이터: 정책 일치와 지원되는 AI 활동
   - 해설: 수집 설정과 권한에 따라 보이는 증적이 달라집니다.

#### L4 · ② 활성 — 민감 텍스트를 AI 사이트에 붙여넣기

   - 데이터: 정책 SIT에 일치하는 텍스트

5. [끝] 지원되는 활동·경고 확인

6. [끝] 이 기기 규칙의 적용 범위 조사

### L3 · A · 기기와 네트워크 경로

#### L4 · 지원 기기 경로와 네트워크 경로 비교 — 다른 강제 지점을 구별

1. [시작] 관리자가 AI 사이트 전송 사례 확인
   - 주체: 관리자
   - 데이터: 텍스트 또는 파일의 전송 경로
   - 해설: 하나의 정책이 모든 경로를 보호한다고 가정하지 않습니다.
2. [처리] Endpoint DLP의 온보딩과 대상 확인
   - 주체: 관리자
   - 위치: Purview 기기 목록과 정책
   - 데이터: 지원 Windows 기기·브라우저
   - 해설: 기기 경로에는 온보딩과 정책 범위가 필요합니다.
3. [처리] 네트워크 통합 및 별도 정책 확인
   - 주체: 관리자
   - 위치: 네트워크 데이터 보안 통합 및 DLP 정책
   - 데이터: 지원 SASE 또는 보안 브라우저 통합
   - 해설: 네트워크 통제는 별도의 공급자 통합이 필요합니다.
4. [판단] 이 예제 전송이 온보딩 기기 경로를 지나는가?
   - 주체: 관리자
   - 데이터: 기기 온보딩·지원 브라우저 여부
   - 해설: 아니오 분기는 네트워크 통제가 이미 구성된 환경을 가정합니다.
   - 기기 → 5
   - 네트워크 → 6
5. [끝] 기기 정책의 지원 활동·결과 조사
   - 주체: 관리자
   - 위치: Endpoint DLP 및 Activity explorer
   - 데이터: 기기의 정책 대상과 활동
   - 해설: 기기 기반 보호의 조건과 결과를 조사합니다.
6. [끝] 네트워크 정책·통합 경로의 결과 조사
   - 주체: 관리자
   - 위치: 네트워크 데이터 보안 정책
   - 데이터: 통합 공급자·네트워크 경로·규칙
   - 해설: 미온보딩만으로 네트워크 차단을 보장하지 않습니다.
- 시나리오: 기기 :: 온보딩 기기의 Endpoint DLP 판정 확인
- 시나리오: 네트워크 :: 별도로 통합된 네트워크 DLP 판정 확인
