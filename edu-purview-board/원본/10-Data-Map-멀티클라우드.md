## L2 · Data Map · 멀티클라우드 — 기존 환경의 원본 스캔

- 설정(Control Plane): 기존 데이터 거버넌스 계정의 원본 등록·자격 증명·런타임·스캔 규칙
- 강제(Enforcement): 스캔이 연결해 메타데이터·스키마를 수집하고 지원되는 분류 적용 | DLP 차단과 구별
- 증적(Evidence): Data Map 스캔 상태·스캔 및 분류된 자산 수 | 검색 가능한 자산 메타데이터
- 메뉴(Admin Center): Data Map > Data sources > New Scan
- 라이선스(License): 기존 계정·원본·스캔별 과금과 Azure 리소스 요건 [확인 필요: 고객 계약·원본별 비용]

### L3 · 0 · 기능 상태 전이 — 스캔 전 → 스캔 구성 → 자산 확인

#### L4 · ⓪ 비활성 — 기존 계정에 예제 스캔이 없음

1. [시작] 기존 데이터 거버넌스 계정 확인
   - 주체: 관리자
   - 위치: 기존 Microsoft Purview 데이터 거버넌스 환경
   - 데이터: 계정·원본·운영 상태
   - 해설: 신규 데이터 거버넌스 계정은 만들 수 없습니다.
2. [처리] 예제 원본의 스캔 설정 확인
   - 주체: 관리자
   - 데이터: 등록된 원본과 스캔 유무
   - 해설: 이 예제에서는 해당 원본을 아직 스캔하지 않았습니다.
3. [처리] 원본별 지원 및 전환 계획 검토
   - 주체: 관리자
   - 데이터: 원본 유형·자격 증명·런타임·Fabric 전환 계획
   - 해설: S3·Snowflake·SQL Server는 각각 지원 문서를 따로 확인합니다.
4. [끝] 스캔 대상과 소유자 선정
   - 주체: 관리자
   - 데이터: 스캔 범위와 담당자
   - 해설: 원본의 네트워크·접근 권한과 비용을 검토합니다.

#### L4 · ① 구성 — 기존 환경에 원본 스캔 설정

1. [시작] 계정 수명주기와 원본 지원 확인
   - 주체: 관리자
   - 위치: Data Map 지원 원본 및 종료 안내
   - 데이터: 기존 계정·원본 유형·지원 범위
   - 해설: 거버넌스 기능은 종료 예정이므로 전환 계획을 병행합니다.
2. [처리] 원본을 도메인 또는 컬렉션에 등록
   - 주체: 관리자
   - 위치: Data Map › Data sources
   - 데이터: 원본 주소와 도메인·컬렉션
   - 해설: 원본 유형별 등록과 접근 조건을 확인합니다.
3. [처리] 네트워크·런타임·자격 증명 준비
   - 주체: 관리자
   - 위치: 원본별 연결 및 Integration Runtime 설정
   - 데이터: 인증 방식·네트워크 경로
   - 해설: 비밀 값은 원고나 테스트 기록에 기재하지 않습니다.
4. [처리] 등록 원본에서 New Scan 선택
   - 주체: 관리자
   - 위치: Data Map › Data sources › 원본 › New Scan
   - 데이터: 스캔 이름과 자격 증명
   - 해설: 원본과 같은 도메인에 속한 설정을 선택합니다.
5. [처리] 대상 컬렉션과 연결 테스트
   - 주체: 관리자
   - 위치: New Scan › Credential › 컬렉션 › Test connection
   - 데이터: 연결 테스트 결과
   - 해설: 실패하면 원본별 자격 증명·런타임·네트워크를 조사합니다.
6. [처리] 스캔 범위와 규칙 집합 선택
   - 주체: 관리자
   - 위치: New Scan › 범위 및 Scan rule set
   - 데이터: 원본별 범위와 분류 규칙
   - 해설: 적용 가능한 범위와 분류는 원본별로 다릅니다.
7. [끝] 일정 또는 일회 실행 설정 후 저장
   - 주체: 관리자
   - 위치: New Scan › trigger › Save and run
   - 데이터: 스캔 일정과 실행 설정
   - 해설: 실행 후 상태와 발견된 자산을 확인합니다.

#### L4 · ② 활성 — 원본 연결과 스캔 상태 확인

1. [시작] 관리자가 설정한 스캔 실행
   - 주체: 관리자
   - 위치: Data Map › Data sources › 스캔
   - 데이터: 원본·자격 증명·런타임·규칙
   - 해설: 기존 환경에서 스캔을 수행하는 예제입니다.
2. [처리] 스캔 런타임이 원본에 연결
   - 주체: 스캔 런타임
   - 데이터: 인증·네트워크 연결
   - 해설: 원본별 인증과 연결 경로가 필요합니다.
3. [판단] 연결이 성공했는가?
   - 주체: 스캔 런타임
   - 데이터: 연결 테스트 결과
   - 해설: 연결 실패는 분류 결과가 없는 원인이 될 수 있습니다.
   - 성공 → 4
   - 실패 → 6
4. [처리] 범위 내 자산 메타데이터·지원 분류 수집
   - 주체: 스캔 런타임
   - 데이터: 원본 메타데이터·스키마·분류 결과
   - 해설: 수집과 분류 범위는 원본과 규칙 집합에 따릅니다.
5. [끝] Last run status와 자산 수 확인
   - 주체: 관리자
   - 위치: Data Map › 원본 › View Details
   - 데이터: 실행 상태·scanned 및 classified 자산 수
   - 해설: 완료 여부와 발견 결과를 확인합니다.
6. [끝] 인증·런타임·네트워크 오류 조사
   - 주체: 관리자
   - 위치: 연결 테스트 및 원본별 문제 해결 문서
   - 데이터: 오류 메시지·인증 방식·연결 경로
   - 해설: 원인 수정 후 연결을 다시 시험합니다.
- 시나리오: 성공 :: 연결 후 스캔 상태와 분류 자산 확인
- 시나리오: 실패 :: 원본 인증 또는 연결 문제 조사

> 주의: Unified Catalog와 클래식 Purview 데이터 거버넌스는 종료 예정이며 신규 계정을 만들 수 없습니다. 기존 기능은 2027-11-12까지 유지 관리 모드입니다. Purview 보안·규정 준수 전체가 종료되는 것은 아닙니다. Microsoft Fabric 전환 지침을 검토합니다.

### L3 · A · 전체·증분 스캔 — 대표 시나리오: 지원 원본의 스캔 방식 비교

#### L4 · ▶ 전체 스캔과 증분 스캔 선택 — 원본별 지원을 먼저 확인

1. [시작] 기존 등록 원본과 이전 스캔 확인
   - 주체: 관리자
   - 위치: Data Map › Data sources
   - 데이터: 원본 유형·마지막 스캔
   - 해설: 첫 스캔 이후 원본별 지원 여부를 검토합니다.
2. [처리] 해당 원본 문서의 지원 표 확인
   - 주체: 관리자
   - 위치: 원본별 Microsoft Learn 문서
   - 데이터: 전체·증분 지원과 전제조건
   - 해설: 모든 원본이 증분 스캔을 지원한다고 가정하지 않습니다.
3. [처리] 스캔 관리 화면 열기
   - 주체: 관리자
   - 위치: Data Map › 원본 › 스캔 관리
   - 데이터: 스캔 범위와 설정
   - 해설: 자격 증명·런타임과 규칙을 함께 확인합니다.
4. [판단] 이번 실행이 지원되는 증분 스캔인가?
   - 주체: 관리자
   - 데이터: 선택한 전체 또는 증분 방식
   - 해설: 증분 경로는 해당 원본이 지원하는 경우에만 선택합니다.
   - 증분 → 5
   - 전체 → 6
5. [끝] 마지막 스캔 이후 업데이트된 리소스 검사
   - 주체: 스캔 런타임
   - 위치: 지원되는 원본의 증분 스캔
   - 데이터: 이전 스캔 이후 변경된 리소스
   - 해설: 원본별 증분 제약과 결과를 확인합니다.
6. [끝] 지정 범위의 모든 콘텐츠 스캔
   - 주체: 스캔 런타임
   - 위치: 원본의 전체 스캔
   - 데이터: 선택한 범위 전체
   - 해설: 전체 스캔의 비용·시간은 범위와 원본에 따라 다릅니다.
- 시나리오: 증분 :: 지원 원본의 변경된 리소스만 증분 스캔
- 시나리오: 전체 :: 선택 범위 전체를 다시 스캔

> 교육 포인트: 스캔 결과는 거버넌스 자산 정보이며 그 자체로 DLP 공유 차단을 뜻하지 않습니다.
