## L2 · 암호화 · 사용 권한 — VIEW · EXTRACT

- 설정(Control Plane): 민감도 레이블의 암호화 | 관리자 지정 사용자·그룹과 사용 권한
- 강제(Enforcement): 지원 앱과 Azure Rights Management가 보호된 콘텐츠의 사용 권한 적용 | Copilot은 접근 권한과 사용 권한 확인
- 증적(Evidence): 레이블 설정 및 사용자별 열기·복사 결과 | 감사·Rights Management 사용 기록 [확인 필요: 이벤트·조회 경로]
- 메뉴(Admin Center): Information Protection > Sensitivity labels > 레이블 만들기 또는 편집 > 암호화 설정
- 라이선스(License): 레이블 암호화 및 Microsoft 365 Copilot의 사용자별 구독 요건 [확인 필요: 고객 SKU·사용 시나리오]

### L3 · 0 · 기능 상태 전이 — 보호 없는 예제 → 권한 구성 → 보호된 문서 열기

#### L4 · ⓪ 비활성 — 예제 문서에 암호화가 적용되지 않음

1. [시작] 관리자가 교육용 문서 준비
   - 주체: 관리자
   - 위치: 테스트용 문서 라이브러리
   - 데이터: 가상 데이터와 문서 접근 권한
   - 해설: 이 예제 문서는 레이블 암호화를 아직 적용하지 않았습니다.
2. [처리] 사용자에게 문서 접근 권한 부여
   - 주체: 관리자
   - 위치: 문서 저장소의 공유 권한
   - 데이터: 사용자별 저장소 접근 권한
   - 해설: 저장소 접근 권한과 문서 암호화 사용 권한은 서로 다른 계층입니다.
3. [처리] 사용자가 지원 앱에서 문서 열기
   - 주체: 사용자
   - 위치: 테스트용 문서 및 Office 앱
   - 데이터: 암호화되지 않은 예제 콘텐츠
   - 해설: 이 예제에는 레이블 암호화에 의한 추가 사용 제한이 없습니다.
4. [끝] 필요한 문서 사용 권한 정의
   - 주체: 관리자
   - 위치: 정보 보호 설계
   - 데이터: 열람할 사용자와 필요한 VIEW·EXTRACT 권한
   - 해설: 다음 단계에서 문서에 적용할 보호 권한을 레이블에 구성합니다.

#### L4 · ① 구성 — 레이블에 암호화와 관리자 지정 권한 설정

1. [시작] 보호 대상과 권한 설계
   - 주체: 관리자
   - 위치: Information Protection 배포 계획
   - 데이터: 가상 그룹·사용자와 필요한 권한
   - 해설: 레이블을 적용할 사용자와 보호된 문서를 열 사용자를 구별합니다.
2. [처리] 민감도 레이블 만들기 또는 편집
   - 주체: 관리자
   - 위치: Microsoft Purview portal › Solutions › Information Protection › Sensitivity labels
   - 데이터: 파일을 포함하는 레이블 범위
   - 해설: 파일 범위가 포함된 레이블을 사용합니다.
3. [처리] 파일의 암호화 설정 선택
   - 주체: 관리자
   - 위치: 레이블 설정 › 암호화 [확인 필요: 테넌트의 정확한 메뉴명]
   - 데이터: 암호화 적용 여부
   - 해설: 보호 설정은 레이블의 표시만 설정하는 것과 다릅니다.
4. [처리] Assign permissions now 선택
   - 주체: 관리자
   - 위치: Access control › Assign permissions now
   - 데이터: 관리자가 지정하는 사용 권한 방식
   - 해설: 여기서는 사용자가 직접 권한을 지정하는 방식 대신 관리자 지정 방식을 사용합니다.
5. [처리] 사용자 또는 그룹과 권한 선택
   - 주체: 관리자
   - 위치: Assign permissions › 사용자 또는 그룹 추가 › Choose permissions
   - 데이터: 대상 사용자·그룹과 사용 권한
   - 해설: 예제의 한 사용자에게 VIEW와 EXTRACT를, 다른 사용자에게 VIEW만 지정합니다.
6. [처리] 만료와 오프라인 접근 옵션 검토
   - 주체: 관리자
   - 위치: Access control › User access to content expires · Allow offline access
   - 데이터: 접근 만료 및 오프라인 옵션
   - 해설: 운영 환경의 요구에 맞춰 옵션을 결정합니다.
7. [끝] 레이블을 저장하고 적용할 사용자에게 게시
   - 주체: 관리자
   - 위치: Sensitivity labels 및 Label policies
   - 데이터: 레이블 정의·게시 정책·대상 사용자
   - 해설: 레이블 게시 후 지원 앱에서 보호된 파일을 만들어 검증합니다.

#### L4 · ② 활성 — 보호된 문서를 열 때 사용 권한 확인

1. [시작] 사용자가 보호된 문서를 열려고 함
   - 주체: 사용자
   - 위치: 지원 Office 앱
   - 데이터: 암호화된 문서·로그인 사용자
   - 해설: 저장소에 접근할 수 있더라도 보호된 콘텐츠의 권한은 별도입니다.
2. [처리] 앱이 문서의 보호 정보를 읽음
   - 주체: Office 앱
   - 위치: 보호된 파일과 Rights Management 경로
   - 데이터: 적용된 레이블과 암호화 보호 정보
   - 해설: 문서의 보호 설정이 사용자의 사용 권한을 결정합니다.
3. [처리] 보호 서비스가 사용자에 대한 권한 확인
   - 주체: Azure Rights Management
   - 위치: Rights Management 서비스
   - 데이터: 레이블에 지정된 사용자 또는 그룹과 사용 권한
   - 해설: 권한 부여 방식과 로그인한 사용자를 확인합니다.
4. [판단] 사용자에게 VIEW 권한이 있는가?
   - 주체: Office 앱
   - 위치: 보호된 문서 사용 권한
   - 데이터: 사용자의 VIEW 권한
   - 해설: 예제에서는 저장소 접근 가능 여부와 필요한 서비스 전제를 이미 확인했습니다.
   - 있음 → 5
   - 없음 → 6
5. [끝] 문서 내용을 볼 수 있음
   - 주체: 사용자
   - 위치: 지원 Office 앱
   - 데이터: 허용된 VIEW와 그 밖의 별도 사용 권한
   - 해설: 열람 가능하다는 것만으로 복사나 Copilot 콘텐츠 요약이 허용되는 것은 아닙니다.
6. [끝] 보호된 문서의 열람 권한을 확인
   - 주체: 사용자
   - 위치: Office 앱 및 레이블 권한 설정
   - 데이터: 사용자의 누락된 VIEW 권한
   - 해설: 예제의 사용자는 VIEW를 받지 않아 보호된 내용을 열람할 수 없습니다.
- 시나리오: 있음 :: VIEW를 받은 사용자가 보호 문서 열람
- 시나리오: 없음 :: VIEW가 없는 사용자의 문서 열람 제한

> 교육 포인트: 게시 대상, 저장소 접근 권한, 보호 문서의 사용 권한을 따로 검토합니다.
> 주의: 앱·파일·사용자 지정 권한 및 오프라인 접근의 지원 조건은 제품 문서와 고객 환경에서 검증합니다.

### L3 · A · Copilot과 사용 권한 — 대표 시나리오: 보호 문서의 요약 가능 여부 비교

#### L4 · VIEW와 EXTRACT 비교 — 같은 암호화 문서에 대한 Copilot 동작

1. [시작] 사용자가 문서 요약 요청
   - 주체: 사용자
   - 위치: 지원되는 Microsoft Copilot 환경
   - 데이터: 저장소 접근이 허용된 암호화 문서와 요청 사용자
   - 해설: 이 예제는 관리자 지정 권한의 지원되는 문서를 가정합니다.
2. [처리] Copilot이 사용자의 기존 접근 권한 확인
   - 주체: Copilot
   - 위치: 문서의 저장소 접근 경로
   - 데이터: 사용자별 저장소 권한
   - 해설: Copilot은 사용자가 접근할 권한이 있는 콘텐츠만 참조합니다.
3. [처리] 문서 보호의 사용 권한 확인
   - 주체: Copilot
   - 위치: 보호된 문서의 사용 권한
   - 데이터: VIEW 및 EXTRACT
   - 해설: 암호화된 콘텐츠를 요약하거나 반환하려면 VIEW와 EXTRACT가 모두 필요합니다.
4. [판단] VIEW와 EXTRACT를 모두 가지고 있는가?
   - 주체: Copilot
   - 위치: 사용자의 문서 사용 권한
   - 데이터: VIEW 있음; EXTRACT 있음 또는 없음
   - 해설: 이 예제는 두 경우 모두 VIEW가 있는 사용자끼리 비교합니다.
   - 둘 다 있음 → 5
   - VIEW만 있음 → 6
5. [끝] 다른 제약이 없다면 콘텐츠를 요약할 수 있음
   - 주체: Copilot
   - 위치: 지원되는 Copilot 응답
   - 데이터: 허용된 콘텐츠와 생성된 응답
   - 해설: 사용 권한 외에 DLP, 지원되는 앱, 사용자 지정 권한 등 다른 조건도 영향을 줍니다.
6. [끝] 콘텐츠를 요약하지 않고 링크를 반환할 수 있음
   - 주체: Copilot
   - 위치: 지원되는 Copilot 응답
   - 데이터: VIEW는 있으나 EXTRACT는 없는 문서
   - 해설: 링크 반환은 가능성이지 보장이 아니며, 문서를 앱에서 열어도 이 콘텐츠에 Copilot을 사용할 수 없습니다.
- 시나리오: 둘 다 있음 :: VIEW와 EXTRACT가 있어 요약 가능
- 시나리오: VIEW만 있음 :: 열람만 허용되어 Copilot 요약 제한

> 교육 포인트: 문서 열람과 Copilot의 콘텐츠 사용은 같은 권한 판정이 아닙니다.
> 주의: 사용자 지정 권한으로 암호화된 미열람 문서와 DKE 보호 문서에는 추가 제한이 있습니다. 저장소 권한과 DLP 정책도 별도 확인합니다.
