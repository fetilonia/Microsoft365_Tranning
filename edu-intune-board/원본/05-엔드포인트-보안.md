## L2 · 엔드포인트 보안 — AV · 방화벽 · BitLocker · ASR

- 설정(Control Plane): Endpoint security > Firewall의 Windows Firewall 프로필 | 그룹 할당과 방화벽 설정
- 강제(Enforcement): Intune이 설정을 전달하고 Windows Firewall CSP가 기기 방화벽을 구성
- 증적(Evidence): 정책별 기기·설정 상태 | Reports > Firewall > MDM Firewall status for Windows
- 메뉴(Admin Center): Intune 관리 센터 > Endpoint security > Firewall
- 라이선스(License): 관리 기기와 사용자에 대한 Intune 라이선스 [확인 필요: 고객 SKU 및 관리 방식별 권한]

### L3 · 0 · 기능 상태 전이 — 미할당 → 정책 구성 → 기기 방화벽 적용

> 교육 포인트: 이 예제는 Intune 관리 Windows 기기의 Windows Firewall 프로필입니다. 방화벽 규칙 프로필의 충돌 동작은 별도로 확인합니다.
> 주의: 정책이 없다고 Windows 방화벽이 반드시 꺼진 것은 아닙니다. 기존 로컬·다른 관리 정책을 확인합니다.
> 출처: https://learn.microsoft.com/en-us/intune/device-configuration/endpoint-security/firewall
> 출처: https://learn.microsoft.com/en-us/intune/device-configuration/endpoint-security/manage-policies

#### L4 · ⓪ 비활성 — 이 방화벽 정책이 없다

1. [시작] 관리자가 회사 Windows 기기를 준비한다
   - 주체: 관리자
   - 데이터: Intune 등록 기기
   - 해설: 기기 등록 자체가 이 예제의 방화벽 정책 배포는 아닙니다
2. [처리] 대상 그룹에 엔드포인트 보안 방화벽 정책이 없다
   - 주체: Intune
   - 데이터: 정책 할당 없음
   - 해설: 이 정책은 기기에 설정을 보내지 않습니다
3. [처리] Windows가 기존 방화벽 구성을 사용한다
   - 주체: 디바이스
   - 데이터: 로컬 설정과 다른 관리 원본 [확인 필요: 기기별 유효 설정]
   - 해설: 보호 상태는 기존 구성에 따라 달라집니다
4. [끝] 관리자가 현재 상태와 배포 요구를 확인한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Reports > Firewall
   - 해설: 이 정책의 미할당과 실제 방화벽 상태를 구분합니다

#### L4 · ① 구성 — Windows Firewall 프로필을 배포한다

1. [시작] 관리자가 테스트 Windows 기기 그룹을 정한다
   - 주체: 관리자
   - 위치: Entra 관리 센터 > Groups
   - 데이터: 기기 테스트 그룹
   - 해설: 기존 방화벽 관리 방식과 대상 범위를 파악합니다
2. [처리] 방화벽 정책 만들기를 연다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Endpoint security > Firewall > Create policy
   - 해설: 엔드포인트 보안 전용 정책을 만듭니다
3. [처리] Windows와 Windows Firewall 프로필을 선택한다
   - 주체: 관리자
   - 위치: Create policy > Platform · Profile
   - 데이터: Windows · Windows Firewall
   - 해설: 이 예제는 세부 허용 규칙이 아닌 방화벽 설정 프로필입니다
4. [처리] 필요한 네트워크 프로필의 방화벽 설정을 지정한다
   - 주체: 관리자
   - 위치: Configuration settings
   - 데이터: 대상 네트워크 프로필과 방화벽 활성화 값 [확인 필요: 설정 이름]
   - 해설: 해당 Windows 네트워크 프로필의 목표 상태를 정합니다
5. [처리] 기존 프로필과 같은 설정의 충돌을 검토한다
   - 주체: 관리자
   - 위치: Endpoint security · Devices > Configuration
   - 데이터: 동일 설정의 다른 정책 값
   - 해설: 다른 유형의 정책도 동일 설정을 관리할 수 있습니다
6. [처리] 테스트 그룹을 할당하고 저장한다
   - 주체: 관리자
   - 위치: Assignments > Review + create
   - 데이터: 포함 · 제외 그룹
   - 해설: 먼저 제한된 대상에 정책을 배포합니다
7. [끝] 기기별 배포 보고서를 연다
   - 주체: 관리자
   - 위치: Endpoint security > Firewall > 해당 정책
   - 데이터: 기기와 설정별 상태
   - 해설: 수신과 적용 결과를 확인할 준비를 합니다

#### L4 · ② 활성 — 기기가 방화벽 설정을 적용한다

1. [시작] 대상 Windows 기기가 Intune에 체크인한다
   - 주체: 디바이스
   - 데이터: 기기 ID와 정책 대상
   - 해설: 기기가 할당된 보안 설정을 확인합니다
2. [처리] Intune이 해당 프로필을 전달한다
   - 주체: Intune
   - 데이터: Windows Firewall 설정과 값
   - 해설: 대상과 지원 플랫폼을 기준으로 설정을 보냅니다
3. [처리] Windows Firewall CSP가 설정을 처리한다
   - 주체: 디바이스
   - 위치: Windows Firewall CSP
   - 데이터: 방화벽 프로필 설정
   - 해설: Windows의 관리 구성 요소가 설정을 적용합니다
4. [처리] 기기가 설정 상태를 보고한다
   - 주체: 디바이스
   - 데이터: 성공 · 오류 · 충돌 또는 대기 상태
   - 해설: 설정에 따라 실제 적용 상태가 달라질 수 있습니다
5. [처리] Intune이 정책별 결과를 표시한다
   - 주체: Intune
   - 위치: Endpoint security > Firewall > 해당 정책
   - 해설: 기기별 상태와 문제 설정을 확인합니다
6. [끝] 관리자가 방화벽 보고서와 대조한다
   - 주체: 관리자
   - 위치: Reports > Firewall > MDM Firewall status for Windows
   - 데이터: 관리 기기의 방화벽 상태
   - 해설: 정책 결과와 기기의 방화벽 보고를 구별해 확인합니다

### L3 · A · 핵심 동작 — 방화벽 설정 배포와 충돌

> 교육 포인트: 같은 Windows Firewall 설정에 서로 다른 값을 지정한 정책이 충돌하면 해당 설정은 기기에 전송되지 않습니다.
> 주의: Windows Firewall rules 프로필의 규칙 충돌은 다른 방식으로 처리됩니다. 오프라인 상태의 표시·시간은 [확인 필요]입니다.
> 출처: https://learn.microsoft.com/en-us/intune/device-configuration/endpoint-security/firewall

#### L4 · ▶ Windows 방화벽 배포 — 대상·연결·충돌을 확인한다

1. [시작] 관리자가 Windows Firewall 프로필을 배포한다
   - 주체: 관리자
   - 위치: Endpoint security > Firewall
   - 데이터: 기기 그룹과 방화벽 설정
   - 해설: 대상 기기의 정책 적용을 추적합니다
2. [판단] 기기가 정책 대상인가?
   - 주체: Intune
   - 데이터: 할당 그룹 · 제외
   - 해설: 제외 기기는 이 프로필을 받지 않습니다
   - 대상 → 3
   - 제외 → [끝] 할당 제외 — 그룹과 필터 확인
3. [판단] 기기가 정책을 받기 위해 연결되어 있는가?
   - 주체: 디바이스
   - 데이터: 마지막 체크인 · 연결 상태
   - 해설: 오프라인 기기는 실제 처리까지 기다려야 합니다
   - 연결됨 → 4
   - 오프라인 → [끝] 적용 대기 — 체크인 후 상태 재확인
4. [판단] 같은 방화벽 설정에 다른 정책 값이 있는가?
   - 주체: Intune
   - 데이터: 충돌하는 Windows Firewall 설정
   - 해설: 다른 값의 정책이 같은 기기에 적용되는지 확인합니다
   - 없음 → 5
   - 충돌 → [차단] 설정 충돌 — 해당 설정 미전송과 원인 정책 확인
5. [처리] 기기의 Firewall CSP가 설정을 적용한다
   - 주체: 디바이스
   - 데이터: 프로필의 방화벽 설정
   - 해설: 기기에서 적용 후 상태를 보고합니다
6. [끝] 관리자가 기기 상태와 방화벽 보고서를 확인한다
   - 주체: 관리자
   - 위치: 정책 기기 상태 · Reports > Firewall
   - 해설: 정책 성공과 기기 방화벽 상태를 대조합니다
- 시나리오: 대상 ▸ 연결됨 ▸ 없음 :: 충돌 없는 정책이 기기에 적용되어 보고
- 시나리오: 제외 :: 대상 제외로 이 방화벽 정책 미적용
- 시나리오: 대상 ▸ 오프라인 :: 오프라인 기기의 적용 결과를 대기
- 시나리오: 대상 ▸ 연결됨 ▸ 충돌 :: 같은 방화벽 설정의 값이 충돌해 미전송
