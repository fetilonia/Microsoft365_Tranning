## L2 · CA 연동 — 준수 기기만 M365 접근

- 설정(Control Plane): Intune 준수 정책·대상 | Entra 조건부 액세스의 사용자·대상 리소스 · 준수 디바이스 요구 · 정책 상태
- 강제(Enforcement): Intune이 준수 상태를 Entra에 보고 | Entra 조건부 액세스가 로그인 시 정책과 기기 신호 평가
- 증적(Evidence): Intune 기기별 준수 상세 | Entra 로그인 로그의 디바이스 정보와 조건부 액세스 결과
- 메뉴(Admin Center): Entra 관리 센터 > Entra ID > Conditional Access > Policies | Intune 관리 센터 > Endpoint security > Device compliance
- 라이선스(License): 준수 평가용 Intune과 조건부 액세스용 Entra 라이선스 [확인 필요: 고객 SKU·사용자별 자격]

### L3 · 0 · 기능 상태 전이 — 신호 준비 → 정책 구성 → 로그인 평가

> 교육 포인트: Intune은 기기 준수 신호를 보고하고 Entra CA는 별도의 접근 정책에 따라 그 신호를 사용합니다.
> 주의: 비준수 표시와 리소스 접근 차단은 같은 기능이 아닙니다. 다른 정책·인증 조건도 최종 로그인에 영향을 줄 수 있습니다.
> 출처: https://learn.microsoft.com/en-us/intune/device-security/compliance/overview
> 출처: https://learn.microsoft.com/en-us/entra/identity/conditional-access/policy-all-users-device-compliance

#### L4 · ⓪ 비활성 — 준수 요구 CA 정책이 없다

1. [시작] 사용자가 회사 앱에 로그인을 시도한다
   - 주체: 사용자
   - 데이터: 사용자 · 리소스 · 기기
   - 해설: 이 예제에서 준수 기기를 요구하는 CA 정책은 적용되지 않습니다
2. [처리] Intune이 관리 기기의 준수 상태를 보고할 수 있다
   - 주체: Intune
   - 데이터: 기기별 준수 결과
   - 해설: 준수 신호가 있어도 이를 사용하는 정책이 별도로 필요합니다
3. [처리] Entra가 다른 해당 로그인 정책을 평가한다
   - 주체: Entra ID
   - 데이터: 다른 적용 정책과 인증 요구
   - 해설: 이 CA 정책이 없다고 모든 접근이 허용되는 것은 아닙니다
4. [끝] 이 예제의 준수 요구는 접근을 제어하지 않는다
   - 주체: Entra ID
   - 위치: Entra 관리 센터 > 로그인 로그
   - 해설: 다른 정책의 결과는 로그인 로그에서 별도로 확인합니다

#### L4 · ① 구성 — 보고 전용 정책부터 준비한다

1. [시작] 관리자가 Intune 준수 정책과 준수 기기를 확인한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Endpoint security > Device compliance
   - 데이터: 테스트 기기의 준수 상태
   - 해설: 준수 정책을 먼저 배포하고 정상 기기를 준비합니다
2. [처리] Entra 조건부 액세스 정책을 새로 만든다
   - 주체: 관리자
   - 위치: Entra 관리 센터 > Entra ID > Conditional Access > Policies > New policy
   - 데이터: 정책 이름
   - 해설: 조건부 액세스 관리 권한을 가진 관리자가 만듭니다
3. [처리] 테스트 사용자와 제외 대상을 지정한다
   - 주체: 관리자
   - 위치: Assignments > Users
   - 데이터: 테스트 그룹 · 비상 액세스 계정 제외
   - 해설: 잠금을 방지하도록 비상 접근을 미리 계획합니다
4. [처리] 테스트할 회사 리소스를 지정한다
   - 주체: 관리자
   - 위치: Target resources > Resources
   - 데이터: 테스트 대상 리소스
   - 해설: 정책이 적용될 로그인 리소스를 정합니다
5. [처리] 권한 부여에서 준수 기기 요구를 선택한다
   - 주체: 관리자
   - 위치: Access controls > Grant > Require device to be marked as compliant
   - 데이터: 준수 기기 요구
   - 해설: Intune의 기기 준수 신호를 접근 판정에 사용합니다
6. [처리] 정책을 보고 전용으로 저장한다
   - 주체: 관리자
   - 위치: Enable policy > Report-only
   - 데이터: 보고 전용 상태
   - 해설: 실제 강제 전에 예상 영향을 로그인 로그로 검토합니다
7. [끝] 테스트 결과를 검토한 뒤 정책 활성화를 결정한다
   - 주체: 관리자
   - 위치: Entra 로그인 로그 > 조건부 액세스
   - 데이터: 보고 전용 평가 결과
   - 해설: 영향과 예외를 확인한 후 운영 정책을 켭니다

#### L4 · ② 활성 — Entra가 준수 상태를 사용한다

1. [시작] 대상 사용자가 회사 리소스에 로그인한다
   - 주체: 사용자
   - 데이터: 사용자 · 대상 리소스 · 기기 신호
   - 해설: 정책 대상에 해당하는 로그인입니다
2. [처리] Entra가 사용자와 리소스 할당을 평가한다
   - 주체: Entra ID
   - 데이터: 포함 및 제외 조건
   - 해설: 정책 적용 여부를 판단합니다
3. [처리] Entra가 기기 준수 상태를 확인한다
   - 주체: Entra ID
   - 데이터: Intune이 보고한 기기 준수 신호
   - 해설: 준수 디바이스 요구의 충족 여부를 평가합니다
4. [처리] 활성화된 CA 정책이 요구 충족 여부를 판정한다
   - 주체: Entra ID
   - 데이터: 정책 상태 On · 준수 기기 요구
   - 해설: 미충족이면 이 정책의 권한 부여 요구를 충족할 수 없습니다
5. [처리] 로그인 결과와 정책 평가를 기록한다
   - 주체: Entra ID
   - 위치: Entra 관리 센터 > 로그인 로그
   - 데이터: 디바이스 정보 · 조건부 액세스 결과
   - 해설: 어떤 정책이 적용됐는지 로그에서 확인합니다
6. [끝] 관리자가 Intune과 Entra 증적을 대조한다
   - 주체: 관리자
   - 위치: Intune 기기 준수 보고서 · Entra 로그인 로그
   - 데이터: 기기 ID · 평가 상태 · 로그인 시각
   - 해설: 두 서비스의 상태와 시점을 함께 비교합니다

### L3 · A · 핵심 동작 — 준수 기기 요구의 적용과 예외

> 교육 포인트: 보고 전용은 평가 결과를 기록하지만 그 정책의 권한 부여를 강제하지 않습니다.
> 주의: 예시의 허용 결과는 다른 차단 정책이나 추가 인증 요구가 없다는 전제입니다. 실제 로그인은 모든 해당 정책과 함께 평가합니다.
> 출처: https://learn.microsoft.com/en-us/entra/identity/conditional-access/policy-all-users-device-compliance
> 출처: https://learn.microsoft.com/en-us/intune/device-security/compliance/overview

#### L4 · ▶ 회사 리소스 로그인 — 준수 상태와 CA 정책을 대조한다

1. [시작] 사용자가 관리 기기에서 회사 리소스에 로그인한다
   - 주체: 사용자
   - 위치: 회사 앱 로그인
   - 데이터: 사용자 · 대상 리소스 · 기기 신호
   - 해설: 로그인과 준수 상태를 함께 살펴봅니다
2. [판단] 사용자와 리소스가 이 CA 정책 대상인가?
   - 주체: Entra ID
   - 데이터: 사용자와 리소스 포함 · 제외
   - 해설: 정책 범위 밖이면 이 정책의 준수 요구는 적용되지 않습니다
   - 대상 → 3
   - 제외 → [끝] 정책 미적용 — 제외 사유와 다른 정책 확인
3. [판단] 정책이 보고 전용인가?
   - 주체: Entra ID
   - 데이터: 정책 상태 Report-only 또는 On
   - 해설: 보고 전용에서는 예상 결과만 기록합니다
   - 보고 전용 → [끝] 평가만 기록 — 이 정책은 접근을 강제하지 않음
   - 활성 → 4
4. [판단] 기기 준수 요구가 충족되는가?
   - 주체: Entra ID
   - 데이터: Entra가 평가에 사용하는 기기 준수 신호
   - 해설: 신호가 없거나 요구를 만족하지 못하면 원인을 조사합니다
   - 충족 → 5
   - 미충족 → [차단] 준수 요구 미충족 — 기기 신호와 Intune 준수 상태 점검
5. [처리] 다른 적용 정책과 인증 요구를 평가한다
   - 주체: Entra ID
   - 데이터: 나머지 CA 정책과 권한 부여 요구
   - 해설: 준수 요구 하나가 충족돼도 다른 요구는 남을 수 있습니다
6. [끝] 다른 요구도 충족한 예제 로그인이 완료된다
   - 주체: Entra ID
   - 위치: Entra 관리 센터 > 로그인 로그 > 조건부 액세스
   - 데이터: 정책 결과 · 기기 정보
   - 해설: 정책 결과와 Intune 준수 보고서를 비교합니다
- 시나리오: 대상 ▸ 활성 ▸ 충족 :: 준수 기기가 요구를 충족하고 다른 요구도 통과
- 시나리오: 제외 :: 대상에서 제외돼 이 준수 요구는 미적용
- 시나리오: 대상 ▸ 보고 전용 :: 보고 전용으로 예상 결과만 기록
- 시나리오: 대상 ▸ 활성 ▸ 미충족 :: 준수 요구 미충족으로 로그인 차단
