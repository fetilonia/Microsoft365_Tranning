## L2 · 원격 작업 · RBAC — 잠금 · 초기화 · 선택적 초기화

- 설정(Control Plane): Intune 역할 권한 · 관리 대상 범위 그룹 · 범위 태그 | 기기 원격 작업과 앱 선택적 초기화 요청
- 강제(Enforcement): 지원되는 관리 기기가 원격 명령을 수신 | 앱 선택적 초기화는 보호 앱의 회사 데이터를 대상으로 처리
- 증적(Evidence): 기기 작업 상태 · Intune 감사 로그 | 앱 선택적 초기화 요청별 상태
- 메뉴(Admin Center): Intune 관리 센터 > Devices > All devices > 기기 > Secure > Remote lock | Apps > App selective wipe | Tenant administration > Roles
- 라이선스(License): 관리 기기와 앱 보호 대상 사용자의 Intune 자격 [확인 필요: 고객 SKU · 기기/앱 조건]

### L3 · 0 · 기능 상태 전이 — 위임 전 → 역할 구성 → 원격 잠금

> 교육 포인트: 예제는 암호가 설정된 Intune 관리 iOS/iPadOS 기기입니다. Remote lock의 지원 플랫폼에 Windows는 포함되지 않습니다.
> 주의: 원격 잠금은 초기화가 아니며, PIN이나 암호가 없는 경우 화면만 꺼지고 접근이 가능할 수 있습니다.
> 출처: https://learn.microsoft.com/en-us/intune/device-management/actions/remote-lock
> 출처: https://learn.microsoft.com/en-us/intune/fundamentals/role-based-access-control/overview
> 확인일: 2026-11-25

#### L4 · ⓪ 비활성 — 담당자에게 원격 잠금 권한이 없다

1. [시작] 사용자가 회사 iPad를 분실했다고 신고한다
   - 주체: 사용자
   - 데이터: Intune 관리 iPad · 신고 내용
   - 해설: 헬프데스크가 대상 기기를 확인합니다
2. [처리] 담당자에게 해당 기기 원격 잠금 역할이 없다
   - 주체: Intune
   - 데이터: 담당자의 역할과 관리 범위
   - 해설: 대상과 필요한 권한이 없는 담당자는 요청할 수 없습니다
3. [처리] 기기는 기존 잠금 설정에 따라 동작한다
   - 주체: 디바이스
   - 데이터: 기존 화면 잠금 · 암호
   - 해설: 이 예제에서 원격 명령은 전송되지 않았습니다
4. [끝] 관리자가 적절한 담당자와 위임 범위를 정한다
   - 주체: 관리자
   - 해설: 최소 권한 원칙으로 관리 역할을 준비합니다

#### L4 · ① 구성 — 담당자에게 잠금 권한을 위임한다

1. [시작] 역할 관리자가 관리 대상과 담당자 그룹을 정의한다
   - 주체: 관리자
   - 위치: Entra 관리 센터 > Groups
   - 데이터: 헬프데스크 관리자 그룹 · 관리 기기 범위 그룹
   - 해설: 작업 담당자와 관리할 대상을 분리합니다
2. [처리] 원격 잠금에 필요한 역할을 선택한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Tenant administration > Roles > All roles
   - 데이터: Help Desk Operator 또는 필요한 읽기와 Remote tasks/Remote lock을 가진 사용자 지정 역할
   - 해설: 명령 권한과 대상 기기 열람 권한을 함께 확인합니다
3. [처리] 역할 할당에 담당자 그룹을 지정한다
   - 주체: 관리자
   - 위치: 역할 > Assignments
   - 데이터: 관리자 멤버 그룹
   - 해설: 실제 원격 작업을 수행할 담당자를 지정합니다
4. [처리] 역할의 관리 범위 그룹을 지정한다
   - 주체: 관리자
   - 위치: 역할 할당 > Scope (Groups)
   - 데이터: 담당자가 관리할 기기 또는 사용자 그룹
   - 해설: 작업 대상의 범위를 제한합니다
5. [처리] 범위 태그와 기기의 가시성을 검토한다
   - 주체: 관리자
   - 위치: 역할 할당 > Scope tags · 대상 기기
   - 데이터: 역할 할당 및 기기 태그
   - 해설: 개체 가시성에 영향을 주는 태그를 검토합니다
6. [처리] iPad에 기존 암호와 인터넷 연결이 있는지 확인한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Devices > All devices
   - 데이터: 지원 플랫폼 · 마지막 체크인 · 암호 요구 정책
   - 해설: 원격 잠금의 효과와 명령 수신 조건을 점검합니다
7. [끝] 위임된 담당자의 대상 가시성과 권한을 시험한다
   - 주체: 관리자
   - 위치: 역할 할당 · 관리 기기
   - 데이터: 테스트 담당자와 범위 내 기기
   - 해설: 실제 분실 대응 전에 최소 권한을 검증합니다

#### L4 · ② 활성 — 담당자가 관리 iPad를 잠근다

1. [시작] 권한 있는 담당자가 분실 신고를 받는다
   - 주체: 관리자
   - 데이터: 사용자 · 기기 식별 정보
   - 해설: 대상 기기가 올바른지 먼저 확인합니다
2. [처리] Intune에서 iPad를 선택한다
   - 주체: 관리자
   - 위치: Devices > All devices > 해당 기기
   - 데이터: 관리 기기 개체와 플랫폼
   - 해설: 범위 안의 관리 기기인지 확인합니다
3. [처리] Secure > Remote lock을 요청한다
   - 주체: 관리자
   - 위치: 기기 개요 > Secure > Remote lock
   - 데이터: 원격 잠금 요청
   - 해설: 원격 잠금은 기기 데이터 초기화 명령이 아닙니다
4. [처리] 기기가 명령을 수신해 잠금을 수행한다
   - 주체: 디바이스
   - 데이터: 기존 기기 암호
   - 해설: 사용자는 기존 암호를 입력해 다시 접근합니다
5. [처리] Intune이 원격 작업 상태를 표시한다
   - 주체: Intune
   - 위치: 기기 개요 > Device action status [확인 필요: 메뉴]
   - 데이터: 요청 시각과 작업 상태
   - 해설: 요청 제출과 실제 기기 처리는 구분해야 합니다
6. [끝] 담당자가 상태와 감사 기록을 확인한다
   - 주체: 관리자
   - 위치: 기기 작업 상태 · Tenant administration > Audit logs
   - 데이터: 담당자 · 대상 · 요청과 처리 결과
   - 해설: 작업의 실행과 기록을 대조합니다

### L3 · A · 핵심 동작 — 권한과 연결에 따른 원격 잠금

> 교육 포인트: 역할 권한, 범위 그룹, 태그와 플랫폼 지원을 함께 확인합니다. 작업 요청이 접수됐다는 것과 기기가 잠겼다는 것은 다릅니다.
> 출처: https://learn.microsoft.com/en-us/intune/device-management/actions/remote-lock

#### L4 · ▶ iPad 원격 잠금 — 권한과 명령 수신을 확인한다

1. [시작] 담당자가 암호가 있는 관리 iPad를 선택한다
   - 주체: 관리자
   - 위치: Devices > All devices
   - 데이터: 기기 ID · iOS/iPadOS · 기존 암호
   - 해설: 지원 기기와 잠금 효과의 전제입니다
2. [판단] 담당자에게 대상 기기의 잠금 권한과 범위가 있는가?
   - 주체: Intune
   - 데이터: Remote tasks/Remote lock · 기기 읽기 · 범위
   - 해설: 권한 또는 범위 밖이면 해당 작업을 수행할 수 없습니다
   - 있음 → 3
   - 없음 → [차단] 권한 또는 범위 부족 — 역할과 대상 확인
3. [처리] 담당자가 원격 잠금을 요청한다
   - 주체: 관리자
   - 위치: 기기 > Secure > Remote lock
   - 해설: Intune에 기기 작업을 제출합니다
4. [판단] 기기가 인터넷에 연결되어 명령을 수신하는가?
   - 주체: 디바이스
   - 데이터: 연결 · 체크인 및 작업 상태
   - 해설: 오프라인이면 수신 및 처리 여부를 추후 확인합니다
   - 수신 → 5
   - 오프라인 → [끝] 처리 대기 — 연결 후 작업 상태 확인
5. [처리] 기기가 잠기고 기존 암호를 요구한다
   - 주체: 디바이스
   - 데이터: 기존 기기 암호
   - 해설: 데이터 삭제 없이 화면 접근을 제한합니다
6. [끝] 담당자가 기기 작업과 감사 기록을 대조한다
   - 주체: 관리자
   - 위치: 기기 작업 상태 · Audit logs
   - 데이터: 작업 결과 · 관리자 · 대상
   - 해설: 명령 처리 결과와 감사 이력을 함께 확인합니다
- 시나리오: 있음 ▸ 수신 :: 권한 있는 담당자의 잠금 명령을 기기가 처리
- 시나리오: 없음 :: 담당자의 권한 또는 범위가 없어 요청 불가
- 시나리오: 있음 ▸ 오프라인 :: 오프라인 기기의 명령 처리 결과 대기

### L3 · B · 앱 데이터 작업 — 선택적 초기화와 기기 작업 구분

> 교육 포인트: 앱 선택적 초기화는 보호 앱의 회사 데이터가 대상이며 기기 전체 Wipe나 원격 잠금과 다릅니다.
> 주의: Android와 iOS/iPadOS에서 앱 선택적 초기화에는 앱 보호 정책 배포가 필요합니다. 요청이 대기 중이면 삭제 완료라고 판단하지 않습니다.
> 출처: https://learn.microsoft.com/en-us/intune/app-management/protection/wipe-corporate-data
> 출처: https://learn.microsoft.com/en-us/intune/device-management/actions/
> 확인일: 2026-11-25

#### L4 · 보호 앱 회사 데이터 제거 — 앱 요청과 처리 결과 확인

1. [시작] 관리자가 사용자의 회사 앱 데이터를 제거하기로 결정한다
   - 주체: 관리자
   - 데이터: 사용자 · 기기 · 보호 앱
   - 해설: 기기 전체 초기화가 아닌 앱의 회사 데이터가 대상입니다
2. [처리] 앱 선택적 초기화 요청을 만든다
   - 주체: 관리자
   - 위치: Apps > App selective wipe > Create wipe request
   - 데이터: 사용자와 기기 선택
   - 해설: Intune에서 보호 앱의 회사 데이터 제거를 요청합니다
3. [판단] 보호 앱이 요청을 처리했는가?
   - 주체: 보호 앱
   - 데이터: 앱 실행 · 정책 수신 · 요청 상태
   - 해설: 앱이 요청을 처리하기 전까지 완료를 가정하지 않습니다
   - 처리 → 4
   - 대기 → [끝] 앱 요청 대기 — 이후 앱 처리와 보고 상태 확인
   - 실패 → [차단] 앱 요청 실패 — 보호 앱과 요청 상태 조사
4. [처리] 앱이 해당 회사 데이터를 제거한다
   - 주체: 보호 앱
   - 데이터: 앱의 회사 데이터
   - 해설: 기기 전체 데이터와 앱 자체를 초기화하는 작업은 아닙니다
5. [끝] 관리자가 앱별 요청 결과를 확인한다
   - 주체: 관리자
   - 위치: Apps > App selective wipe
   - 데이터: 앱별 Pending · Failed · Successful
   - 해설: 하나의 사용자에게 여러 앱 요청이 있을 수 있으므로 각각 확인합니다
- 시나리오: 처리 :: 보호 앱의 회사 데이터를 제거하고 결과 확인
- 시나리오: 대기 :: 앱이 아직 요청을 처리하지 않아 완료 대기
- 시나리오: 실패 :: 앱 초기화 요청 실패 원인을 확인
