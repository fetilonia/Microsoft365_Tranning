## L2 · 앱 보호 (MAM) — BYOD · 앱 단위 회사 데이터

- 설정(Control Plane): Android 앱 보호 정책 · 사용자와 보호 앱 할당 | 앱 PIN · 회사 데이터 이동 제한
- 강제(Enforcement): Intune 앱 보호를 지원하는 앱이 업무 계정 컨텍스트에 정책 적용
- 증적(Evidence): 앱 보호 정책 사용자 상태 보고서 | 앱에서 PIN 및 데이터 이동 제한 확인
- 메뉴(Admin Center): Intune 관리 센터 > Apps > App protection policies
- 라이선스(License): 사용자별 Intune 앱 보호 라이선스 및 서비스 자격 [확인 필요: 고객 SKU와 플랫폼 요구]

### L3 · 0 · 기능 상태 전이 — 보호 없음 → 정책 구성 → 업무 앱 보호

> 교육 포인트: 앱 보호는 MDM 등록 없이도 지원되는 앱의 회사 데이터를 보호할 수 있습니다. 기기 관리, 앱 설치, Wi-Fi 설정을 대신하지는 않습니다.
> 주의: 예제는 Android의 Outlook과 지원되는 보호 앱입니다. Android는 앱 보호 정책 수신에 Company Portal이 필요합니다.
> 출처: https://learn.microsoft.com/en-us/intune/app-management/protection/overview
> 출처: https://learn.microsoft.com/en-us/intune/app-management/ref-protected-apps

#### L4 · ⓪ 비활성 — 회사 데이터에 앱 보호 정책이 없다

1. [시작] 사용자가 개인 Android 기기에서 회사 메일에 접근한다
   - 주체: 사용자
   - 데이터: 개인 기기 · 회사 계정
   - 해설: 기기는 이 예제에서 MDM에 등록되지 않았습니다
2. [처리] 회사 계정에 이 앱 보호 정책이 할당되지 않았다
   - 주체: Intune
   - 데이터: 대상 사용자와 앱 할당 없음
   - 해설: 예제의 PIN과 데이터 이동 제한은 적용되지 않습니다
3. [처리] 앱의 기존 동작과 다른 보호 정책을 확인한다
   - 주체: 관리자
   - 데이터: 기존 앱 · 접근 정책 [확인 필요: 환경별 구성]
   - 해설: 다른 통제까지 없다고 가정하지 않습니다
4. [끝] 관리자가 회사 데이터 이동 위험을 평가한다
   - 주체: 관리자
   - 해설: 기기 전체 관리 없이 보호할 앱과 데이터를 정합니다

#### L4 · ① 구성 — Outlook 앱 보호를 지정한다

1. [시작] 관리자가 BYOD 사용자와 Android 앱을 확인한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Apps
   - 데이터: 사용자 그룹 · 지원 앱 · 라이선스
   - 해설: 사용자와 앱이 정책의 대상이 되는지 확인합니다
2. [처리] Android 앱 보호 정책을 만든다
   - 주체: 관리자
   - 위치: Apps > App protection policies > Create policy > Android
   - 데이터: 정책 이름 · 플랫폼
   - 해설: 모바일 앱의 업무 데이터 보호 정책을 만듭니다
3. [처리] Outlook과 필요한 보호 앱을 선택한다
   - 주체: 관리자
   - 위치: 정책 > Apps
   - 데이터: 대상 앱 · 기기 관리 상태 [확인 필요: 해당 테넌트 설정]
   - 해설: 정책이 실제로 적용될 앱을 명시합니다
4. [처리] 회사 데이터 이동 제한을 구성한다
   - 주체: 관리자
   - 위치: 정책 > Data protection
   - 데이터: Restrict cut, copy, and paste · 다른 앱으로 데이터 전송 설정
   - 해설: 업무 데이터가 개인 앱으로 이동하지 않도록 설정합니다
5. [처리] 업무 앱 접근 PIN을 요구한다
   - 주체: 관리자
   - 위치: 정책 > Access requirements
   - 데이터: PIN 요구와 복잡도 [확인 필요: 세부 설정]
   - 해설: 업무 컨텍스트 접근 시 추가 보호를 정합니다
6. [처리] 사용자 그룹에 정책을 할당한다
   - 주체: 관리자
   - 위치: 정책 > Assignments
   - 데이터: 포함 · 제외 사용자 그룹
   - 해설: 앱이 업무 사용자에 대해 정책을 받을 수 있게 합니다
7. [끝] 지원 앱과 Company Portal 준비를 안내한다
   - 주체: 관리자
   - 위치: 사용자 앱 스토어 · Company Portal
   - 데이터: Android용 Outlook · Company Portal
   - 해설: 미등록 기기에서는 사용자가 앱을 설치합니다

#### L4 · ② 활성 — 개인 기기에서 업무 데이터를 보호한다

1. [시작] 사용자가 개인 Android 기기에 Outlook과 Company Portal을 설치한다
   - 주체: 사용자
   - 위치: Android 앱 스토어
   - 데이터: 이 예제는 MDM 미등록 기기
   - 해설: 앱 보호에 기기 MDM 등록은 필수가 아닙니다
2. [처리] 사용자가 Outlook에 회사 계정으로 로그인한다
   - 주체: 사용자
   - 데이터: 업무 계정 · 대상 앱
   - 해설: 정책 대상 사용자의 업무 컨텍스트가 시작됩니다
3. [처리] 앱이 할당된 보호 정책을 수신한다
   - 주체: Outlook
   - 데이터: 앱 보호 정책 · 회사 계정
   - 해설: 지원 앱이 업무 데이터 보호 설정을 적용합니다
4. [처리] 사용자가 앱 PIN 요구를 충족한다
   - 주체: 사용자
   - 데이터: 정책이 요구한 앱 PIN
   - 해설: 기기 화면 잠금과 별개인 앱 접근 조건입니다
5. [처리] 회사 데이터 이동 요청에 정책을 적용한다
   - 주체: Outlook
   - 데이터: 복사 · 붙여넣기 및 전송 제한 설정
   - 해설: 업무 데이터가 허용된 경로로만 이동하도록 통제합니다
6. [끝] 관리자가 앱 보호 상태를 확인한다
   - 주체: 관리자
   - 위치: Apps > Monitor > App protection status [확인 필요: 메뉴]
   - 데이터: 사용자·앱의 정책 상태
   - 해설: 사용자 보고와 실제 앱 동작을 함께 점검합니다

### L3 · A · 핵심 동작 — 회사 데이터 이동 제한

> 교육 포인트: 보호 앱의 업무 계정과 개인 앱은 다릅니다. 앱 보호 적용만으로 지원하지 않는 클라이언트의 접근이 자동 차단된다고 가정하지 않습니다.
> 주의: 허용 대상과 붙여넣기 결과는 플랫폼·정책 값·앱 버전에 따라 [확인 필요: 기능·플랫폼·정책 모드별 동작을 최신 Microsoft Learn 및 격리된 테스트 테넌트에서 재현해 확인]입니다.
> 출처: https://learn.microsoft.com/en-us/intune/app-management/protection/overview

#### L4 · BYOD Outlook 데이터 이동 — 정책과 대상 앱을 비교한다

1. [시작] 사용자가 Android Outlook에서 회사 메일 내용을 선택한다
   - 주체: 사용자
   - 데이터: 업무 계정의 회사 데이터
   - 해설: 개인 기기의 업무 컨텍스트에서 이동을 시도합니다
2. [판단] 사용자와 Outlook이 앱 보호 정책 대상인가?
   - 주체: Intune · Outlook
   - 데이터: 정책 할당 · 지원 앱 · 업무 계정
   - 해설: 대상이 아니거나 지원되지 않으면 이 정책이 해당 앱을 보호한다고 주장할 수 없습니다
   - 대상 → 3
   - 미대상 → [끝] 정책 미적용 — 앱 지원과 사용자 할당 확인
3. [처리] Outlook이 정책을 받고 앱 PIN을 요구한다
   - 주체: Outlook
   - 데이터: 앱 보호 PIN · 데이터 이동 정책
   - 해설: 정책이 적용된 업무 앱을 엽니다
4. [판단] 선택한 이동 대상이 정책에 허용된 보호 앱인가?
   - 주체: Outlook
   - 데이터: Restrict cut, copy, and paste · 대상 앱
   - 해설: 이 예제는 보호 앱으로의 이동을 허용하고 개인 앱은 제한합니다
   - 허용 앱 → 5
   - 개인 앱 → [차단] 데이터 이동 제한 — 개인 앱 붙여넣기 제한
5. [처리] 사용자가 허용된 보호 앱에서 데이터를 사용한다
   - 주체: 사용자
   - 데이터: 정책이 허용한 업무 데이터 이동
   - 해설: 정책과 대상 앱이 모두 허용한 경로만 사용합니다
6. [끝] 관리자가 정책 상태와 사용자 경험을 확인한다
   - 주체: 관리자
   - 위치: 앱 보호 상태 보고서 · 대상 앱
   - 데이터: 정책 수신 여부 · 복사 결과
   - 해설: 실제 단말에서 허용과 제한을 각각 시험합니다
- 시나리오: 대상 ▸ 허용 앱 :: 보호 앱 사이에 허용된 업무 데이터 이동
- 시나리오: 미대상 :: 사용자 또는 앱이 대상이 아니어서 정책 미적용
- 시나리오: 대상 ▸ 개인 앱 :: 회사 데이터를 개인 앱에 붙여넣지 못함
