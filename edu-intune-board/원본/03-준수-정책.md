## L2 · 준수 정책 — 암호화 · OS 버전 · 암호

- 설정(Control Plane): 플랫폼별 준수 규칙 · 그룹 할당 · 비준수 조치 | 미할당 기기의 테넌트 처리 설정
- 강제(Enforcement): 기기 상태를 준수 규칙과 비교하고 Intune이 상태 보고 | 접근 제어는 별도의 Entra 조건부 액세스
- 증적(Evidence): Intune 정책별 · 기기별 준수 상태와 실패 설정 | Entra에 보고된 기기 준수 상태
- 메뉴(Admin Center): Intune 관리 센터 > Endpoint security > Device compliance
- 라이선스(License): Intune을 통한 관리와 준수 정책 대상의 라이선스 [확인 필요: 고객 SKU 및 기기 유형] | 조건부 액세스 사용 시 Entra 라이선스 별도 확인

### L3 · 0 · 기능 상태 전이 — 기준 없음 → 준수 기준 구성 → 기기 평가

> 교육 포인트: 준수 정책은 상태를 평가합니다. 암호화를 실제로 설정하는 구성 정책 및 접근을 차단하는 CA 정책과 구분합니다.
> 주의: 정책 미할당 기기의 상태는 테넌트의 별도 설정에 따라 결정됩니다. 정책이 없다는 사실만으로 보호가 확인된 것은 아닙니다.
> 출처: https://learn.microsoft.com/en-us/intune/device-security/compliance/overview
> 출처: https://learn.microsoft.com/en-us/intune/device-security/compliance/configure-noncompliance-actions

#### L4 · ⓪ 비활성 — 이 기기에 준수 정책이 할당되지 않았다

1. [시작] 관리 기기에 사용자가 로그인한다
   - 주체: 사용자
   - 데이터: Intune 등록 Windows 기기
   - 해설: 기기 등록만으로 개별 준수 기준이 배포되지는 않습니다
2. [처리] 기기에 개별 준수 정책이 할당되지 않았다
   - 주체: Intune
   - 데이터: 정책 할당 없음
   - 해설: 암호화와 OS 버전에 대한 이 예제의 규칙은 평가되지 않습니다
3. [처리] 테넌트가 미할당 기기의 상태를 결정한다
   - 주체: Intune
   - 위치: Endpoint security > Device compliance > Compliance policy settings
   - 데이터: Mark devices with no compliance policy assigned as · Compliant 또는 Not compliant
   - 해설: 미할당 상태를 준수 또는 비준수로 다루도록 별도 설정합니다
4. [끝] 관리자가 미할당 상태와 실제 보호를 구분한다
   - 주체: 관리자
   - 데이터: 테넌트 설정과 실제 정책 할당
   - 해설: 준수로 표시되어도 개별 정책의 암호화 검사를 통과했다는 뜻은 아닙니다

#### L4 · ① 구성 — Windows 준수 기준과 조치를 만든다

1. [시작] 관리자가 테스트할 Windows 기기 그룹을 정한다
   - 주체: 관리자
   - 위치: Entra 관리 센터 > Groups
   - 데이터: 테스트 사용자 또는 기기 그룹
   - 해설: 실제 배포 전에 대상과 제외를 검토합니다
2. [처리] 새 Windows 준수 정책을 만든다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Endpoint security > Device compliance > Policies > Create policy [확인 필요: 메뉴]
   - 데이터: Windows 10 and later 플랫폼
   - 해설: 준수 정책은 플랫폼별로 만듭니다
3. [처리] 기기 암호화 요구를 선택한다
   - 주체: 관리자
   - 위치: 정책 > Compliance settings
   - 데이터: 암호화 요구 설정 [확인 필요: 메뉴 및 플랫폼 조건]
   - 해설: 기기 암호화 여부를 판단 기준으로 사용합니다
4. [처리] 최소 OS 버전 기준을 지정한다
   - 주체: 관리자
   - 위치: 정책 > Compliance settings
   - 데이터: 테스트용 최소 OS 버전
   - 해설: 조직이 허용할 OS 버전의 하한을 정합니다
5. [처리] 비준수 표시와 알림 일정을 확인한다
   - 주체: 관리자
   - 위치: 정책 > Actions for noncompliance
   - 데이터: 기본 비준수 표시 0일 · 선택적 유예와 알림
   - 해설: 비준수 판정과 조치 시점을 분리해 설정합니다
6. [처리] 정책을 테스트 그룹에 할당한다
   - 주체: 관리자
   - 위치: 정책 > Assignments
   - 데이터: 포함 및 제외 그룹
   - 해설: 이 정책을 평가할 대상을 지정합니다
7. [끝] 미할당 기기와 상태 유효 기간 설정을 검토한다
   - 주체: 관리자
   - 위치: Device compliance > Compliance policy settings
   - 데이터: 미할당 처리 · 상태 유효 기간
   - 해설: 개별 정책 외에 테넌트 수준의 평가 규칙이 있습니다

#### L4 · ② 활성 — 기기 상태를 평가해 보고한다

1. [시작] 대상 Windows 기기가 Intune에 체크인한다
   - 주체: 디바이스
   - 데이터: 대상 그룹 및 준수 정책
   - 해설: 기기가 할당된 기준을 받습니다
2. [처리] 기기가 암호화 상태를 확인한다
   - 주체: 디바이스
   - 데이터: 암호화 상태와 정책 요구
   - 해설: 실제 상태를 설정된 암호화 기준과 비교합니다
3. [처리] OS 버전을 기준과 비교한다
   - 주체: 디바이스
   - 데이터: 현재 OS 버전 · 최소 버전
   - 해설: 설정된 최소 버전도 충족해야 합니다
4. [처리] Intune이 평가 결과와 비준수 조치를 처리한다
   - 주체: Intune
   - 데이터: 준수 · 비준수 또는 처리 중 상태 [확인 필요: 각 상태의 세부 조건]
   - 해설: 설정된 일정에 따라 비준수 표시 및 알림을 처리합니다
5. [처리] 준수 상태가 Entra에 보고된다
   - 주체: Intune
   - 데이터: Entra 기기 준수 상태
   - 해설: CA는 이 신호를 별도 정책에서 사용할 수 있습니다
6. [끝] 관리자가 실패한 설정을 확인한다
   - 주체: 관리자
   - 위치: Intune 관리 센터 > Device compliance > 정책 및 기기 보고서
   - 데이터: 기기별 · 설정별 준수 상태
   - 해설: 상태와 원인을 함께 확인합니다

### L3 · A · 핵심 동작 — 암호화 기준과 유예 기간

> 교육 포인트: 비준수 표시는 기본 0일이나 관리자가 일정을 변경하면 유예 기간을 둘 수 있습니다.
> 주의: 미할당 기기의 상태와 오래된 체크인은 별도 테넌트 설정의 영향을 받습니다. CA가 없으면 비준수 자체가 곧바로 리소스 접근 차단을 뜻하지 않습니다.
> 출처: https://learn.microsoft.com/en-us/intune/device-security/compliance/overview
> 출처: https://learn.microsoft.com/en-us/intune/device-security/compliance/configure-noncompliance-actions

#### L4 · ▶ 암호화 준수 평가 — 실제 상태와 비준수 일정을 비교한다

1. [시작] 관리자가 암호화 요구 정책을 기기 그룹에 할당한다
   - 주체: 관리자
   - 위치: Endpoint security > Device compliance > Policies
   - 데이터: Windows 암호화 요구 · 비준수 표시 일정
   - 해설: 정책과 조치 일정이 평가 기준이 됩니다
2. [판단] 이 기기에 정책이 할당되었는가?
   - 주체: Intune
   - 데이터: 그룹 멤버십과 정책 할당
   - 해설: 미할당이면 테넌트의 미할당 기기 설정을 확인합니다
   - 할당됨 → 3
   - 미할당 → [끝] 정책 미할당 — 테넌트 미할당 처리 설정 확인
3. [처리] 기기가 체크인하여 암호화 상태를 보고한다
   - 주체: 디바이스
   - 데이터: 암호화 여부 · 마지막 체크인
   - 해설: 평가와 보고는 기기 체크인에 의존합니다
4. [판단] 보고된 상태가 암호화 기준을 충족하는가?
   - 주체: Intune
   - 데이터: 암호화 요구와 기기 상태
   - 해설: 기준에 미달하면 비준수 조치 일정이 적용됩니다
   - 충족 → 5
   - 미충족 → 6
5. [끝] 기기가 이 정책의 암호화 기준을 충족한다
   - 주체: Intune
   - 데이터: 기기별 준수 보고서
   - 해설: 다른 준수 정책과 테넌트 설정 결과는 별도 확인합니다
6. [판단] 비준수 표시 유예 기간이 남았는가?
   - 주체: Intune
   - 데이터: Mark device noncompliant 일정
   - 해설: 기본 0일이면 유예 없이 비준수 표시를 처리합니다
   - 남음 → [끝] 유예 중 — 사용자 조치와 다음 평가를 기다림
   - 만료 → [끝] 비준수 — 보고서의 실패 설정과 조치 확인
- 시나리오: 할당됨 ▸ 충족 :: 암호화 기준을 충족해 정책 결과 확인
- 시나리오: 미할당 :: 정책 미할당으로 테넌트 기본 처리 확인
- 시나리오: 할당됨 ▸ 미충족 ▸ 남음 :: 암호화 미충족이나 비준수 표시 유예 중
- 시나리오: 할당됨 ▸ 미충족 ▸ 만료 :: 암호화 미충족과 유예 만료로 비준수 표시
