## L2 · 그라운딩 — Graph · Semantic Index

- 설정(Control Plane): SharePoint · OneDrive 문서 권한 | 사이트 멤버십과 공유 링크 검토
- 강제(Enforcement): 사용자에게 허용된 조직 데이터 경계 | 검색 및 관련성에 따른 참조
- 증적(Evidence): Microsoft Purview 감사의 Copilot 상호작용과 접근한 리소스 | 프롬프트·응답 본문은 별도 eDiscovery 또는 DSPM for AI
- 메뉴(Admin Center): SharePoint 관리 센터 > 사이트 > 활성 사이트 [확인 필요: 테넌트 메뉴] | Microsoft Purview > 감사
- 라이선스(License): Copilot 경험별 적격 구독 및 라이선스 확인 | Purview 감사·eDiscovery 기능별 SKU와 역할 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 기존 공유 상태 → 권한 검토 → 사용자별 결과 확인

#### L4 · ⓪ 기준 — 기존 공유 권한이 그대로 적용

1. [시작] 조직에 SharePoint 문서가 존재
   - 주체: 사용자
   - 데이터: 문서 · 사이트 · 기존 공유 권한
   - 해설: Copilot이 사용되기 전부터 사이트와 문서에는 기존 권한이 있습니다.
2. [처리] 문서 소유자가 공유 범위를 정함
   - 주체: 사용자
   - 위치: SharePoint 문서 › 액세스 관리 [확인 필요: 메뉴]
   - 데이터: 직접 공유 · 그룹 · 링크
   - 해설: 사용자별 접근 가능성은 원본의 공유와 멤버십에 달려 있습니다.
3. [처리] 관리자가 공유 범위를 살펴봄
   - 주체: 관리자
   - 데이터: 실제 사용자와 접근 가능한 문서
   - 해설: 너무 넓은 공유가 있으면 권한이 있는 사용자에게 콘텐츠가 노출될 수 있습니다.
4. [끝] 접근 권한과 검색 가능성을 구분
   - 주체: 관리자
   - 데이터: 파일 접근 권한 · 검색과 참조 여부
   - 해설: 접근할 수 있다는 사실만으로 특정 답변에 문서가 반드시 인용되는 것은 아닙니다.

#### L4 · ① 구성 — 테스트 문서와 공유 범위 검토

1. [시작] 테스트용 문서와 두 사용자를 정한다
   - 주체: 관리자
   - 위치: SharePoint 테스트 사이트
   - 데이터: 문서 · 허용 사용자 · 미허용 사용자
   - 해설: 실제 민감 데이터를 사용하지 않는 비교 예시를 준비합니다.
2. [처리] 문서의 현재 공유 상태를 확인
   - 주체: 관리자
   - 위치: SharePoint 문서 › 액세스 관리 [확인 필요: 메뉴]
   - 데이터: 사용자별 권한 · 링크 · 그룹
   - 해설: 직접 부여 외에 그룹과 공유 링크로 생긴 권한도 확인합니다.
3. [처리] 허용된 사용자의 파일 접근을 확인
   - 주체: 사용자
   - 위치: SharePoint 문서
   - 데이터: 허용 사용자의 보기 권한
   - 해설: 허용된 사용자가 원본 파일을 열 수 있는지 확인합니다.
4. [처리] 다른 사용자의 권한을 검토
   - 주체: 관리자
   - 위치: SharePoint 문서 › 액세스 관리 [확인 필요: 메뉴]
   - 데이터: 미허용 사용자와 그룹 멤버십
   - 해설: 비교 사용자가 간접적인 공유 권한을 갖고 있지 않은지 확인합니다.
5. [처리] 사용자의 Copilot 경험과 감사 요구를 확인
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › 사용자 › 활성 사용자
   - 데이터: 대상 경험 · 라이선스 · 감사 접근 역할
   - 해설: 테스트 경험과 조사 도구에 필요한 권한은 별도로 준비합니다.
6. [끝] 사용자별 테스트 조건을 기록
   - 주체: 관리자
   - 위치: 테스트 기록
   - 데이터: 질문 · 문서 · 사용자 · 접근 조건
   - 해설: 같은 질문을 각 사용자에게 사용해 조건과 결과를 비교합니다.

#### L4 · ② 적용 — 권한과 응답 근거를 조사

1. [시작] 사용자가 문서 관련 질문을 제출
   - 주체: 사용자
   - 데이터: 프롬프트 · 사용자 컨텍스트
   - 해설: 사용자가 조직 문서에 관한 질문을 합니다.
2. [처리] Copilot이 조직 데이터와 문맥을 활용
   - 주체: Copilot
   - 데이터: Microsoft Graph의 접근 가능한 콘텐츠와 문맥
   - 해설: Copilot은 사용자가 접근할 수 있는 조직 데이터에 근거해 응답할 수 있습니다.
3. [처리] 적합한 결과가 있는지 확인
   - 주체: Copilot
   - 데이터: 접근 가능 여부 · 관련성 · 검색 가능성
   - 해설: 접근 권한은 필요 조건이지만 특정 자료의 검색이나 인용을 보장하지 않습니다.
4. [처리] 응답과 인용을 사용자에게 표시
   - 주체: Copilot
   - 데이터: 응답 · 인용 [확인 필요: 해당 경험의 표시]
   - 해설: 선택된 자료가 응답에 쓰이면 사용자는 인용을 검토할 수 있습니다.
5. [처리] 관리자가 감사 기록을 검색
   - 주체: 관리자
   - 위치: Microsoft Purview › 감사
   - 데이터: 사용자 · 시각 · 접근한 리소스
   - 해설: 감사는 상호작용과 접근 리소스를 조사하는 경로입니다.
6. [끝] 감사와 상호작용 본문을 구분
   - 주체: 관리자
   - 위치: Microsoft Purview › eDiscovery 또는 DSPM for AI
   - 데이터: 프롬프트와 응답 본문
   - 해설: 감사 레코드에는 프롬프트와 응답의 본문이 들어 있지 않습니다.

> 교육 포인트: 권한 경계, 검색 가능성, 실제 인용은 서로 다른 질문입니다. 확인일 2026-11-24.
> 주의: 서비스 내부 순서와 필드 이름은 예시이며 특정 API 호출을 Copilot 내부 구현으로 단정하지 않습니다.

### L3 · A · 조직 문서 그라운딩 — 사용자 권한과 검색 결과에 따른 차이

#### L4 · 권한 있는 문서 기반 답변 — 문서 접근과 실제 인용을 비교

1. [시작] 사용자가 문서 관련 질문을 제출
   - 주체: 사용자
   - 데이터: 질문 · 사용자 계정 · 대상 문서
   - 해설: 조직 문서에 대한 질문을 사용자별로 비교합니다.
2. [판단] 사용자에게 해당 문서의 보기 권한이 있는가?
   - 주체: SharePoint
   - 데이터: 문서 ACL · 공유 링크 · 사이트 멤버십
   - 해설: Copilot은 사용자가 접근할 권한이 있는 조직 데이터만 제공합니다.
   - 있음 → 3
   - 없음 → 7
3. [판단] 관련 문서가 이번 검색에서 선택됐는가?
   - 주체: Copilot
   - 데이터: 관련성 · 검색 가능성 [확인 필요: 경험별 조건]
   - 해설: 권한이 있다고 해서 해당 문서가 매번 검색되거나 인용되는 것은 아닙니다.
   - 선택됨 → 4
   - 선택 안 됨 → 8
4. [처리] 허용된 문서를 응답의 근거로 사용
   - 주체: Copilot
   - 데이터: 접근 가능한 문서 내용 · 질의 문맥
   - 해설: 관련 자료가 선택된 예시에서 그 내용으로 응답을 보강할 수 있습니다.
5. [처리] 사용자가 응답과 인용을 확인
   - 주체: 사용자
   - 데이터: 응답 · 인용 링크
   - 해설: 응답에 인용이 표시되면 원본과 내용을 비교합니다.
6. [끝] 관리자가 감사의 접근 리소스를 조사
   - 주체: 관리자
   - 위치: Microsoft Purview › 감사
   - 데이터: Copilot 상호작용 · 접근한 파일과 사이트
   - 해설: 감사와 대화 본문은 별도 경로이며 각 기록의 범위를 확인합니다.
7. [차단] 문서 접근 권한 없음 — 해당 내용은 제공하지 않음
   - 주체: Copilot
   - 데이터: 사용자에게 허용되지 않은 문서
   - 해설: 해당 문서의 접근 권한이 없다면 그 문서 내용을 사용자에게 제공하지 않습니다.
8. [끝] 문서 미선택 — 접근 가능해도 인용은 보장되지 않음
   - 주체: 사용자
   - 데이터: 검색 결과 · 답변의 인용 여부
   - 해설: 문서가 선택되지 않은 원인은 검색·관련성 등에서 따로 확인해야 합니다.
- 시나리오: 있음 ▸ 선택됨 :: 접근 가능한 문서를 근거로 답변
- 시나리오: 있음 ▸ 선택 안 됨 :: 접근 가능하지만 이번 답변에 미선택
- 시나리오: 없음 :: 문서 접근 권한이 없어 내용 미제공

> 주의: 공유 권한이 과도하면 Copilot은 이미 접근 권한을 가진 사용자에게 해당 내용을 제공할 수 있습니다. 검색 제한과 원본 권한 수정은 다릅니다.
> 교육 포인트: Graph 위임 권한은 앱에 부여된 권한과 사용자 자신의 권한에 제한됩니다. 앱 전용 권한은 로그인 사용자 없이 동작하며 이 예시의 Copilot 내부 권한과 동일하다고 가정하지 않습니다.
