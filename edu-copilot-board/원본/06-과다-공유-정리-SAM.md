## L2 · 과다 공유 정리 (SAM) — Copilot 도입 전 위생

- 설정(Control Plane): 데이터 액세스 거버넌스 보고서 | 사이트별 Restricted Content Discovery(RCD) · 제한된 액세스 제어(RAC)
- 강제(Enforcement): RCD는 조직 전체 검색·Copilot 검색 노출 제한 | RAC는 별도의 사이트 접근 통제
- 증적(Evidence): 공유 및 액세스 거버넌스 보고서 | Get-SPOSite의 RestrictContentOrgWideSearch
- 메뉴(Admin Center): SharePoint 관리 센터 > 사이트 > 활성 사이트 > 설정
- 라이선스(License): RCD는 Copilot 라이선스와 SharePoint Advanced Management의 전제 조건 확인 | 보고서·RAC별 SKU와 역할 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 공유 상태 확인 → 검색 제한 → 권한 정리

#### L4 · ⓪ 기준 — 사이트의 기존 공유 상태 조사

1. [시작] 관리자가 검토할 SharePoint 사이트를 고른다
   - 주체: 관리자
   - 데이터: 사이트 URL · 사이트 소유자
   - 해설: 권한 검토가 필요한 사이트를 정합니다.
2. [처리] 사이트 공유와 접근을 검토
   - 주체: 관리자
   - 위치: SharePoint 관리 센터 › 데이터 액세스 거버넌스 [확인 필요: 메뉴]
   - 데이터: 공유 링크 · 사용자와 그룹
   - 해설: 보고서를 이용해 접근 범위를 조사합니다.
3. [처리] Copilot의 기존 사용자 권한 경계를 이해
   - 주체: Copilot
   - 데이터: 현재 사용자가 접근 가능한 콘텐츠
   - 해설: 과도하게 공유된 콘텐츠도 이미 접근할 수 있는 사용자에게 제공될 수 있습니다.
4. [끝] 검토 전 임시 검색 제한 필요 여부 결정
   - 주체: 관리자
   - 데이터: 사이트 위험도 · 소유자 검토 계획
   - 해설: 검색 제한과 실제 접근 권한 수정을 서로 다른 조치로 판단합니다.

#### L4 · ① 구성 — 사이트의 RCD를 켜고 상태 확인

1. [시작] 관리자가 전제 조건을 확인
   - 주체: 관리자
   - 위치: SharePoint Advanced Management 전제 조건 문서
   - 데이터: 관리자 역할 · Copilot 라이선스
   - 해설: 필요한 역할과 라이선스를 확인합니다.
2. [처리] SharePoint 관리 센터의 사이트 목록을 연다
   - 주체: 관리자
   - 위치: SharePoint 관리 센터 › 사이트 › 활성 사이트
   - 데이터: 검토할 사이트
   - 해설: RCD를 적용할 사이트를 선택합니다.
3. [처리] 사이트의 설정 탭을 연다
   - 주체: 관리자
   - 위치: 활성 사이트 › 사이트 선택 › 설정
   - 데이터: 사이트 설정
   - 해설: 사이트별 설정에서 검색 노출 제한을 구성합니다.
4. [처리] Restrict content from Microsoft Copilot을 켠다
   - 주체: 관리자
   - 위치: 설정 › Restrict content from Microsoft Copilot
   - 데이터: RCD 활성화
   - 해설: 설정을 켜고 저장합니다.
5. [처리] 상태를 PowerShell로 확인
   - 주체: 관리자
   - 위치: SharePoint Online PowerShell
   - 데이터: Get-SPOSite -Identity <site-url> | Select RestrictContentOrgWideSearch
   - 해설: 사이트의 제한 설정값을 조회합니다.
6. [끝] 검색 시스템 전파를 기다리고 검토를 진행
   - 주체: 관리자
   - 위치: 사이트 소유자의 권한 검토
   - 데이터: 전파 상태 · 검토 결과
   - 해설: 변경 전파에는 시간이 걸리며 검색 제한이 사이트 권한을 변경하지 않습니다.

#### L4 · ② 적용 — 검색 제한과 직접 접근 비교

1. [시작] 사용자가 조직 전체 검색이나 Copilot에서 질문
   - 주체: 사용자
   - 데이터: 질문 · RCD가 적용된 사이트
   - 해설: 조직 전체 검색 경로에서 사이트 콘텐츠를 찾으려 합니다.
2. [처리] 사이트별 RCD 설정 적용
   - 주체: Microsoft 365 검색
   - 데이터: 사이트의 검색 제한 상태
   - 해설: 설정이 전파된 후 사이트 콘텐츠의 조직 전체 검색과 Copilot 노출을 제한합니다.
3. [처리] 검색 노출과 원본 권한을 구분
   - 주체: 관리자
   - 데이터: 검색 제한 · 기존 사이트 권한
   - 해설: RCD는 기존 권한을 변경하거나 검색 인덱스에서 콘텐츠를 제거하지 않습니다.
4. [처리] 권한 있는 사용자의 직접 접근 확인
   - 주체: 사용자
   - 위치: SharePoint 사이트 또는 문서 직접 링크
   - 데이터: 기존 문서 권한
   - 해설: 기존 권한이 있으면 직접 접근할 수 있습니다.
5. [처리] 소유자가 과다 공유를 수정
   - 주체: 사이트 소유자
   - 위치: SharePoint 사이트의 권한 관리
   - 데이터: 사용자 · 그룹 · 공유 링크
   - 해설: 실제 과다 공유는 별도로 권한과 공유 설정을 조정해 해결합니다.
6. [끝] 검토 후 제한 상태 재평가
   - 주체: 관리자
   - 위치: SharePoint 관리 센터 › 사이트 › 활성 사이트 › 설정
   - 데이터: 권한 검토 결과 · RCD 설정
   - 해설: 검토 결과에 따라 임시 검색 제한의 유지 또는 해제를 결정합니다.

> 교육 포인트: RCD는 임시 검색 발견 제한이고 RAC는 별도 접근 통제입니다. 확인일 2026-11-24.
> 주의: RCD는 OneDrive 사이트에 적용되지 않으며 사이트 내부 검색과 일부 다른 경험에는 영향을 주지 않습니다.

### L3 · A · 공유 조사와 노출 축소 — 검색과 접근의 차이

#### L4 · 공유 범위 검토 — RCD와 직접 접근을 비교

1. [시작] 관리자가 과다 공유가 우려되는 사이트를 조사
   - 주체: 관리자
   - 데이터: 사이트 · 기존 사용자 권한
   - 해설: 조직 전체 검색에 나타날 수 있는 사이트를 검토합니다.
2. [판단] 사이트에 RCD가 적용되고 전파됐는가?
   - 주체: Microsoft 365 검색
   - 데이터: 사이트별 RCD 설정 · 전파 상태
   - 해설: 검색 제한이 아직 적용되지 않았거나 전파 중이면 결과가 달라질 수 있습니다.
   - 적용됨 → 3
   - 미적용 → 7
3. [처리] 조직 전체 검색과 Copilot 노출 제한
   - 주체: Microsoft 365 검색
   - 데이터: 사이트 콘텐츠 · 검색 제한
   - 해설: 전파된 RCD는 최근 상호작용한 파일을 포함해 해당 사이트의 조직 전체 검색 노출을 제한합니다.
4. [판단] 사용자가 원본에 직접 접근할 권한이 있는가?
   - 주체: SharePoint
   - 데이터: 사이트 및 문서 권한
   - 해설: RCD가 기존 권한을 바꾸지는 않습니다.
   - 있음 → 5
   - 없음 → 8
5. [처리] 권한 있는 사용자가 직접 문서에 접근
   - 주체: 사용자
   - 위치: SharePoint 사이트 또는 문서 직접 링크
   - 데이터: 기존 문서 권한
   - 해설: 조직 전체 검색에서 제한돼도 직접 접근은 기존 권한에 따릅니다.
6. [끝] 설정과 공유 범위를 따로 검토
   - 주체: 관리자
   - 위치: SharePoint 관리 센터 · 사이트 권한 관리
   - 데이터: RCD 상태 · 공유 권한
   - 해설: 검색 제한 상태와 과다 공유 수정을 각각 확인합니다.
7. [끝] 검색 제한 미적용 또는 전파 중
   - 주체: 관리자
   - 데이터: RCD 설정 · 전파 상태
   - 해설: 설정과 전파 상태를 확인하고 사이트의 실제 권한을 검토합니다.
8. [차단] 원본 권한 없음 — 직접 접근 불가
   - 주체: SharePoint
   - 데이터: 사용자 권한
   - 해설: 사용자에게 필요한 원본 권한이 없다면 직접 접근할 수 없습니다.
- 시나리오: 적용됨 ▸ 있음 :: 검색 제한에도 기존 권한으로 직접 접근
- 시나리오: 적용됨 ▸ 없음 :: 검색 제한 및 원본 접근 권한 없음
- 시나리오: 미적용 :: 제한 미적용 또는 전파 상태 확인

> 주의: RAC 적용 시의 그룹 및 예외 조건은 별도 제품 문서와 테넌트 설정으로 [확인 필요: 대상 구독·테넌트·리전의 설정과 권한을 공식 절차 및 실제 관리자 화면에서 확인]. RCD를 권한 제거의 대체 수단으로 설명하지 않습니다.

> 출처: https://learn.microsoft.com/en-us/sharepoint/data-access-governance-reports
