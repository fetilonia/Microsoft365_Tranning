## L2 · 사용자 접근 — 누가 · 어떤 기기로 쓰는가

- 설정(Control Plane): 적격 기본 구독과 Copilot 라이선스 할당 | 대상 서비스에 적용되는 조건부 액세스 정책 검토
- 강제(Enforcement): Entra ID 로그인 및 적용 정책 평가 | 경험별 라이선스·서비스 요구 사항 확인
- 증적(Evidence): Microsoft 365 사용자 라이선스 상태 | Entra 로그인 로그의 조건부 액세스 결과
- 메뉴(Admin Center): Microsoft 365 관리 센터 > 청구 > 라이선스 | Entra 관리 센터 > 보호 > 조건부 액세스 [확인 필요: 테넌트 메뉴]
- 라이선스(License): Microsoft Copilot 유료 기능은 적격 기본 라이선스와 Copilot 라이선스 필요 | 적격 Microsoft 365 구독의 Copilot Chat은 별도 Copilot 라이선스 불필요 | CA·Intune 요구 SKU [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]

### L3 · 0 · 기능 상태 전이 — 경험과 할당 확인 → 라이선스 구성 → 로그인 점검

#### L4 · ⓪ 기준 — Copilot 라이선스가 없는 적격 사용자

1. [시작] 관리자가 대상 사용자의 조직 계정을 확인
   - 주체: 관리자
   - 데이터: Microsoft Entra 직장 또는 학교 계정
   - 해설: 이 예시는 조직 계정을 사용하는 대상 사용자를 기준으로 합니다.
2. [처리] 현재 구독과 제품 할당을 확인
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › 사용자 › 활성 사용자
   - 데이터: 적격 기본 구독과 Copilot 제품 할당 상태
   - 해설: 기존 구독과 별도 라이선스를 구분합니다.
3. [처리] 적격 Copilot Chat 가능성을 검토
   - 주체: 관리자
   - 데이터: 적격 구독과 사용 경험
   - 해설: 별도 Copilot 라이선스가 없어도 적격 사용자는 Copilot Chat을 사용할 수 있습니다.
4. [끝] 유료 기능의 추가 요구 사항을 확인
   - 주체: 관리자
   - 데이터: 계획된 앱과 유료 기능
   - 해설: Chat 가능 여부만으로 유료 Copilot 기능이 할당됐다고 판단할 수 없습니다.

#### L4 · ① 구성 — 적격 구독과 Copilot 라이선스 배정

1. [시작] 대상 사용자와 필요한 경험을 정한다
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › 사용자 › 활성 사용자
   - 데이터: 사용자 계정과 사용할 앱
   - 해설: 어떤 사용자가 어떤 Copilot 경험을 필요로 하는지 정합니다.
2. [처리] 기본 구독과 서비스 요구 사항을 검토
   - 주체: 관리자
   - 위치: Microsoft Copilot 요구 사항 문서
   - 데이터: 적격 기본 라이선스 · 앱 · 사서함 · 지원 클라이언트
   - 해설: 사서함을 사용하는 경험에는 Exchange Online 사서함이 필요합니다.
3. [처리] Copilot 라이선스 제품을 연다
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › 청구 › 라이선스 › Microsoft Copilot
   - 데이터: 제품 및 사용 가능한 라이선스
   - 해설: 제품 상세에서 대상 사용자 또는 그룹에 라이선스를 할당합니다.
4. [처리] 사용자를 선택하고 라이선스를 할당
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › 청구 › 라이선스 › Microsoft Copilot
   - 데이터: 사용자 또는 그룹 할당
   - 해설: 관리자는 필요한 사용자에게 제품 라이선스를 부여합니다.
5. [처리] 할당 상태를 사용자 화면에서 확인
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › 사용자 › 활성 사용자
   - 데이터: 사용자의 활성 라이선스
   - 해설: 할당 결과가 사용자에게 표시되는지 확인합니다.
6. [끝] 대상 앱과 로그인 정책을 점검
   - 주체: 관리자
   - 위치: Entra 관리 센터 › 보호 › 조건부 액세스
   - 데이터: 대상 사용자 · 리소스 · 조건부 액세스 정책 [확인 필요: 해당 앱 적용 범위]
   - 해설: 라이선스 외에 실제 앱에 적용되는 접근 정책과 클라이언트 요구 사항을 검토합니다.

#### L4 · ② 적용 — 사용자 로그인과 할당 상태 확인

1. [시작] 사용자가 지원되는 앱에서 조직 계정으로 로그인
   - 주체: 사용자
   - 데이터: 직장 또는 학교 계정 · 클라이언트
   - 해설: 지원되는 앱에서 조직 계정으로 로그인합니다.
2. [처리] Entra ID가 로그인 요청을 처리
   - 주체: Entra ID
   - 데이터: 사용자 · 리소스 · 로그인 조건
   - 해설: 로그인과 적용 대상 정책은 라이선스 배정과 별도로 확인합니다.
3. [처리] 앱이 사용 가능한 경험을 확인
   - 주체: 앱
   - 데이터: 라이선스 · 기본 구독 · 앱 및 서비스 요구 사항
   - 해설: 사용 가능한 경험은 라이선스와 앱 설정에 따라 다릅니다.
4. [처리] 사용자가 Copilot 경험을 연다
   - 주체: 사용자
   - 데이터: 선택한 앱 · 작업
   - 해설: 앱이 나타나지 않으면 배정 상태와 요구 사항을 재확인합니다.
5. [처리] 관리자가 로그인 기록을 조사
   - 주체: 관리자
   - 위치: Entra 관리 센터 › 모니터링 및 상태 › 로그인 로그 [확인 필요: 메뉴]
   - 데이터: 로그인 결과 · 조건부 액세스 결과
   - 해설: 로그인 문제와 정책 평가 결과를 로그인 로그에서 구분합니다.
6. [끝] 라이선스 상태와 로그인 결과를 함께 해석
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › 사용자 › 활성 사용자
   - 데이터: 라이선스 상태 · 로그인 결과
   - 해설: 라이선스가 있더라도 정책이나 앱 요구 사항을 별도로 확인해야 합니다.

> 교육 포인트: Microsoft 365 Copilot은 현재 Microsoft Copilot으로, Microsoft 365 Copilot Chat은 Microsoft Copilot Chat으로 명칭이 변경되었습니다. 확인일 2026-11-24.
> 주의: 앱 보호 정책의 지원 클라이언트·조건과 조건부 액세스의 대상 리소스는 환경과 앱별로 확인해야 합니다.

### L3 · A · 사용자 접근 판정 — 경험별 라이선스와 로그인 정책 비교

#### L4 · ▶ 적격 사용자의 접근 — 라이선스와 적용 정책에 따라 다른 경험

1. [시작] 사용자가 조직 계정으로 Copilot에 접근
   - 주체: 사용자
   - 위치: 지원되는 Copilot 클라이언트
   - 데이터: 사용자 · 선택한 경험 · 디바이스
   - 해설: 같은 사용자의 접근에서도 라이선스와 로그인 정책을 각각 살펴봅니다.
2. [판단] 유료 Copilot 기능에 필요한 라이선스가 할당됐는가?
   - 주체: 관리자
   - 데이터: 적격 기본 라이선스 · Copilot 라이선스
   - 해설: 유료 기능에는 별도 Copilot 라이선스와 적격 기본 라이선스가 필요합니다.
   - 예 → 3
   - 아니오 → 7
3. [판단] 이 로그인에 적용되는 접근 조건을 충족했는가?
   - 주체: Entra ID
   - 데이터: 실제 대상 리소스에 적용되는 조건부 액세스 결과 [확인 필요: 대상 테넌트에서 해당 데이터 필드·수집 조건·정책 결과를 기록 또는 보고서와 대조]
   - 해설: 해당 앱에 정책이 적용된다면 그 정책의 조건을 충족해야 합니다.
   - 충족 → 4
   - 미충족 → 6
4. [처리] 지원 앱과 서비스 요구 사항을 확인
   - 주체: 앱
   - 데이터: 앱 버전 · 필요 시 Exchange Online 사서함
   - 해설: 라이선스와 로그인 외에도 앱별 요구 사항이 있습니다.
5. [끝] 적격 경험 사용 및 상태 확인
   - 주체: 사용자
   - 데이터: 선택한 앱의 Copilot 경험 · 라이선스 상태
   - 해설: 요구 사항이 모두 충족된 예시에서 해당 경험을 사용할 수 있습니다.
6. [차단] 적용 정책의 요구 미충족 — 로그인 결과 조사
   - 주체: 관리자
   - 위치: Entra 관리 센터 › 로그인 로그
   - 데이터: 로그인 실패 사유 · 조건부 액세스 결과
   - 해설: 조건을 충족하지 못해 차단된 경우 로그와 실제 정책을 조사합니다.
7. [판단] 사용자가 Copilot Chat에 적격인가?
   - 주체: 관리자
   - 데이터: 적격 Microsoft 365 구독 · 사용자 계정
   - 해설: 별도 유료 라이선스가 없어도 적격 사용자는 Chat을 사용할 수 있습니다.
   - 적격 → 8
   - 미적격 → 9
8. [끝] 적격 Chat 확인 — 접근 정책은 별도
   - 주체: 사용자
   - 데이터: Chat 이용 자격
   - 해설: Chat 적격성은 유료 기능 할당 증거가 아니며 실제 접근은 적용 정책과 앱 요구 사항을 별도로 확인합니다.
9. [차단] 적격 구독 확인 필요 — 경험 사용 요건 미충족
   - 주체: 관리자
   - 데이터: 제품 할당 · 구독 상태
   - 해설: 적격 구독이나 계정이 없으면 요구 사항을 먼저 해결합니다.
- 시나리오: 예 ▸ 충족 :: 유료 라이선스와 접근 조건 충족
- 시나리오: 예 ▸ 미충족 :: 적용된 접근 조건 미충족으로 차단
- 시나리오: 아니오 ▸ 적격 :: 별도 유료 라이선스 없이 적격 Chat
- 시나리오: 아니오 ▸ 미적격 :: 적격 구독과 계정 요건 확인 필요

> 주의: 앱 보호 정책 적용 대상 여부와 사용자 경험은 [확인 필요: 실제 SKU별 사용 권한과 대상 사용자 조건을 Microsoft Learn 서비스 설명·고객 계약 및 할당된 라이선스에서 대조]. 라이선스 배정 후 앱에 나타나기까지 지연될 수 있으며 앱과 환경별로 확인합니다.
