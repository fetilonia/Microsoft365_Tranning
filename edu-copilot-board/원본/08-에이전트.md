## L2 · 에이전트 — Copilot Studio · Agent ID

- 설정(Control Plane): 에이전트 등록 · 승인 · 할당 | 연결 및 데이터 접근 권한 검토
- 강제(Enforcement): 에이전트 유형별 사용자 접근 · 연결 인증 · 데이터 권한
- 증적(Evidence): Agent Registry의 상태 | 감사·보안 신호 [확인 필요: 유형별 기록]
- 메뉴(Admin Center): Microsoft 365 관리 센터 > Agents & connectors > Agent Registry [확인 필요: 테넌트 메뉴]
- 라이선스(License): 에이전트 유형 · 작성 · 사용 및 보안 기능별 SKU와 역할 [확인 필요]

### L3 · 0 · 기능 상태 전이 — 인벤토리 확인 → 허용·할당 → 사용

#### L4 · ⓪ 기준 — 에이전트와 데이터 연결 검토

1. [시작] 관리자가 사용할 에이전트를 확인
   - 주체: 관리자
   - 데이터: 에이전트 이름 · 게시자 · 유형
   - 해설: 조직 게시 에이전트와 외부 파트너 에이전트의 유형을 구분합니다.
2. [처리] 등록 및 가용성 상태를 조사
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › Agent Registry
   - 데이터: 상태 · 게시자 · 대상
   - 해설: 관리자는 레지스트리에서 에이전트 수명 주기와 상태를 볼 수 있습니다.
3. [처리] 연결과 데이터 원본을 검토
   - 주체: 관리자
   - 데이터: 도구 · 연결 · 데이터 원본
   - 해설: 에이전트가 사용하는 도구와 연결은 유형별로 확인합니다.
4. [끝] 사용자에게 허용할지 판단
   - 주체: 관리자
   - 데이터: 조직 정책 · 접근 범위
   - 해설: 사용자 접근 허용과 데이터 원본의 권한은 별도 판단입니다.

#### L4 · ① 구성 — 에이전트 검토와 사용자 할당

1. [시작] 관리자가 에이전트 관리 화면을 연다
   - 주체: 관리자
   - 위치: Microsoft 365 관리 센터 › Agents & connectors [확인 필요: 메뉴]
   - 데이터: 대상 테넌트 · 관리자 역할
   - 해설: 에이전트 유형과 관리 역할을 확인합니다.
2. [처리] Agent Registry에서 대상 에이전트를 선택
   - 주체: 관리자
   - 위치: Agents & connectors › Agent Registry
   - 데이터: 에이전트 이름 · 게시 상태
   - 해설: 조직이 허용할 에이전트를 식별합니다.
3. [처리] 데이터 원본과 연결을 검토
   - 주체: 관리자
   - 위치: 에이전트 상세 [확인 필요: 메뉴]
   - 데이터: 도구 · 연결 · 요구 권한
   - 해설: 외부 서비스에 어떤 데이터가 전달되는지 유형별 약관과 권한을 검토합니다.
4. [처리] 조직의 승인 또는 허용 여부 결정
   - 주체: 관리자
   - 위치: 에이전트 요청 · 관리 화면 [확인 필요]
   - 데이터: 요청 상태 · 승인 또는 차단
   - 해설: 관리 기능으로 에이전트를 허용하거나 차단할 수 있습니다.
5. [처리] 대상 사용자에게 배포 또는 할당
   - 주체: 관리자
   - 위치: 에이전트 관리 › 할당 [확인 필요]
   - 데이터: 사용자 · 그룹 · 배포 상태
   - 해설: 적용 가능한 에이전트 유형의 사용자 범위를 확인합니다.
6. [끝] 데이터 원본의 사용자 권한을 검토
   - 주체: 관리자
   - 위치: 해당 데이터 원본의 권한 관리
   - 데이터: 사용자 권한 · 연결 인증
   - 해설: 에이전트가 허용됐다는 사실만으로 원본 데이터 접근이 보장되지는 않습니다.

#### L4 · ② 적용 — 허용된 에이전트 호출

1. [시작] 사용자가 허용된 에이전트를 선택
   - 주체: 사용자
   - 위치: Copilot 앱의 에이전트
   - 데이터: 사용자 · 에이전트
   - 해설: 사용자는 관리자가 허용한 에이전트에 접근합니다.
2. [처리] 에이전트가 요청과 지시를 처리
   - 주체: 에이전트
   - 데이터: 사용자 요청 · 에이전트 지침
   - 해설: 에이전트는 설정된 지식과 도구를 이용해 요청을 처리합니다.
3. [처리] 필요한 데이터 연결과 인증을 사용
   - 주체: 에이전트
   - 데이터: 연결 · 인증 · 요청 대상
   - 해설: 연결 유형에 따라 인증 방식과 접근 범위가 다릅니다.
4. [처리] 허용된 데이터 또는 도구 결과를 수신
   - 주체: 외부 서비스
   - 데이터: 데이터 원본의 권한 · 결과
   - 해설: 실제 데이터 접근은 원본과 연결의 권한에 따릅니다.
5. [처리] 사용자가 에이전트 응답을 검토
   - 주체: 사용자
   - 데이터: 결과 · 가능한 인용
   - 해설: 결과와 연결된 출처를 검토합니다.
6. [끝] 관리자가 상태와 기록을 확인
   - 주체: 관리자
   - 위치: Agent Registry · Microsoft Purview 감사 [확인 필요: 유형별 기록]
   - 데이터: 가용성 · 상호작용 증적
   - 해설: 레지스트리 상태와 상호작용 기록은 서로 다른 조사 경로입니다.

> 교육 포인트: 에이전트 허용, 연결 인증, 원본 권한은 별개의 경계입니다. 확인일 2026-11-24.
> 주의: Researcher와 Analyst는 핵심 Copilot 경험의 일부이며 이 문서에 따르면 에이전트 관련 설정에 속하지 않습니다.

### L3 · A · 승인된 에이전트 호출 — 사용 허용과 연결 접근 비교

#### L4 · 에이전트가 데이터로 답변 — 관리와 원본 접근 판정

1. [시작] 사용자가 에이전트에 데이터 조회를 요청
   - 주체: 사용자
   - 데이터: 사용자 · 에이전트 · 질문
   - 해설: 이 예시는 데이터 원본이 연결된 에이전트를 사용합니다.
2. [판단] 관리자가 이 에이전트의 사용을 허용했는가?
   - 주체: 관리자
   - 데이터: 에이전트 허용 · 사용자 할당 상태
   - 해설: 사용자는 관리자가 허용한 에이전트에만 접근할 수 있습니다.
   - 허용 → 3
   - 차단 → 8
3. [판단] 연결 인증이 유효한가?
   - 주체: 외부 서비스
   - 데이터: 연결 인증 상태 [확인 필요: 에이전트 유형별]
   - 해설: 연결에 필요한 인증이 없거나 만료되면 해당 연결을 조사합니다.
   - 유효 → 4
   - 실패 → 9
4. [판단] 데이터 원본이 요청된 접근을 허용하는가?
   - 주체: 데이터 원본
   - 데이터: 원본 권한 · 연결의 인증 컨텍스트
   - 해설: 접근 판단은 원본과 연결의 구현 방식에 따라 확인합니다.
   - 허용 → 5
   - 거부 → 10
5. [처리] 에이전트가 데이터를 사용해 응답
   - 주체: 에이전트
   - 데이터: 허용된 데이터 · 응답
   - 해설: 이 예시에서는 연결과 접근이 허용되어 응답을 생성합니다.
6. [처리] 사용자가 결과를 확인
   - 주체: 사용자
   - 데이터: 응답 · 가능한 인용
   - 해설: 응답과 참조 출처를 검토합니다.
7. [끝] 관리자가 상태 및 감사 범위를 검토
   - 주체: 관리자
   - 위치: Agent Registry · Microsoft Purview 감사
   - 데이터: 에이전트 상태 · 기록 [확인 필요]
   - 해설: 각 에이전트 유형의 감사 및 운영 기록 범위를 확인합니다.
8. [차단] 관리자가 에이전트를 차단
   - 주체: 관리자
   - 데이터: 차단 상태
   - 해설: 관리자가 허용하지 않은 에이전트는 사용자가 이용할 수 없습니다.
9. [차단] 연결 인증 실패 — 연결을 조사
   - 주체: 관리자
   - 데이터: 연결 상태 · 오류 [확인 필요]
   - 해설: 실제 오류 메시지와 복구 절차는 연결 유형에 따라 확인합니다.
10. [차단] 원본 권한 부족 — 접근을 조사
   - 주체: 데이터 원본
   - 데이터: 원본의 거부 결과 [확인 필요]
   - 해설: 원본 권한과 연결에 사용된 인증 컨텍스트를 조사합니다.
- 시나리오: 허용 ▸ 유효 ▸ 허용 :: 에이전트와 연결 접근이 허용되어 응답
- 시나리오: 허용 ▸ 유효 ▸ 거부 :: 에이전트는 허용됐으나 원본 접근 거부
- 시나리오: 허용 ▸ 실패 :: 연결 인증 실패로 데이터 조회 불가
- 시나리오: 차단 :: 관리자 차단으로 에이전트 사용 불가

> 주의: Agent ID, Copilot Studio, Agent 365 및 Defender 기능의 관계·미리 보기 상태·로그는 유형과 환경별 [확인 필요]. 오류 표시와 접근 거부 동작도 연결 구현마다 검증합니다.
